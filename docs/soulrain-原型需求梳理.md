## 0. 关键修正与阅读说明

原型中头像下方的标注写成了“笔名（id）”。按本次确认，正确含义是：**头像下方显示笔名**。账号 ID 不在该位置展示；是否需要展示或编辑账号 ID，另行设计。

原型中同时出现了基础写作功能和 AI 写作、伏笔、拆文、知识库分析等扩展能力。本文用以下标记区分来源和状态：

- **[原型]**：画布中已出现的页面、控件或说明。
- **[已确认 MVP]**：前一轮已确认的 Windows 离线写作闭环。
- **[融合分析]**：根据页面、文字标注和导航连线整理出的业务关系。
- **[待确认]**：原型表达了意图，但还不足以形成唯一验收规则。

## 1. 产品定位

SoulRain 是面向真实作者的本地写作工作台：作者可以管理作品和章节，在正文写作时引用个人知识库，并在后续阶段使用 AI 对作品结构、正文和写作风格进行辅助分析或生成。

首版目标仍是让作者在 Windows 上离线完成一部自定终点的作品并导出 DOCX/TXT。原型表达的 AI 对话、段落润色、续写、剧情感受、伏笔架构、自动拆文和 XMind 导入，应作为产品路线中的后续能力，不能反向扩大当前 MVP。

### 交互规则

1. 应用启动后默认进入创作集，不要求用户先进入空白正文。
2. 侧栏支持展开和收起；收起状态至少保留菜单入口，不能遮挡正文。
3. 侧栏中的当前模块需要有明确选中状态。
4. 笔名与作品内容是不同数据域；修改笔名不能改变作品标题或作品作者字段，具体联动关系待确认。

### 原型提出的架构能力

1. 架构以树状显示，并计划支持 XMind 思维导图导入。[原型]
2. 剧情架构可以逐步细化为“卷 → 章 → 详细节点”。[原型]
3. 在剧情架构节点上右键，可以添加伏笔或多选知识库条目。[原型]
4. 伏笔示例包含名称、编号和结果关系，例如“XX死亡伏笔 001 → 结果”。排序规则为先按创建时间，再按名称。[原型]

这些能力适合进入后续大纲/伏笔模块。首版先实现稳定的作品、可选分卷、章节和正文段落，不把伏笔树、任意多级大纲或 XMind 导入列为 MVP 验收项。

### 正文右键菜单

原型选中段落后给出以下入口：

| 操作 | 原型含义 | 建议状态 |
| --- | --- | --- |
| 段落润色 | 由 AI 对整段润色 | 后置 |
| 单句润色 | 优先使用剧情架构关联知识库；相似度达到 90 以上时优先取知识库句子，否则使用全局知识库 | 后置，需定义相似度算法和人工确认 |
| 续写 | 根据写作风格、上下文和剧情架构续写 | 后置 |
| 纠错 | 检查错别字；也可作为润色/续写流程的一部分 | 后置 |
| 剧情感受 | 检查是否脱离大纲、上下文衔接是否流畅 | 后置 |
| 插入知识库 | 未选中段落时打开树状知识选择弹窗 | 知识引用为 P0；树状分类弹窗需实现 |

所有 AI 生成或修改正文的操作都应先展示候选结果，用户确认后写入正文，并保留撤销、版本和失败提示；不能自动覆盖原文。这是后续设计的安全约束。[融合分析]

## 6. 知识库与拆文工具

### 6.1 知识库页面

| 项目 | 内容 | 来源 |
| --- | --- | --- |
| 页面名称 | 知识库 | [原型] |
| 功能模块 | 知识条目管理、检索和引用 | [融合分析] |
| 页面布局 | 左侧分类栏，右侧搜索与结果区 | [原型] |
| 目标用户 | 作者 | [已确认 MVP] |

#### 分类和结果

原型展示了以下分类或入口：

- 拆文工具
- 人物描写
- 景物描写
- 内心描写
- 经典引用
- 其他可滚动分类

右侧有搜索框和结果卡片，卡片可显示内容摘要和“出自 XXX”等来源信息。[原型]

#### 首版需求

首版知识库必须支持手工条目新增、编辑、软删除、标签、来源、全文搜索和段落引用。搜索同时覆盖正文与知识条目，标签多选按 AND 组合；引用显示来源，条目修改后同步最新内容，软删除后保留“已删除条目”占位。

#### 后续需求

原型提出了分类树、拆文自动分类和从正文提取人物/景物/内心描写。后续需要补充：分类是否由系统固定、作者能否自定义、一个条目是否允许多个分类、自动分类是否可人工纠正。

### 6.2 拆文工具

原型说明拆文后自动分辨多种描写类型，并在右侧以分类结果展示。建议流程为：

`导入或粘贴文本 → 执行拆文 → 生成分类候选 → 作者校正/合并 → 保存为知识条目`

待确认规则：

1. 输入来源是当前作品正文、剪贴板文本，还是外部 TXT/DOCX。
2. 分类标签是否仅限人物、景物、内心、经典引用，还是允许自定义。
3. 自动分类结果是否直接入库，还是必须逐条确认。
4. 条目来源如何记录，是否保存原文位置和原始文本。

## 8. 设置

原型标注了三类设置：

1. 字体：提供全局字体选择或字体集合。[原型]
2. AI 写作风格特色规则：默认为空时，从文章上下文定义风格。[原型]
3. 全局知识库配置：为 AI 操作指定默认知识库。[原型]

建议分期：首版只实现固定编辑样式及必要的本地数据设置；字体扩展、风格规则和全局知识库作为后续 AI 配置。若开放字体，需定义已有正文是否跟随全局设置，以及 DOCX 导出时缺少字体的替代规则。

## 9. 核心业务流程

### 9.1 首版写作闭环

`启动应用 → 进入创作集 → 新建/打开作品 → 创建分卷（可选）→ 创建章节 → 编辑正文 → 实时字数与自动保存 → 插入知识引用 → 创建快照 → 导出 DOCX/TXT`

### 9.2 知识引用闭环

`新增知识条目 → 填标题/正文/来源/标签 → 全文搜索或标签 AND 筛选 → 选择条目 → 插入指定段落 → 正文显示引用标记 → 导出正文和文末引用清单`

### 9.3 后续 AI 段落操作

`选择段落 → 右键选择润色/续写/纠错/剧情感受 → AI 读取允许的上下文和知识库 → 展示候选结果与依据 → 作者确认 → 生成新版本`

### 9.4 后续需求会话

`选择作品 → 新建会话 → 选择扫描范围 → 输入问题 → AI 返回分析/方案/检查结果 → 作者决定是否应用 → 产生版本或架构变更记录`

## 11. 分期建议

### P0：当前已冻结的首版

- Windows 10/11 64 位、单机单用户、离线可用。
- 创作集基础导航、创建/打开作品。
- 作品 → 可选分卷 → 章节 → 正文段落。
- 固定样式所见即所得编辑、实时章节字数、实时自动保存。
- 手工知识条目、标签 AND 筛选、正文/知识全文搜索、段落引用。
- 手动快照、差异查看、恢复为新版本。
- 项目归档导入/导出、DOCX/TXT 导出。

### P1：原型结构增强

- 完整创作集卡片和项目学习合集语义。
- 侧栏状态、作品最近会话入口、知识库分类管理。
- 基础大纲节点、章节右键关联知识条目。
- 拆文工具的人工分类流程，不接 AI 自动生成。

### P2：AI 和高级架构

- 段落/单句润色、续写、纠错、剧情感受。
- 需求会话扫描作品架构和正文，支持任务进度、取消和结果引用。
- 伏笔架构、结果链、任意多级剧情大纲。
- XMind 导入。
- AI 写作风格规则、全局知识库配置、自动拆文分类。

## 12. 待确认问题

1. “创作集”“项目学习合集”“作品”三者的层级和多归属关系是什么？
2. 无分卷时是否允许直接创建章节？原型写着先添加卷，再添加章节，但首版需求允许可选分卷，需要统一。
3. 伏笔节点需要哪些状态：未埋设、已埋设、已回收、废弃？结果是文本、章节引用还是另一个节点？
4. 剧情架构的详细节点是否和正文章节一一对应，还是允许独立大纲节点？
5. XMind 支持哪些版本和导入格式？导入失败如何回滚？
6. 拆文工具的分类、置信度、人工修正和批量入库规则是什么？
7. AI 操作的上下文范围、模型位置、隐私边界、成本和联网要求是什么？
8. AI 结果是否必须用户确认后写入正文，是否每次生成都自动创建版本？
9. 需求会话是否只绑定一个作品，还是可以跨作品比较？
10. 笔名是否可在侧栏直接编辑，头像是否支持上传和本地路径迁移？

## 13. 原型完整性结论

原型已经表达了主要产品骨架：全局侧栏、创作集、作品架构、正文编辑、知识库、拆文工具、需求会话和设置。当前最清晰且可直接验收的主链仍是“写作 → 知识引用 → 版本 → 导出”。

原型中 AI 入口和高级架构很多，但输入、输出、确认、失败恢复和数据权限尚未定义；这些功能进入实施前必须单独完成需求确认。当前文档可以作为原型评审和后续拆分的文字基线，不能直接替代 AI 模块的详细规格。
