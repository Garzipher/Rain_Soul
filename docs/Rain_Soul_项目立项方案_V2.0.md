## 1 项目概述

### 1.1 项目背景

网文写作常见设定分散、大纲与正文脱节、伏笔遗忘、素材难复用、AI 修改不可控和版本混乱等问题。Rain_Soul 为作者提供本地优先的写作工作台，把写作特点、大纲、章节、段落、知识库、引用、伏笔、AI 辅助、版本和导出连接成可追溯闭环。

### 1.2 产品定位

Rain_Soul 是一个**作者可控的网文写作工作台**。写作是主产品，知识库和 AI 是支撑能力，学习路径是开发过程中的内部学习产物，最终整理为“学习路径”作品。产品不承诺一键生成完整小说，也不以 AI 替代作者判断。

- **写作系统**：从写作特点、大纲、章节到定稿导出。
- **知识系统**：按作品维护知识条目、分类、标签、来源和正文引用。
- **AI 系统**：在作者授权和候选确认下完成润色、续写、纠错、分析和回写。
- **学习路径**：学习卡随功能开发记录，作品集功能完成后集中整理，不阻断作者功能交付。

### 1.3 立项结论

首版（P0）采用 V2.0 完整主写作流程：写作特点、大纲、知识库与分类、伏笔、基础 AI、剧情感受、一致性检查、正文回写、版本与备份、DOCX/TXT 导出。需求会话、跨作品分析、手工/自动拆文、URL 导入、XMind 导入、向量检索等作为扩展，逐项通过真实需求和安全/质量门槛后再开发。

### 1.4 资源与验证边界

- 首版目标平台为 Windows 10/11 64 位，普通用户可安装运行。
- 首版单机单用户，一次只允许一个 Rain_Soul 窗口写入。
- 首版不要求真实作者试用，只做开发团队测试；这会降低产品需求验证强度，必须作为发布风险记录。
- 作者可自行决定作品长度，产品不设置中短篇、章节数或总字数上限。性能测试样本只用于性能验收，不构成写作限制。

## 2 目标与价值

### 2.1 产品目标

1. 作者可在断网状态下创建作品、写作、保存、搜索、查看版本、备份和导出。
2. 大纲、正文、知识条目、引用和伏笔之间有稳定 ID 和可定位证据。
3. AI 只生成候选或分析建议；正文写入必须经过作者对比和确认。
4. 正文回写知识库必须经过逐条审核，不能无审核地污染正文或知识库。
5. 所有导入、导出、恢复和迁移失败都保留原数据，并给出可操作提示。

### 2.2 用户价值

作者可以在一个本地工作台中组织长篇写作资产，减少跨工具复制粘贴；知识引用和伏笔可追溯；AI 的发送范围、费用、候选结果和版本变化透明可控。

### 2.3 学习价值

学习卡根据当前项目结构编写，覆盖 Electron、React/TypeScript、SQLite、Python/FastAPI、AI 适配、数据结构和验收实验。大纲用于组织模块和步骤，伏笔架构用于记录接口、路由、前后端对接、数据流等联系。学习卡是开发知识产物，不是作者使用门槛；作品集功能完成后统一整理进“学习路径”作品。

### 2.4 成功标准

- 开发团队能够在 Windows 10/11 64 位上完成从创建作品到 DOCX/TXT 导出的端到端测试。
- 断网时写作、保存、搜索、版本、备份和导出仍可用。
- 章节字数实时更新，统计汉字、字母和数字，不统计标点、空格、换行及书签标记。
- 搜索同时覆盖正文和知识条目，标签 AND 筛选正确，固定本地样本 UI 搜索 P95 ≤ 1 秒。
- AI 操作有授权、范围、费用提示、候选对比、版本保护和失败重试边界。

## 3 用户、场景与非目标

### 3.1 目标用户

| 维度 | 描述 |
| --- | --- |
| 身份 | 网文作者，单机写作 |
| 技术背景 | 有浅编程基础，希望通过项目学习 AI、后端和 Python |
| 设备 | Windows 10/11 64 位 |
| 网络 | 写作核心流程可断网；AI 由作者选择是否连接云端 |

### 3.2 核心场景

进入“我的作品”书架 → 创建或打开作品 → 设置写作特点 → 编写卷/章/详细节点大纲 → 创建章节 → 编辑正文 → 插入知识引用和伏笔书签 → 使用基础 AI 并确认候选 → 做一致性和剧情感受检查 → 审核正文回写 → 创建版本/备份 → 导出 DOCX/TXT。

### 3.3 非目标

- 不做多人实时协作、账号同步或云端作品存储。
- 不做一键自动生成完整长篇小说。
- 不内置版权内容库，不绕过网站反爬或访问私网地址。
- 首版不做向量检索、本地 Ollama/本地模型、EPUB/PDF、需求会话、跨作品分析、自动拆文、URL 下载和 XMind 导入。

## 4 产品范围与阶段

### 4.1 P0：完整主写作流程

| 功能 | 首版要求 |
| --- | --- |
| “我的作品”书架 | 系统只有一个作品集，所有作品在其中展列；“学习路径”是其中一部作品 |
| 个人资料 | 本地头像、笔名展示；支持上传头像和编辑笔名，头像下方文字为笔名 |
| 写作特点 | 版本化 `StyleProfile`，作品默认、章节可覆盖 |
| 大纲 | 卷 → 章 → 详细节点，可关联章节；不自动生成章节 |
| 作品结构 | 作品 → 可选分卷 → 章节 → 正文段落；无分卷可直接建章 |
| 固定样式编辑 | 微软雅黑 12 pt、1.5 倍行距、`#242424` 正文；微软雅黑 16 pt、加粗、`#1C1C1C` 章节标题 |
| 实时字数 | 只计汉字、字母和数字；书签、标点、空格、换行不计入 |
| 知识库 | 手工条目、层级分类、主分类、标签、来源、全文搜索、标签 AND 筛选 |
| 引用与伏笔 | 可点击行内书签；点击查看详情；伏笔五状态和证据 |
| 基础 AI | 段落润色、单句润色、续写、纠错、一致性检查、剧情感受、正文回写 |
| 版本与保存 | 实时自动保存、手动快照、恢复为新版本、保存失败保护 |
| 备份与导入 | `.rainsoul` 项目归档；TXT/DOCX 手稿导入为新作品 |
| 导出 | DOCX、TXT；引用编号和伏笔清单按规则输出 |

### 4.2 后置扩展候选（阶段待评估）

以下功能保留入口但不承诺首版交付，也不预先指定为 P1 或 P2；每项通过第 9.2 节的独立评估后再确定阶段：

- 需求会话、跨作品分析。
- 手工拆文、自动拆文和 URL 导入。
- XMind 导入（目标覆盖所有 XMind 版本）。
- 关键词不足且有真实查询证据后的向量检索。
- 搜索和 AI 使用数据分析。
- EPUB/PDF 导出、章节生成、AI 风格自动提取、全局 AI 知识库配置。

每项功能单独评估；必须同时有真实需求证据、数据安全方案、失败恢复方案和可验证质量门槛，满足后才进入开发。进入扩展候选不代表自动排期。

## 5 页面结构与导航

### 5.1 全局导航

侧栏始终显示全部入口：

1. 头像：显示本地头像，可上传。
2. 笔名：显示在头像下方，可直接编辑。
3. 我的作品：进入唯一作品集，以书架形式展列所有作品。
4. 知识库：进入当前作品知识库或 P0 只读全局汇总；汇总仅展示知识条目并标注所属作品。
5. 需求会话：后置功能入口。
6. 设置：固定样式、AI 服务配置、数据导入导出和高级管理。

已交付功能正常进入；后置功能统一显示：**“后续开发：本功能尚未交付”**，同时标注当前阶段并提供返回按钮，不进入空白页面，也不伪装成可用功能。

### 5.2 页面地图

```text
我的作品（唯一作品集）
├── 作品书架
│   └── 作品详情
│       ├── 写作特点（StyleProfile）
│       ├── 大纲：卷 → 章 → 详细节点
│       ├── 伏笔架构：五状态和证据
│       └── 章节写作页
│           ├── 固定样式编辑器、实时字数、保存状态
│           ├── 行内知识/伏笔书签详情
│           └── AI 操作：润色、续写、纠错、分析、回写
知识库
├── 当前作品条目管理
├── P0 全局知识条目只读汇总（显示所属作品）
└── 分类、标签、来源和搜索
需求会话（后置）
└── 统一后续开发提示
设置
├── AI 服务与授权
├── 归档导入/导出
└── 分类字典与高级管理
```

### 5.3 页面交互规则

1. 启动后进入“我的作品”，没有作品时显示创建作品入口，不显示空白正文。
2. 一次只编辑一个作品；切换前必须完成保存。
3. 侧栏有明确选中状态，收起后仍保留图标入口和可访问名称。
4. 笔名与作品数据是不同数据域，修改笔名不改变作品标题或历史正文。
5. 所有加载、保存、导入、导出、AI 请求和失败状态都要有可读提示。

## 6 核心功能规格

### 6.1 作品集、作品与个人资料

- 作品集固定为“我的作品”，不建立独立的学习合集。
- 每个作品有独立数据域；“学习路径”作为普通作品展列在书架中。
- 作品删除、归档、恢复需确认，并保留可恢复路径。
- 作品默认数据目录为 `%LOCALAPPDATA%\RainSoul\Projects`，用户可选择备份位置。
- 头像存储在本机应用数据目录，笔名实时保存。

### 6.2 作品结构、编辑器与字数

作品结构为“作品 → 可选分卷 → 章节 → 正文段落”。分卷可为空；无分卷时章节直接挂在作品下。正文使用固定样式的所见即所得编辑器，编辑器内视觉效果与 DOCX 导出样式一致。首版不提供字体、字号、行距或颜色自定义；未来是否开放自定义另行评估。

字数统计口径为汉字、英文字母和数字。标点、空格、换行、知识引用标记和伏笔书签标记均不计入。每章显示实时字数，作品和分卷显示汇总值。

### 6.3 写作特点与大纲

`StyleProfile` 版本化保存人称、节奏、禁用项、参考作品等规则。作品有默认配置，章节可覆盖；覆盖关系和生效版本可追溯。

大纲为“卷 → 章 → 详细节点”树。节点可关联章节、知识条目和伏笔；首版不支持节点自动生成章节。大纲编辑也必须遵守自动保存和版本规则。

### 6.4 伏笔架构与正文书签

伏笔状态为：未埋设、已埋设、已触发、已回收、废弃。每个伏笔记录埋设、触发、回收的章节/段落证据，并可从正文书签反向定位。

知识引用和伏笔都显示可点击的行内书签标记。作者可从编辑器工具栏或段落上下文菜单选择“插入知识引用”或“插入伏笔书签”；目标默认为光标所在段落，选中多个段落时使用当前选区的首个段落，并在插入前选择已有条目或伏笔。点击书签打开详情并可定位回原段落，标记不计字数。书签使用稳定目标 ID，不依赖正文字符偏移；段落移动后仍可定位到段落和锚点。删除行内标记只移除当前正文中的关联，不删除知识条目或伏笔。

### 6.5 知识库、分类、搜索与引用

1. 知识条目按作品保存。全局页面可汇总查看，但只能编辑当前作品条目；跨作品复用时复制条目并保留来源作品和原条目 ID。
2. 首版支持动态层级分类字典；作者可新增、重命名、调整排序和移动分类。每条知识只有一个主分类，可附多个标签。移动分类时不得把分类移到自身或其后代下，系统必须阻止形成环状父级关系。多个标签按 AND 筛选，空筛选显示全部。
3. 删除分类前必须把条目迁移到其他分类或“未分类”，迁移完成后才能删除分类；空分类删除后不影响条目历史。
4. 搜索同时覆盖正文和知识条目标题/内容，结果显示来源、匹配片段并支持定位；中文单字、短词和长词都必须可命中。
5. 搜索性能验收使用固定基线：100 章、统计字数 100 万、1000 条知识条目；测试机为四核 CPU、8 GB 内存、SSD 的 Windows 10/11 64 位环境。测试夹具必须以版本控制文件保存（建议 `tests/fixtures/search-baseline-v1.json`），包含固定数据集和 20 条查询的具体内容；若通过脚本生成，必须固定随机种子并记录生成器版本。预热一次后，20 条查询各执行 10 次，覆盖单字、双字、长词、无结果和标签筛选，得到 200 个样本；将 200 个样本合并排序，按 nearest-rank 计算 P95（位置为 `ceil(0.95 × 200) = 190`，从 1 开始计数），预热样本不纳入统计。从发起查询到结果显示测量 UI 延迟，P95 ≤ 1 秒。夹具变更必须递增版本并记录原因；该样本只用于回归测试，不限制作者作品规模。
6. 条目编辑后，正文引用显示最新内容；软删除后保留“已删除条目”、原 ID、标题和来源，引用仍可追溯。

### 6.6 保存、快照、恢复与备份

- 停止输入约 500ms 后自动保存；持续输入最长 5 秒必须强制落盘。
- 切换章节、作品、快照、备份、导出和关闭前先保存。
- 保存失败时保留编辑区内容，显示失败原因和重试入口；在成功保存前阻止切换、快照、备份、导出和关闭。
- 手动快照保存整部作品的完整状态，包括大纲、写作特点、分卷、章节、正文、知识条目、分类、标签、引用和伏笔。
- 恢复旧快照会先把恢复前的当前状态保存为可访问的新版本/快照，再把旧快照复制为新的当前版本；当前状态和全部历史保留，不覆盖历史记录。恢复任一步失败都回滚事务，恢复前的当前状态和历史记录保持不变。
- `.rainsoul` 归档包含格式清单、版本信息和校验信息。导入先校验，成功后创建新项目，不覆盖已有项目。
- Windows 卸载默认保留作品数据，只有用户明确选择删除时才删除。
- 启用单实例锁；第二次启动聚焦已有窗口并提示，不允许并发写入。

### 6.7 TXT/DOCX 手稿导入

- TXT/DOCX 手稿导入始终创建新作品，不直接写入当前作品。
- 识别常见章节标题，作者在预览中可修改拆章结果；识别不到时整份作为一章。
- DOCX 只导入正文段落和可识别标题；图片、表格等不导入，预览时明确提示。
- 这里的章节标题识别只服务于 TXT/DOCX 手稿导入预览，不等同于后置的独立手工/自动拆文工具；后置工具另行定义知识抽取、分类和审核流程。
- 导入失败不覆盖现有项目，保留错误报告和可重试入口。

### 6.8 AI 操作、安全和候选确认

首版 AI 操作包括段落润色、单句润色、续写、纠错、一致性检查、剧情感受和正文回写。上下文支持当前章节、前章衔接、全卷和自定义范围。上下文过长时提示作者，选择分块或缩小范围，禁止静默截断。

正文修改统一走以下流程：

1. 作者选择操作和上下文范围。
2. 若使用云端模型，显示服务/模型、实际发送范围、预计费用或计费提示和取消按钮；作者确认后才发送。
3. 生成候选结果并与原文并排或逐段对比。
4. 若原文在生成期间发生变化，要求重新生成或重新对比。
5. 确认写入前自动创建快照；确认后才写入新版本。

API Key 使用 Windows Credential Manager 或 Electron `safeStorage`/DPAPI 保存，不进入 `.rainsoul`、日志或错误报告。云端请求超时、断网或额度不足时保留原文和候选状态，显示原因，由作者手动重试，不自动重发。

一致性检查覆盖角色、时间、地点、伏笔、大纲偏离和写作特点漂移。规则型结果必须提供可定位证据；AI 结果标为“AI 建议”，不能自动修改正文。

“剧情感受”根据大纲和上下文评价衔接、合理性和是否偏离剧情。结果必须标为“AI 建议”，显示证据和不确定性，不自动改稿。

正文回写由 AI 提取摘要、角色、事件、伏笔等候选；作者逐条审核后入库，并保存来源章节、段落和正文版本。未审核候选不能成为正式知识条目。

### 6.9 DOCX/TXT 导出

- 按分卷、章节和段落顺序导出；无分卷时直接按章节顺序导出。
- DOCX 映射固定字体、字号、行距、颜色和标题加粗放大规则；TXT 输出纯文本顺序。
- 知识引用在正文保留引用标记并转换为编号；同一知识条目重复引用复用编号，文末按首次出现顺序列一次引用清单。
- 伏笔在正文保留 `[伏笔：名称]` 标记，文末附伏笔清单、状态及章节/段落证据；伏笔标记不计字数。
- 导出失败明确提示，原数据和当前版本不被覆盖；用户可重试或选择新位置。

### 6.10 后置功能边界

- XMind 未来目标支持所有 XMind 版本；开发时建立官方格式版本兼容矩阵和逐版本样例测试。导入先保存为临时导入草稿，作者确认后才写入大纲，解析失败或部分成功时尽量保留已解析内容，不能直接污染现有大纲。
- URL 导入仅支持作者有权使用的公开网页；限制协议、私网地址、重定向、大小和时间，不突破反爬。
- 向量检索只有在真实查询证据证明关键词不足后才进入开发。
- 需求会话、跨作品分析、自动拆文等功能必须有扫描范围、隐私边界、取消、失败恢复和版本写入规则后再开发。

### 7.1 核心实体

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |

| 大纲节点 | `id`, `work_id`, `parent_id`, `title`, `sort_order`, `chapter_id` | 树节点可关联章节 |
| 知识分类 | `id`, `work_id`, `parent_id`, `name`, `sort_order` | 可新增、改名、移动和排序；删除前迁移，禁止环状父级关系 |

| 伏笔 | `id`, `work_id`, `outline_node_id`, `name`, `status` | 五状态和证据列表 |
| 正文版本 | `id`, `work_id`, `reason`, `created_at` | AI、恢复和手动版本均记录 |
| 快照 | `id`, `work_id`, `revision_id`, `reason`, `created_at` | 保存整部作品及知识状态 |
| AI 候选 | `id`, `work_id`, `operation`, `scope`, `source_revision`, `status` | 候选、确认、取消、失败 |
| 导入草稿 | `id`, `work_id`, `format`, `raw_manifest`, `parsed_content`, `status` | XMind 等导入先落草稿 |
| 学习卡 | `id`, `feature`, `content`, `created_at` | 开发学习产物 |

### 7.2 逻辑规则

1. 实体使用稳定 ID；软删除保留来源和历史引用。
2. 引用只关联稳定知识/伏笔 ID 和段落锚点，不把易变正文偏移作为唯一定位。
3. 快照恢复生成新版本，任何历史版本不可被覆盖。
4. AI 候选未经作者确认不得写入正文；回写候选未经逐条审核不得入库。
5. 归档导入、手稿导入和 XMind 草稿导入不得覆盖既有项目。
6. 作品内知识版本随快照保存；跨作品复用只能复制并保留来源。
7. 大纲、章节、段落、知识和伏笔之间不能形成无审核的循环污染。

## 8 技术架构与安全

### 8.1 技术选型

| 层 | 技术 | 责任 |
| --- | --- | --- |
| 桌面壳 | Electron | 主进程、窗口、文件系统、单实例锁、安全策略 |
| 前端 | React + TypeScript | 编辑器、导航、候选对比、状态展示 |
| 预加载 | Electron preload | 只开放明确的读写命令，不暴露任意 Node API |
| 数据库 | SQLite | 本地作品、版本、知识、索引和迁移 |
| 搜索 | SQLite FTS5 或等价本地全文索引 | 正文和知识条目关键词搜索 |
| AI 学习路径 | Python/FastAPI | 学习与验证用适配实验；首版客户端不要求启动本地服务 |
| 构建 | React/TypeScript 对应的 Vite/Electron 构建链 | 开发、测试和 Windows 打包 |

### 8.2 离线与在线策略

| 功能 | 断网可用 | 说明 |
| --- | --- | --- |
| 写作、保存、搜索 | 是 | 本地 SQLite 和全文索引 |
| 版本、快照、归档 | 是 | 数据不依赖云端 |
| DOCX/TXT 导出 | 是 | 导出到用户选择的位置 |
| 全部首版 AI 操作（段落/单句润色、续写、纠错、一致性检查、剧情感受、正文回写） | 否（首版） | 首版仅支持云端适配层；断网时不发起、不排队请求，恢复联网后由作者手动重试；本地 Ollama/本地模型后置 |
| URL 下载 | 否 | 后置功能，需网络和安全限制 |
| 本地 Ollama/本地模型 | 后置 | 有真实需求和资源后评估 |

### 8.3 本地路径、密钥和日志

- 默认作品目录：`%LOCALAPPDATA%\RainSoul\Projects`。
- API Key 仅写入 Windows Credential Manager 或 Electron `safeStorage`/DPAPI。
- 日志记录阶段、错误码、项目 ID 和请求状态，不记录正文、密钥、完整提示词或候选内容。
- `.rainsoul` 不包含 API Key；导出和错误报告不泄露密钥。

### 8.4 SQLite 升级

使用版本化前向迁移。升级前创建数据库备份；迁移失败时恢复备份并阻止启动，提示用户保存诊断信息。不做自动降级，不在迁移失败时继续写入。

## 12 附则

- 本方案是当前需求基线；新增或改变功能必须记录变更原因、影响范围、数据迁移和验收标准。
- 后置功能没有真实需求和质量证据时，不进入排期，不以入口存在代替交付。
- 代码、测试、构建和文档交付遵循仓库 `AGENTS.md` 的中文提交、测试和审查规范。
- 评审报告用于解释问题、风险和对比依据；它与本方案同时保留。
