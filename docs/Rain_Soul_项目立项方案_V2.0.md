## 1 项目概述

### 1.1 项目背景

网文写作常见设定分散、大纲与正文脱节、伏笔遗忘、素材难复用、AI 修改不可控和版本混乱等问题。Rain_Soul 为作者提供本地优先的写作工作台，把写作特点、大纲、章节、段落、知识库、引用、伏笔、AI 辅助、版本和导出连接成可追溯闭环。

### 1.2 产品定位

Rain_Soul 是一个**作者可控的网文写作工作台**。写作是主产品，知识库和 AI 是支撑能力，学习路径是开发过程中的内部学习产物，最终整理为“学习路径”作品。产品不承诺一键生成完整小说，也不以 AI 替代作者判断。

- **写作系统**：从写作特点、大纲、章节到定稿导出。
- **知识系统**：按作品维护描写、引用等完整写作素材、分类、标签、来源和正文引用，供作者学习、仿写以及 AI 检索参考。
- **AI 系统**：在作者授权和候选确认下完成润色、续写、纠错、分析和回写。
- **学习路径**：学习卡随功能开发记录，作品集功能完成后集中整理，不阻断作者功能交付。

### 1.3 立项结论

首版（P0）采用 V2.0 完整主写作流程：写作特点、大纲、知识库与分类、伏笔、基础 AI、剧情感受、一致性检查、正文回写、版本与备份、DOCX/TXT 导出。需求会话、跨作品分析、手工/自动拆文、URL 导入、XMind 导入、向量检索等作为扩展，逐项通过真实需求和安全/质量门槛后再开发。

### 1.4 资源与验证边界

- 首版目标平台为 Windows 10/11 64 位，普通用户可安装运行。
- 首版单机单用户，一次只允许一个 Rain_Soul 窗口写入。
- 首版不要求真实作者试用，只做开发团队测试；这会降低产品需求验证强度，必须作为发布风险记录。
- 作者可自行决定作品长度，产品不设置中短篇、章节数或总字数上限。性能测试样本只用于性能验收，不构成写作限制。

## 2 目标与价值

### 2.1 产品目标

1. 作者可在断网状态下创建作品、写作、保存、搜索、查看版本、备份和导出。
2. 大纲、正文、知识条目、引用和伏笔之间有稳定 ID 和可定位证据。
3. AI 只生成候选或分析建议；正文写入必须经过作者对比和确认。
4. 正文回写知识库必须经过逐条审核，不能无审核地污染正文或知识库。
5. 所有导入、导出、恢复和迁移失败都保留原数据，并给出可操作提示。

### 2.2 用户价值

作者可以在一个本地工作台中组织长篇写作资产，减少跨工具复制粘贴；知识引用和伏笔可追溯；AI 的发送范围、费用、候选结果和版本变化透明可控。知识库积累优秀写作片段，作者可学习写法并进行仿写；AI 可针对当前正文检索相关描写，比较写法的长处与不足，提出由作者决定是否采用的修改候选。

### 2.3 学习价值

学习卡根据当前项目结构编写，覆盖 Electron、React/TypeScript、SQLite、Python/FastAPI、AI 适配、数据结构和验收实验。大纲用于组织模块和步骤，伏笔架构用于记录接口、路由、前后端对接、数据流等联系。学习卡是开发知识产物，不是作者使用门槛；作品集功能完成后统一整理进“学习路径”作品。

### 2.4 成功标准

- 开发团队能够在 Windows 10/11 64 位上完成从创建作品到 DOCX/TXT 导出的端到端测试。
- 断网时写作、保存、搜索、版本、备份和导出仍可用。
- 章节字数实时更新，统计汉字、字母和数字，不统计标点、空格、换行及书签标记。
- 搜索同时覆盖正文和知识条目，标签 AND 筛选正确，固定本地样本 UI 搜索 P95 ≤ 1 秒。
- AI 操作有授权、范围、费用提示、候选对比、版本保护和失败重试边界。

## 3 用户、场景与非目标

### 3.1 目标用户

| 维度 | 描述 |
| --- | --- |
| 身份 | 网文作者，单机写作 |
| 技术背景 | 有浅编程基础，希望通过项目学习 AI、后端和 Python |
| 设备 | Windows 10/11 64 位 |
| 网络 | 写作核心流程可断网；AI 由作者选择是否连接云端 |

### 3.2 核心场景

进入“作品集”书架 → 创建或打开作品 → 设置写作特点 → 编写卷/章/详细节点大纲 → 创建章节 → 编辑正文 → 插入知识引用和伏笔书签 → 使用基础 AI 并确认候选 → 做一致性和剧情感受检查 → 审核正文回写 → 创建版本/备份 → 导出 DOCX/TXT。

### 3.3 非目标

- 不做多人实时协作、账号同步或云端作品存储。
- 不做一键自动生成完整长篇小说。
- 不内置版权内容库，不绕过网站反爬或访问私网地址。
- 首版不做向量检索、本地 Ollama/本地模型、EPUB/PDF、需求会话、跨作品分析、自动拆文、URL 下载和 XMind 导入。

## 4 产品范围与阶段

### 4.1 P0：完整主写作流程

| 功能 | 首版要求 |
| --- | --- |
| 作品集书架 | 系统只有一个作品集，所有作品在其中展列；“学习路径”是其中一部作品 |
| 个人资料 | 本地头像、头像下方直接显示笔名，不出现“笔名”标签；支持上传头像和编辑笔名 |
| 写作特点 | 版本化 `StyleProfile`，作品默认、章节可覆盖 |
| 剧情架构（大纲） | 卷 → 章 → 详细节点，可关联章节，并多选同作品知识和伏笔；不自动生成章节 |
| 作品结构 | 作品 → 可选分卷 → 章节 → 正文段落；无分卷可直接建章 |
| 固定样式编辑 | 微软雅黑 12 pt、1.5 倍行距、`#242424` 正文；微软雅黑 16 pt、加粗、`#1C1C1C` 章节标题 |
| 实时字数 | 只计汉字、字母和数字；书签、标点、空格、换行不计入 |
| 知识库 | 完整写作素材、无独立标题的两行卡片和原位展开、层级分类、主分类、标签、来源、内容/出处/标签搜索、标签 AND 筛选 |
| 引用与伏笔 | 可点击行内书签；点击查看详情；伏笔五状态和证据 |
| 基础 AI | 段落润色、单句润色、续写、纠错、一致性检查、剧情感受、正文回写 |
| 版本与保存 | 实时自动保存、手动快照、恢复为新版本、保存失败保护 |
| 备份与导入 | `.rainsoul` 项目归档；TXT/DOCX 手稿导入为新作品 |
| 导出 | DOCX、TXT；引用编号和伏笔清单按规则输出 |

### 4.2 后置扩展候选（阶段待评估）

以下功能保留入口但不承诺首版交付，也不预先指定为 P1 或 P2；每项通过第 9.2 节的独立评估后再确定阶段：

- 需求会话、跨作品分析。
- 手工拆文、自动拆文和 URL 导入。
- XMind 导入（目标覆盖所有 XMind 版本）。
- 关键词不足且有真实查询证据后的向量检索。
- 搜索和 AI 使用数据分析。
- EPUB/PDF 导出、章节生成、AI 风格自动提取、全局 AI 知识库配置。

每项功能单独评估；必须同时有真实需求证据、数据安全方案、失败恢复方案和可验证质量门槛，满足后才进入开发。进入扩展候选不代表自动排期。

## 5 页面结构与导航

### 5.1 全局导航与视觉

整体为白色 Codex 风格，天蓝色用于主按钮、选中态和链接；保留第一版 RainSoul 标题与倾斜方框、右上圆点 Logo。使用细边框、克制阴影和小圆角，不用大面积蓝色装饰框。正文编辑器获得焦点时不出现蓝色方框，其他交互控件保留清晰的键盘焦点提示。每页主标题仅出现一次。

侧栏默认收起，方框内三条横线的菜单按钮可展开/收起；展开时显示头像、笔名和导航，设置固定在底部。窄屏展开时作为覆盖式抽屉，可通过遮罩关闭。导航保留全部入口：

1. 头像：显示本地头像，可上传。
2. 头像下方直接显示笔名：可编辑，不显示“笔名”两个字。
3. 作品集：进入唯一作品集，以书架形式展列所有作品。
4. 知识库：默认当前作品，可通过范围下拉选择另一部作品或“全部作品”只读汇总，标注所属作品；仅能编辑当前作品条目。
5. 需求会话：后置功能入口。
6. 设置：纵向单列分组管理个人资料、固定编辑样式、知识库分类/标签、本机数据和云端 AI。

正式产品中，已交付功能正常进入；后置功能统一显示：**“后续开发：本功能尚未交付”**，同时标注当前阶段并提供返回按钮。Demo 的需求会话与拆书工具可以进入参考工作区，但须按第 5.4 节说明演示范围，不能据此宣称正式功能已交付。

### 5.3 页面交互规则

1. 启动后进入“作品集”，只使用“作品集”名称，不叫“我的作品”；没有作品时显示创建入口。作品集不显示“已保存”、冗余介绍或“最近编辑优先”，新建作品按钮只放在作品集。
2. 一次只编辑一个作品；切换前必须完成保存。
3. 侧栏有明确选中状态，收起后仍保留图标入口和可访问名称。
4. 笔名与作品数据是不同数据域，修改笔名不改变作品标题或历史正文。
5. 所有加载、保存、导入、导出、AI 请求和失败状态都要有可读提示。
6. 作品卡片、卷和章节支持右键、`Shift+F10` 或菜单键打开删除菜单；打开确认弹窗前关闭菜单，弹窗标题分别为“删除作品”“删除卷及章节”“删除章节”。确认前不改数据，保存失败时禁止删除；删除后清理失效关联并保留正式版恢复路径。
7. 作品内显示“正文 / 剧情架构 / 伏笔架构”标签页，切换不改变当前作品；键盘可切换，保存失败时不允许离开正文。无节点、无伏笔和无搜索结果均有可操作空状态。

需求会话参考布局沿用 Codex：作品作为项目，作品下开启会话；内容区显示作品名、会话列表和对话区，不重复放“需求会话”标题和新建作品按钮，不显示“当前上下文”框。会话右侧删除按钮在悬停或键盘聚焦时显示，删除需确认；切换作品不混用消息，删除当前会话后选同作品剩余会话，无会话时显示空状态。

## 6 核心功能规格

### 6.1 作品集、作品与个人资料

- 系统固定一个作品集，不建立独立的学习合集。
- 每个作品有独立数据域；“学习路径”作为普通作品展列在书架中。
- 作品删除、归档、恢复需确认，并保留可恢复路径。
- 作品默认数据目录为 `%LOCALAPPDATA%\RainSoul\Projects`，用户可选择备份位置。
- 头像存储在本机应用数据目录，笔名保存到本地作者档案。侧栏直接呈现名称，设置中使用“显示名称”维护。

### 6.2 作品结构、编辑器与字数

作品结构为“作品 → 可选分卷 → 章节 → 正文段落”。分卷可为空；无分卷时章节直接挂在作品下。正文使用固定样式的所见即所得编辑器，编辑器内视觉效果与 DOCX 导出样式一致。首版不提供字体、字号、行距或颜色自定义；未来是否开放自定义另行评估。

字数统计口径为汉字、英文字母和数字。标点、空格、换行、知识引用标记和伏笔书签标记均不计入。每章显示实时字数，作品和分卷显示汇总值。

### 6.3 写作特点与大纲

`StyleProfile` 版本化保存人称、节奏、禁用项、参考作品等规则。作品有默认配置，章节可覆盖；覆盖关系和生效版本可追溯。

大纲在界面中称为“剧情架构”，为“卷 → 章 → 详细节点”树；未建卷时可直接创建章级节点。支持新增、重命名、内容编辑、展开/收起、同级排序及确认删除。大纲节点与正文章节是不同对象，节点可关联一章、多个知识条目和多个伏笔，范围限当前作品；关联不会创建或覆盖正文章节。大纲编辑也必须遵守自动保存和版本规则。

关联知识与关联伏笔统一采用多选下拉：

- 按钮显示“关联知识条目”或“关联伏笔”提示，提示本身不是下拉选项；列表只显示真实条目，复选框在每行右侧。
- 勾选后立即显示在下方关联区，可继续勾选多个，不因一次选择而关闭；取消勾选同步移除，下方移除操作也同步取消勾选。
- 已选项目仍在列表中，并显示勾选状态；下方每项可跳转到知识全文或伏笔详情。空列表显示空状态，点击外部或按 Escape 可关闭，键盘和窄屏均可操作。
- 一个剧情节点可关联多个伏笔，每个伏笔同一时刻只归属一个剧情节点。已属于其他节点的伏笔须在勾选前显示“当前关联：原节点；勾选后移到本节点”；勾选即确认并立即转移，不勾选不改原关联。取消关联只解除所属节点，不删除伏笔或证据。
- 删除剧情节点和下级节点后保留知识、伏笔及其正文证据，仅清理失效关联；不得跳转到别的章节或作品。

### 6.4 伏笔架构与正文书签

伏笔状态为：未埋设、已埋设、已触发、已回收、废弃。每个伏笔记录埋设、触发、回收的章节/段落证据，一个阶段可有多条证据，并可从正文书签反向定位。状态修改不自动生成证据；缺少证据明确显示“尚无证据”。正文来源失效时保留原出处，禁止错误定位，并提供清理或重新关联入口。

知识引用和伏笔都显示可点击的行内书签标记。作者可从编辑器工具栏或段落上下文菜单选择“插入知识引用”或“插入伏笔书签”；目标默认为光标所在段落，选中多个段落时使用当前选区的首个段落，并在插入前选择已有条目或伏笔。点击书签打开详情并可定位回原段落，标记不计字数。书签使用稳定目标 ID，不依赖正文字符偏移；段落移动后仍可定位到段落和锚点。删除行内标记只移除当前正文中的关联，不删除知识条目或伏笔。

### 6.5 知识库、分类、搜索与引用

1. 知识条目按作品保存。全局页面可汇总查看，但只能编辑当前作品条目；跨作品复用时复制条目并保留来源作品和原条目 ID。
2. 知识内容包括人物描写、景物描写、内心描写、经典引用、剧情与伏笔等完整写作素材。条目只有一份完整内容，不另设必填标题；卡片收起时最多显示内容前两行，点击原位展开同一份全文，再次点击收起。始终保留标签和右下角出处，长出处可换行，汇总时标注所属作品；移除独立“条目详情”面板。
3. 首版支持动态层级分类字典；作者在设置中维护分类和标签，可新增、重命名、调整排序和移动分类。每条知识只有一个主分类，可附多个标签。移动分类时不得把分类移到自身或其后代下，系统必须阻止形成环状父级关系。多个标签按 AND 筛选，空筛选显示全部。知识页只关联已维护标签，不因录入内容隐式创建标签；标签支持名称内空格。
4. 删除分类前必须把条目迁移到其他分类或“未分类”，迁移完成后才能删除分类；空分类删除后不影响条目历史。删除已使用标签需确认，只解除标签关联，不删除知识正文。
5. 知识页顶部保留一个模糊搜索框，按内容、出处和标签匹配，并与分类、作品范围和 AND 标签筛选共同生效；这里的“模糊”指关键词/子串匹配，不承诺语义或拼写纠错。正式全文搜索同时覆盖正文和知识内容，结果显示来源、匹配片段并支持定位；中文单字、短词和长词都必须可命中。
6. 搜索性能验收使用固定基线：100 章、统计字数 100 万、1000 条知识条目；测试机为四核 CPU、8 GB 内存、SSD 的 Windows 10/11 64 位环境。测试夹具必须以版本控制文件保存（建议 `tests/fixtures/search-baseline-v1.json`），包含固定数据集和 20 条查询的具体内容；若通过脚本生成，必须固定随机种子并记录生成器版本。预热一次后，20 条查询各执行 10 次，覆盖单字、双字、长词、无结果和标签筛选，得到 200 个样本；将 200 个样本合并排序，按 nearest-rank 计算 P95（位置为 `ceil(0.95 × 200) = 190`，从 1 开始计数），预热样本不纳入统计。从发起查询到结果显示测量 UI 延迟，P95 ≤ 1 秒。夹具变更必须递增版本并记录原因；该样本只用于回归测试，不限制作者作品规模。
7. 条目编辑后，正文引用显示最新内容；软删除后保留“已删除条目”、原 ID、内容摘要和来源，引用仍可追溯。
8. 知识页提供“新增知识”和“拆书工具”，分类侧栏可收起。新增知识保存当前作品的内容、主分类、现有标签和出处；分类/标签新增和维护集中在设置，不额外显示“新添知识库”按钮。正式 AI 以当前正文为线索，先在当前作品知识库做关键词检索，把相关片段与出处作为参考供作者审核，再按授权规则生成候选；不直接复制优秀原句充当作者正文，不未经确认自动入库或改稿。

### 6.6 保存、快照、恢复与备份

- 停止输入约 500ms 后自动保存；持续输入最长 5 秒必须强制落盘。
- 切换章节、作品、快照、备份、导出和关闭前先保存。
- 保存失败时保留编辑区内容，显示失败原因和重试入口；在成功保存前阻止切换、快照、备份、导出和关闭。
- 手动快照保存整部作品的完整状态，包括大纲、写作特点、分卷、章节、正文、知识条目、分类、标签、引用和伏笔。
- 恢复旧快照会先把恢复前的当前状态保存为可访问的新版本/快照，再把旧快照复制为新的当前版本；当前状态和全部历史保留，不覆盖历史记录。恢复任一步失败都回滚事务，恢复前的当前状态和历史记录保持不变。
- `.rainsoul` 归档包含格式清单、版本信息和校验信息。导入先校验，成功后创建新项目，不覆盖已有项目。
- Windows 卸载默认保留作品数据，只有用户明确选择删除时才删除。
- 启用单实例锁；第二次启动聚焦已有窗口并提示，不允许并发写入。

### 6.7 TXT/DOCX 手稿导入

- TXT/DOCX 手稿导入始终创建新作品，不直接写入当前作品。
- 识别常见章节标题，作者在预览中可修改拆章结果；识别不到时整份作为一章。
- DOCX 只导入正文段落和可识别标题；图片、表格等不导入，预览时明确提示。
- 这里的章节标题识别只服务于 TXT/DOCX 手稿导入预览，不等同于第 6.10 节的独立拆书/拆文工具。手稿导入的目标是新作品正文；拆书的目标是当前作品知识库中的写作参考。
- 导入失败不覆盖现有项目，保留错误报告和可重试入口。

### 6.8 AI 操作、安全和候选确认

首版 AI 操作包括段落润色、单句润色、续写、纠错、一致性检查、剧情感受和正文回写。上下文支持当前章节、前章衔接、全卷和自定义范围。上下文过长时提示作者，选择分块或缩小范围，禁止静默截断。

正文修改统一走以下流程：

1. 作者选择操作和上下文范围。
2. 作者可查看、选用知识库相关参考及出处。若使用云端模型，显示服务/模型、实际发送范围（正文、写作特点、大纲、知识参考等实际携带内容）、预计费用或计费提示和取消按钮；作者确认后才发送。
3. 生成候选结果并与原文并排或逐段对比。
4. 若原文在生成期间发生变化，要求重新生成或重新对比。
5. 确认写入前自动创建快照；确认后才写入新版本。

API Key 使用 Windows Credential Manager 或 Electron `safeStorage`/DPAPI 保存，不进入 `.rainsoul`、日志或错误报告。云端请求超时、断网或额度不足时保留原文和候选状态，显示原因，由作者手动重试，不自动重发。

一致性检查覆盖角色、时间、地点、伏笔、大纲偏离和写作特点漂移。规则型结果必须提供可定位证据；AI 结果标为“AI 建议”，不能自动修改正文。

“剧情感受”根据大纲和上下文评价衔接、合理性和是否偏离剧情。结果必须标为“AI 建议”，显示证据和不确定性，不自动改稿。

正文回写由 AI 提取摘要、角色、事件、伏笔等候选；作者逐条审核后入库，并保存来源章节、段落和正文版本。未审核候选不能成为正式知识条目。

### 6.9 DOCX/TXT 导出

- 按分卷、章节和段落顺序导出；无分卷时直接按章节顺序导出。
- DOCX 映射固定字体、字号、行距、颜色和标题加粗放大规则；TXT 输出纯文本顺序。
- 知识引用在正文保留引用标记并转换为编号；同一知识条目重复引用复用编号，文末按首次出现顺序列一次引用清单。
- 伏笔在正文保留 `[伏笔：名称]` 标记，文末附伏笔清单、状态及章节/段落证据；伏笔标记不计字数。
- 导出失败明确提示，原数据和当前版本不被覆盖；用户可重试或选择新位置。

### 6.10 后置功能边界

- 拆书工具（拆文）从作者有权使用的优秀作品中摘选值得学习的描写、句子和写法，加入当前作品知识库，供学习、仿写和 AI 参考，不创建新作品、不覆盖当前手稿。入口位于知识库顶部，打开独立工作区；正式流程为选择 TXT/DOCX → 识别正文/可识别标题 → 预览与逐段勾选 → 核对分类、标签、真实出处和权限 → 确认入库。图片、表格等复杂内容不导入并明确提示，未选段落不入库，失败保留当前选择和原知识数据。
- 当前 Demo 不读取所选文件正文，固定示例入库必须标记“演示样例”，不可伪称来自上传文件。自动拆文/URL 后置，须在真实内容解析和作者审核方案明确后单独评估。
- 需求会话正式实现以作品作为项目，作品下创建独立会话，按第 5.4 节布局开发；不能把示例消息或本地发送动作描述为已调用真实 AI。
- XMind 未来目标支持所有 XMind 版本；开发时建立官方格式版本兼容矩阵和逐版本样例测试。导入先保存为临时导入草稿，作者确认后才写入大纲，解析失败或部分成功时尽量保留已解析内容，不能直接污染现有大纲。
- URL 导入仅支持作者有权使用的公开网页；限制协议、私网地址、重定向、大小和时间，不突破反爬。
- 向量检索只有在真实查询证据证明关键词不足后才进入开发。
- 需求会话、跨作品分析、自动拆文等功能必须有扫描范围、隐私边界、取消、失败恢复和版本写入规则后再开发。

## 7 数据模型与一致性

### 7.1 核心实体

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 作者档案 | `avatar`, `pen_name` | 本地头像与笔名；界面直接显示名称，数据库字段为 `pen_name` |
| 作品集 | `id`, `name` | 系统固定一个作品集 |
| 作品 | `id`, `title`, `collection_id`, `updated_at`, `word_count` | 独立作品数据域 |
| 分卷 | `id`, `work_id`, `title`, `sort_order` | 可选 |
| 章节 | `id`, `work_id`, `volume_id`, `title`, `sort_order` | `volume_id` 可为空 |
| 段落 | `id`, `chapter_id`, `content`, `sort_order`, `revision_id` | 稳定段落 ID |
| 写作特点 | `id`, `work_id`, `version`, `persona`, `rhythm`, `taboos`, `refs` | 作品默认、章节覆盖 |
| 大纲节点 | `id`, `work_id`, `type`, `parent_id`, `title`, `summary`, `sort_order`, `chapter_id` | 剧情树节点可关联一章，章节关联可为空 |
| 大纲知识关联 | `outline_node_id`, `knowledge_id` | 多对多，同作品，组合唯一；取消关联不删除条目 |
| 知识分类 | `id`, `work_id`, `parent_id`, `name`, `sort_order` | 可新增、改名、移动和排序；删除前迁移，禁止环状父级关系 |
| 知识条目 | `id`, `work_id`, `category_id`, `body`, `source`, `origin_work_id`, `origin_entry_id`, `deleted_at` | 一份完整内容，无独立标题；一个主分类、多标签；复制保留来源 |
| 标签 | `id`, `work_id`, `name` | 条目多对多 |
| 引用书签 | `id`, `paragraph_id`, `kind`, `target_id`, `anchor` | `kind` 为知识或伏笔 |
| 伏笔 | `id`, `work_id`, `outline_node_id`, `name`, `status` | 五状态和证据列表 |
| 伏笔证据 | `id`, `foreshadow_id`, `kind`, `chapter_id`, `paragraph_id`, `excerpt`, `source_revision` | 埋设/触发/回收，可多条；保留原出处和失效状态 |
| 正文版本 | `id`, `work_id`, `reason`, `created_at` | AI、恢复和手动版本均记录 |
| 快照 | `id`, `work_id`, `revision_id`, `reason`, `created_at` | 保存整部作品及知识状态 |
| AI 候选 | `id`, `work_id`, `operation`, `scope`, `source_revision`, `status` | 候选、确认、取消、失败 |
| 导入草稿 | `id`, `work_id`, `format`, `raw_manifest`, `parsed_content`, `status` | XMind 等导入先落草稿 |
| 学习卡 | `id`, `feature`, `content`, `created_at` | 开发学习产物 |

### 7.2 逻辑规则

1. 实体使用稳定 ID；软删除保留来源和历史引用。
2. 引用只关联稳定知识/伏笔 ID 和段落锚点，不把易变正文偏移作为唯一定位。
3. 快照恢复生成新版本，任何历史版本不可被覆盖。
4. AI 候选未经作者确认不得写入正文；回写候选未经逐条审核不得入库。
5. 归档导入、手稿导入和 XMind 草稿导入不得覆盖既有项目。
6. 作品内知识版本随快照保存；跨作品复用只能复制并保留来源。
7. 大纲、章节、段落、知识和伏笔之间不能形成无审核的循环污染。
8. 大纲知识关联为同作品多对多；伏笔至多归属一个剧情节点，勾选前说明原归属与转移结果，勾选即确认；同一节点可选多个伏笔，取消只解除关联。
9. 删除章节/段落后相关证据保留原来源并标记失效；重新关联不冒充原始证据，也不能误指向同名对象。正式存储使用稳定 ID，Demo 的名称键不作为数据库方案。

## 8 技术架构与安全

### 8.1 技术选型

| 层 | 技术 | 责任 |
| --- | --- | --- |
| 桌面壳 | Electron | 主进程、窗口、文件系统、单实例锁、安全策略 |
| 前端 | React + TypeScript | 编辑器、导航、候选对比、状态展示 |
| 预加载 | Electron preload | 只开放明确的读写命令，不暴露任意 Node API |
| 数据库 | SQLite | 本地作品、版本、知识、索引和迁移 |
| 搜索 | SQLite FTS5 或等价本地全文索引 | 正文和知识条目关键词搜索 |
| AI 学习路径 | Python/FastAPI | 学习与验证用适配实验；首版客户端不要求启动本地服务 |
| 构建 | React/TypeScript 对应的 Vite/Electron 构建链 | 开发、测试和 Windows 打包 |

### 8.2 离线与在线策略

| 功能 | 断网可用 | 说明 |
| --- | --- | --- |
| 写作、保存、搜索 | 是 | 本地 SQLite 和全文索引 |
| 版本、快照、归档 | 是 | 数据不依赖云端 |
| DOCX/TXT 导出 | 是 | 导出到用户选择的位置 |
| 全部首版 AI 操作（段落/单句润色、续写、纠错、一致性检查、剧情感受、正文回写） | 否（首版） | 首版仅支持云端适配层；断网时不发起、不排队请求，恢复联网后由作者手动重试；本地 Ollama/本地模型后置 |
| URL 下载 | 否 | 后置功能，需网络和安全限制 |
| 本地 Ollama/本地模型 | 后置 | 有真实需求和资源后评估 |

### 8.3 本地路径、密钥和日志

- 默认作品目录：`%LOCALAPPDATA%\RainSoul\Projects`。
- API Key 仅写入 Windows Credential Manager 或 Electron `safeStorage`/DPAPI。
- 日志记录阶段、错误码、项目 ID 和请求状态，不记录正文、密钥、完整提示词或候选内容。
- `.rainsoul` 不包含 API Key；导出和错误报告不泄露密钥。

### 8.4 SQLite 升级

使用版本化前向迁移。升级前创建数据库备份；迁移失败时恢复备份并阻止启动，提示用户保存诊断信息。不做自动降级，不在迁移失败时继续写入。

## 9 实施路线与进阶门槛

### 9.1 P0 实施顺序

1. Electron 窗口、preload 命令边界、单实例锁和本地路径。
2. SQLite schema、版本迁移、作品/卷/章/段落和自动保存。
3. 固定编辑器、字数统计、作品书架、头像和头像下方笔名。
4. 大纲、写作特点、知识分类/标签/搜索、引用和伏笔书签。
5. 快照、恢复、`.rainsoul` 归档、TXT/DOCX 手稿导入。
6. 云端 AI 适配层、授权提示、候选对比、版本保护和失败重试。
7. 一致性/剧情感受建议、正文回写审核、DOCX/TXT 导出。

### 9.2 后置扩展评估顺序

后置功能不按整批承诺，也不因列入候选就自动获得 P1 或 P2 阶段。每项功能必须先补充 ADR 或需求记录，说明：用户问题、数据范围、隐私和安全、失败恢复、质量指标、测试样本、对现有模型的影响和退出方案。通过独立评估后再确定阶段。

建议评估顺序（仅表示先后，不代表阶段承诺）：

- 第一批评估候选：手工拆文、EPUB/PDF、跨作品分析、搜索/AI 使用数据分析。
- 后续评估候选：需求会话、URL/自动拆文、XMind、向量检索、本地模型。

## 10 验收标准

### 10.1 P0 产品验收

- [ ] Windows 10/11 64 位普通用户可安装、启动、卸载；卸载默认保留作品数据。
- [ ] 第二次启动聚焦已有窗口并提示，不产生并发写入。
- [ ] “作品集”书架可创建、打开和切换作品；“学习路径”作为普通作品展列。
- [ ] 作品 → 可选分卷 → 章节 → 正文段落结构可用，无分卷可直接建章。
- [ ] 个人头像可上传，头像下方直接显示并可编辑笔名，不显示“笔名”标签；侧栏默认收起、方框三横线按钮可展开，设置位于侧栏底部。
- [ ] 整体白色、天蓝色交互重点、第一版 Logo 和 RainSoul 标题；同页主标题不重复，作品集没有“已保存”和冗余介绍，写作/会话页没有新建作品按钮，正文焦点没有蓝色方框。
- [ ] 作品、卷、章节右键/键盘删除菜单与确认弹窗可用，确认时旧菜单关闭；取消不改数据，保存失败禁止删除，正式版删除保留恢复路径。
- [ ] 固定样式所见即所得：编辑器直接呈现最终样式，并与 DOCX 导出的字体、字号、行距、颜色和标题加粗放大规则一致。
- [ ] 每章实时统计汉字、字母和数字；标点、空格、换行和书签不计入。
- [ ] 写作、保存、搜索、版本、备份和导出在断网时可用；默认数据位于 `%LOCALAPPDATA%\RainSoul\Projects`，未获得作者逐次确认时不发送正文到云端。
- [ ] 500ms 停顿保存，连续输入最长 5 秒落盘；保存失败时保留内容并阻止切换、快照、备份、导出和关闭。
- [ ] 写作特点可版本化，作品默认值和章节覆盖可追溯。
- [ ] 当前作品有“正文 / 剧情架构 / 伏笔架构”标签页；剧情树支持卷、章、详细节点、展开、编辑、同级排序和章节关联；首版不自动生成章节。
- [ ] 关联知识与关联伏笔下拉只列真实项目，提示不是选项，右侧复选框可多选；勾选立即显示下方、取消/移除双向同步、已选项仍显示勾选；伏笔勾选前说明原节点与转移结果，勾选立即转移，不勾选不改关联；键盘、窄屏和无候选空状态可用。
- [ ] 知识条目、层级分类、主分类、标签、来源和软删除可用；分类可新增、改名、排序和移动，移动到自身或后代时必须阻止，删除分类前必须把条目迁移到其他分类或“未分类”。
- [ ] 知识卡不要求独立标题，默认最多两行，点击原位展开同一份全文，保留标签和右下角出处；分类包括人物/景物/内心描写、经典引用等，可收起分类侧栏；一个搜索框检索内容、出处和标签，与作品范围、分类和标签 AND 共同生效。
- [ ] 设置为纵向分组，维护分类/标签和个人资料；新增知识只选择现有标签；跨作品只读查看，复制复用保留原出处和原 ID，不把他作条目直接变成当前作品资产。
- [ ] 正文和知识条目可全文搜索，结果标注来源、匹配片段并可定位；标签按 AND 筛选、空筛选显示全部，中文单字/短词命中；按第 6.5 节固定数据集、设备、查询集和测量方法验收 UI 搜索 P95 ≤ 1 秒。
- [ ] 可从工具栏或段落菜单把知识引用/伏笔插入光标所在段落（多段选区取首段）；书签可点击查看详情并定位，段落移动后仍按稳定 ID 定位，删除标记只移除当前关联；条目编辑后引用显示最新内容，软删除保留“已删除条目”、原 ID、内容摘要和来源；书签不计字数。
- [ ] 伏笔五状态可用，埋设、触发、回收可分别有多条章节/段落证据；无证据或失效证据明确显示，不错误跳转，可清理或重新关联；切换和删除作品后无跨作品架构残留。
- [ ] AI 支持段落润色、单句润色、续写、纠错、一致性检查、剧情感受和正文回写；支持当前章节、前章衔接、全卷和自定义范围，超长时提示并由作者选择分块或缩小范围，不静默截断；首版模型通过用户配置的云端适配层接入，断网时不发起或排队请求。
- [ ] 每次云端 AI 请求显示服务、发送范围、费用/计费提示和取消按钮，作者确认后才发送；API Key 只存入 Windows Credential Manager 或 `safeStorage`/DPAPI，不进入 `.rainsoul`、日志或错误报告。
- [ ] AI 可针对当前正文检索当前作品的知识参考，展示相关内容与出处，发送清单覆盖实际携带参考；修改仍经候选对比和确认，不把参考原句未经作者判断直接写入正文。
- [ ] AI 候选与原文对比，原文变化时重新生成或对比，确认前自动快照，确认后才写入。
- [ ] AI 失败保留原文和候选状态，显示原因，手动重试且不自动重发。
- [ ] 一致性检查覆盖角色、时间、地点、伏笔、大纲偏离和写作特点漂移，规则结果有证据，AI 结果标为建议。
- [ ] 剧情感受标为 AI 建议，显示证据和不确定性，不自动改稿。
- [ ] 正文回写候选逐条审核，未审核候选不能成为正式条目；生效条目保留来源章节、段落和正文版本。
- [ ] TXT/DOCX 导入始终创建新作品；只导入正文段落和可识别标题，识别不到标题时整份作为一章；章节识别可预览修改，DOCX 图片和表格提示不导入；该识别流程与后置独立拆文工具边界清楚。
- [ ] 可手动导出 `.rainsoul` 到用户选择的位置，并完成包含清单、版本和校验信息的导出→导入往返；导入先校验并创建新项目，不覆盖现有项目。
- [ ] 快照恢复前状态可访问，恢复为新版本并保留历史；恢复或导入任一步失败都回滚事务，恢复前当前状态和历史不变。
- [ ] DOCX/TXT 按顺序导出，正文知识引用保留编号标记，同一条目重复引用复用编号并按首次出现列一次文末清单；伏笔输出 `[伏笔：名称]`、状态和证据清单。
- [ ] 导入、导出、迁移和保存失败均明确提示且不覆盖原数据；SQLite 升级前创建备份，迁移失败时恢复备份并阻止启动。
- [ ] 全部入口可见，后置入口显示统一提示、阶段和返回按钮，不进入空白页。

### 10.2 扩展验收门槛

- [ ] 每项后置功能有真实需求证据、隐私边界、失败恢复、质量指标和回滚方案。
- [ ] 向量检索只有在真实查询数据证明关键词不足后才验收。
- [ ] URL 导入通过协议、私网、重定向、大小、超时和版权边界测试，不突破反爬。
- [ ] XMind 后置目标覆盖所有 XMind 版本；交付前提供官方格式版本兼容矩阵和逐版本样例，解析先形成临时导入草稿，确认后才写入大纲，部分解析结果可保留。

- [ ] 需求会话以作品为项目，作品下开会话；消息和删除操作按作品隔离，悬停/聚焦时显示会话删除按钮，无会话有空状态；真实模型能力另行验收。
- [ ] 拆书工具只把勾选并审核的真实段落入当前作品知识库，保留真实出处和使用权限，不创建手稿作品、不污染原数据；TXT/DOCX 类型、复杂内容提示、取消和失败恢复可验证。
