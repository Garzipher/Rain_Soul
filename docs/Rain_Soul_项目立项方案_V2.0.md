# Rain_Soul 项目立项方案

**PC 端网文写作工作台**

## 1 项目概述

### 1.1 项目背景

长篇网文写作通常面临设定分散、大纲与正文脱节、伏笔遗忘、知识库难复用、AI 生成不可控、版本混乱等问题。Rain_Soul 旨在为作者提供一个 PC 端本地优先的写作工作台，把写作特点、大纲、章节、段落、知识库、引用、AI 重写、版本和导出连接成闭环。

### 1.2 产品定位

Rain_Soul 是一个**网文写作工作台**。核心是服务网文写作，知识库和 AI 是增强能力，学习路径是副产品。它不是一键写小说工具，而是作者可控、可追溯、可沉淀的写作操作系统。

- **写作系统**：从写作特点到定稿导出的完整闭环
- **知识系统**：知识库引用 + 拆文工具 + 回写审核，作为写作系统的支撑层
- **学习路径**：随功能开发顺带产出学习卡，不作为独立产品线

### 1.3 一句话定义

Rain_Soul：可追溯、可引用、可回写、可学习的 PC 端网文写作工作台。

### 1.4 立项结论

已确认立项。分三个阶段实施：P0 先完成写作闭环 + 知识库 + 导出，P1 加入基础 AI + 伏笔 + 向量检索，P2 加入高级 AI + 需求会话 + XMind 导入。

## 2 目标与价值

### 2.1 产品目标

- 建立从写作特点到导出的完整闭环。
- 让伏笔、正文、独段、知识条目都可索引、可引用、可追踪。
- 让 AI 重写润色基于知识库和写作特点，且结果可对比、可回滚。
- 让写好的正文以审核后的形式回写知识库，成为后续写作资产。

### 2.2 用户价值

作者不再需要在多个工具之间复制粘贴；设定、伏笔、素材、正文可以互相关联；AI 是助手而非替代者；所有生成和修改都有版本和来源。

### 2.3 学习价值

每个核心功能绑定学习卡，覆盖后端、AI、算法、数据结构、Python、原理问题和验收实验。学习卡根据当前项目结构编写，伏笔架构可用于学习接口联系、路由联系、前后端对接、数据流等知识；大纲架构对应项目结构与模块划分。最终形成《关于 Rain_Soul 项目实现全链路学习》。

### 2.4 成功标准

- 能完成一部中短篇从写作特点到大纲、章节、定稿、导出的全过程。
- 伏笔可埋、可查、可收、可提醒。
- 段落可引用知识库并重写，结果可追溯、可对比、可回滚。
- 正文回写知识库不会污染原文。
- 检索能同时支持关键词和语义（P1 起）。
- 每个核心功能都有对应学习路径。
- 用户不用 AI 也能完成写作。
- 用户用 AI 时不会失去控制权。
- 数据可备份、可导出、可迁移。

## 3 目标用户与使用场景

### 3.1 目标用户

| 维度 | 描述 |
|------|------|
| 身份 | 网文作者，兼职写作 |
| 技术背景 | 有浅编程基础，希望通过开发此项目学习 AI、后端、Python |
| 使用场景 | 在 PC 上离线写作，需要管理长篇多卷多章结构 |
| 设备 | Windows 10/11 64 位 |

### 3.2 核心场景

创建作品 → 设置写作特点 → 编写大纲 → 建立大纲索引 → 创建章节 → 写段落 → 引用知识库 → AI 重写润色 → 回写知识库 → 一致性校验 → 版本定稿 → 导出成品。

### 3.3 边界与非目标

- 不做一键全自动长篇小说生成。
- 不做多人实时协作（私人工作台，单机单用户）。
- 不内置版权内容库。
- 不强迫用户使用 AI；不用 AI 也能完成写作。

| 跨作品会话 | 支持跨作品分析比较 |
| 自动拆文 | URL/文件导入 → AI 自动拆解分类 → 人工审核确认 → 入库 |

| XMind 导入 | .xmind 文件导入转为剧情架构树，事务性回滚 |

| AI 写作风格规则 | 默认为空时从上下文自动定义风格 |
| 全局知识库配置 | 为 AI 操作指定默认知识库 |

### 5.1 全局导航

左侧竖栏 4 个入口（从上到下）：

| 序号 | 入口 | 说明 |
|------|------|------|
| 1 | 头像 | 展示头像，支持本地上传 |
| 2 | 笔名 | 头像下方显示笔名，可在侧栏直接点击编辑 |

### 5.2 页面地图

```
创作集入口
├── 作品列表页（展示作品卡片 + 学习合集入口）
│   └── 点击作品 → 大纲架构页
│       ├── 伏笔架构（P1）：伏笔树，按创建时间+名称排序
│       └── 剧情架构（P1）：大纲树，卷→章→详细节点，支持右键加伏笔/知识库
│           └── 点击章节 → 正文写作页
│               ├── 选中段落右键：润色/单句润色/续写/纠错/剧情感受（P1/P2）
│               └── 不选中右键：插入知识库（P0）
│
知识库入口
├── 知识库主页（分类总览：拆文工具/人物描写/景物描写/内心描写/经典引用/…）
│   └── 点击分类 → 分类详情页（搜索框 + 内容列表 + "出自XXX"来源标注）
│       └── 拆文工具 → 拆文工具页面（P1手动/P2自动）
│
需求会话入口（P2）
├── 会话页：左侧作品/会话列表 + 右侧 AI 对话区
│   ├── 默认扫描当前作品
│   └── 支持跨作品分析
│
设置入口
├── 设置页：字体 / AI 写作风格规则 / 全局知识库配置 / 高级模式
│   └── 高级模式：分类字典管理、知识库维护、数据导入导出
```

### 5.3 页面交互规则

1. 应用启动后默认进入创作集，不进入空白正文。
2. 侧栏支持展开和收起；收起状态至少保留菜单入口。
3. 当前模块需要有明确选中状态。
4. 笔名与作品内容是不同数据域；修改笔名不改变作品标题或作者字段。

## 6 核心功能规格

### 6.1 创作集与作品管理

**层级结构**：创作集 → 作品（一对多）。"项目学习合集"是特殊的创作集，里面放置学习卡。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 作品名称 | 文本 | 是 | 卡片主标题和作品根节点名称 |
| 最近修改时间 | 日期时间 | 是 | 用于排序和恢复提示 |
| 作品字数 | 数字 | 否 | 由章节字数汇总得到 |
| 所属创作集 | 关系 | 是 | 一个作品属于一个创作集 |

**业务规则**：
- 一次只编辑一个作品；切换作品前必须完成当前保存。
- 作品删除、归档、恢复必须有确认和可恢复路径。
- 新建作品有"从大纲生成"入口（P2，大纲节点一键生成章节）。

### 6.2 分卷与章节

**分卷规则**：可选分卷。可以不建卷直接建章节（章节挂在作品根节点下），有卷则挂在卷下。

| 对象 | 关键字段 | 说明 |
|------|---------|------|
| 分卷 | id, work_id, title, sort_order | 可选；非空时不能直接删除 |
| 章节 | id, volume_id(可选), title, sort_order | 章节正文和字数统计入口 |
| 段落 | id, chapter_id, content, sort_order | 段落 ID 稳定，引用挂在段落上 |

### 6.3 大纲架构

**结构**：树状结构，卷 → 章 → 详细节点。

**大纲节点与章节的关系**（B+C 模式）：
- B：大纲节点可以比章节更细（一章下有多个大纲细项），也允许有不在正文体现的大纲节点
- C：大纲节点可一键生成章节，一个大纲节点可生成多个章节

**右键菜单**：剧情架构节点可右键 → 添加伏笔 / 添加知识库条目（可多选）

**AI 联动**：AI 创作和续写根据卷-章找到对应大纲，按大纲需求审核/续写

### 6.4 伏笔架构

**状态模型**（五状态）：

```
未埋设 → 已埋设 → 已触发 → 已回收
                    ↓
                 废弃
```

| 状态 | 说明 |
|------|------|
| 未埋设 | 伏笔已规划但未写入正文 |
| 已埋设 | 已写入正文，等待触发 |
| 已触发 | 伏笔事件已发生但未收束 |
| 已回收 | 伏笔已收束，结果已落实 |
| 废弃 | 伏笔放弃使用 |

**结果类型**：文本说明 + 关联章节引用

**排序**：按创建时间 + 伏笔名称排序，如"XX死亡伏笔001 → XX死亡伏笔-结果001"

### 6.5 正文编辑器

**编辑器规格**：
- 固定样式：字体、字号、行距、颜色、标题样式
- 实时字数统计：只计汉字、字母和数字
- 实时自动保存

**右键菜单**：

| 操作 | 优先级 | 说明 |
|------|--------|------|
| 段落润色 | P1 | AI 全段润色 |
| 单句润色 | P1 | 优先匹配剧情架构配置的知识库，相似度≥90% 直接取用；未配置则用全局 |
| 续写 | P1 | 根据写作风格 + 上下文 + 剧情架构合理续写 |
| 纠错 | P1 | 错别字筛查，润色和续写内置此功能 |
| 剧情感受 | P2 | 核对大纲 + 上下文，审核合理性、是否脱离剧情、衔接是否流畅 |
| 插入知识库 | P0 | 不选中段落时，打开树状知识选择弹窗 |

### 6.6 AI 操作规格

**上下文范围**（用户可选）：

| 选项 | 范围 | 适用场景 |
|------|------|---------|
| 当前章节 | 当前章节 + 关联知识库条目 | 快速润色 |
| 衔接模式 | 当前章节 + 前一章尾部 + 关联知识库 | 保持上下文衔接 |
| 全卷模式 | 当前卷全部章节 + 关联知识库 | 一致性检查 |
| 自定义范围 | X卷-X卷 / X章-X章 | 灵活指定 |

**结果确认流程**：

1. 用户选择操作（润色/续写/纠错等）
2. AI 生成候选结果
3. 在原文下方显示候选结果，方框圈起、背景颜色突出
4. 用户对比原文与候选结果
5. 点击确认后才替换原文
6. 自动创建版本快照

**例外**：直接插入知识库操作（不修改原文）无需对比，但仍记录引用版本。

**安全约束**：AI 不能直接覆盖原文，只能生成新版本。所有 AI 操作保留撤销和版本历史。

### 6.7 知识库

**分类管理**：
- 分类不固定，由"分类字典"动态控制
- 拆文时 AI 发现新描写类型可建议新建分类，用户确认后加入字典
- 后续拆文和写作时都能看到新分类

**P0 功能**：手工条目新增、编辑、软删除、标签、来源、全文搜索、标签 AND 筛选、段落引用

**P1 功能**：向量检索（关键词 + 语义混合搜索）

**引用规则**：
- 引用显示来源
- 条目修改后同步最新内容
- 软删除后保留"已删除条目"占位

**正文回写知识库**（P1）：
- 所有正文可进知识库，但必须经过候选 → 审核 → 生效流程
- 回写形式：章节摘要、段落卡片、角色信息、事件记录、伏笔状态、独段素材

### 6.8 拆文工具

**工作流**：

```
输入源（三选一）
├── URL 链接（P2）→ AI 分析页面 → 下载内容 → 进入拆文
├── 本地文件（txt/epub/pdf/docx）→ 导入 → 进入拆文
└── 手动粘贴文本 → 直接进入拆文
         ↓
    AI 自动拆解 + 分类推荐（P2）/ 人工手动标记（P1）
         ↓
    置信度判断（P2）
    ├── 置信度 ≥80%：自动入库
    └── 置信度 <80%：需人工确认
         ↓
    人工审核
    （可修改分类、调整拆分粒度、合并/拆分条目）
    （支持批量选择多个条目一起入库）
         ↓
    入库
    （每条记录：来源URL/文件、出处章节、拆入时间、原文片段）
```

**URL 下载策略**（P2）：
- 支持网文平台（公开章节页）和通用网页
- AI 分析页面结构，提取正文内容
- 网文平台有反爬机制，需设计应对策略

**动态分类**：
- AI 发现新描写类型（如"氛围描写"、"战斗描写"）且现有分类无匹配
- 建议新建分类，用户确认后自动加入分类字典
- 后续拆文和写作时可见新分类

### 6.9 需求会话

**布局**：左侧作品/会话列表（可折叠、有分隔） + 右侧 AI 对话区（和 TRAE 一样）+ 底部输入框

**会话绑定规则**：
- 会话在作品下开启，默认扫描该作品的架构和内容
- 支持跨作品会话（当需要跨作品分析时）

**能力**：
- 调整架构
- 全文检查
- 类似 Codex 的任务式交互
- 引用证据展示
- 任务进度和取消

**需后续定义**：
- 扫描范围（整本/分卷/章节/选中文本）
- 长文分批策略
- 隐私边界
- 云端/本地模型选择
- 生成结果如何进入版本历史

### 6.10 设置

| 设置项 | 优先级 | 说明 |
|--------|--------|------|
| 字体 | P0 | 全局字体选择 |
| 固定编辑样式 | P0 | 字号、行距、颜色、标题样式 |
| AI 写作风格规则 | P2 | 默认为空时从上下文自动定义风格 |
| 全局知识库配置 | P2 | 为 AI 操作指定默认知识库 |
| 高级模式 | P1 | 分类字典管理、知识库维护、数据导入导出 |

**笔名编辑**：可在侧栏直接点击编辑

**头像上传**：支持本地上传，存储在应用数据目录

## 7 数据模型

### 7.1 核心实体

| 对象 | 关键字段 | 关系和说明 |
|------|---------|-----------|
| 作者档案 | avatar, pen_name | 头像下方显示 pen_name；笔名可在侧栏编辑 |
| 创作集 | id, name, created_at | 包含作品；一个作品属于一个创作集 |
| 作品 | id, title, collection_id, updated_at, word_count | 一次编辑一个作品 |
| 分卷 | id, work_id, title, sort_order | 可选；非空时不能直接删除 |
| 章节 | id, volume_id(可选), title, sort_order | 无卷时 volume_id 为 null |
| 段落 | id, chapter_id, content, sort_order | 段落 ID 稳定，引用挂在段落上 |
| 知识条目 | id, title, body, source, tags, category, deleted_at | 软删除保留追溯 |
| 知识分类 | id, name, parent_id, sort_order | 动态分类字典，支持新增/编辑/删除 |
| 引用 | id, paragraph_id, knowledge_id, anchor | 支持编辑、移动、导出和快照 |
| 快照 | id, work_id, created_at, reason | 恢复生成新快照，不覆盖历史 |
| 写作特点 | id, work_id, style, persona, rhythm, taboos, refs | 版本化，可继承和覆盖 |
| 大纲节点 | id, work_id, parent_id, title, sort_order, chapter_id(可选) | 树状结构，可关联章节 |
| 伏笔节点 | id, outline_node_id, name, status, result_text, result_chapter_id, created_at | 五状态模型 |
| 拆文结果 | id, source_text, category, confidence, source_url, source_chapter | 支持人工校正 |
| 需求会话 | id, work_id, title, messages, scope, cross_work | 支持跨作品 |
| 学习卡 | id, feature, content, created_at | 绑定功能，随开发产出 |

### 7.2 逻辑正确性规则

1. 一切实体必须有 ID、类型、状态、版本、来源。
2. 索引必须指向真实存在的实体，删除使用软删除。
3. 引用必须记录来源、目标、位置、强度、时间。
4. 重写必须基于快照，输出新版本，不直接覆盖原文。
5. 正文回写知识库必须经过候选、审核、生效。
6. 伏笔回收必须关联埋设点。
7. 大纲、章节、段落、知识库之间不能形成无审核的循环污染。

## 8 技术架构

### 8.1 技术选型

| 层 | 技术 | 版本 | 理由 |
|----|------|------|------|
| 桌面壳 | Tauri | 2.0 | Rust 内核，包体小，性能好，前沿 |
| 前端 | React | 18 + TypeScript | 企业级标配，生态最大 |
| 后端 | Python FastAPI | 最新 | AI 生态最强，和学习方向一致 |
| 数据库 | SQLite | 内置 | 本地优先，零配置 |
| 向量检索 | sqlite-vec | — | 不引入额外服务，轻量 |
| ORM | SQLModel | — | FastAPI 作者出品，无缝集成 |
| 构建工具 | Vite | — | 极速热更新 |

### 8.2 离线与在线策略

| 功能 | 离线可用 | 说明 |
|------|---------|------|
| 写作、检索、版本、导出 | ✅ | 核心功能完全离线 |
| AI 重写润色 | 视配置 | 云端模型需联网，本地模型离线 |
| URL 下载拆文 | ❌ | 需要联网 |
| 向量检索 | ✅ | 本地 embedding 模型 |

### 8.3 AI 能力方案

**混合模式**：默认用云端 API（效果更好），配置了本地模型后可切换。

**模型来源**：

| 来源 | 说明 | 优先级 |
|------|------|--------|
| 云端 API（自定义 Key） | 用户输入 API Key，支持 OpenAI/Claude/国产模型 | 默认 |
| 云端 API（免费模型） | 提供市面上免费模型的接入 | 备选 |
| 本地模型 | Ollama + Qwen/LLaMA，完全离线 | 可选切换 |

**密钥管理**：API Key 存储在本地配置中，不上传，不外泄。

## 9 实施路线图

### 9.1 阶段一（P0）：核心写作闭环

**目标**：作者可以在 Windows 上离线完成一部作品的写作并导出。

- 创作集导航、创建/打开作品
- 可选分卷 → 章节 → 正文段落
- 固定样式编辑器、实时字数、自动保存
- 手工知识条目、标签 AND 筛选、全文搜索、段落引用
- 手动快照、差异查看、恢复为新版本
- 项目归档导入/导出、DOCX/TXT 导出
- 学习路径框架，每个功能绑定学习卡

### 9.2 阶段二（P1）：AI 增强 + 伏笔 + 向量检索

**目标**：引入 AI 辅助写作，建立伏笔追踪和语义检索。

- 写作特点（StyleProfile）
- 基础大纲架构、右键关联知识条目
- 伏笔架构（五状态模型）
- 段落润色/单句润色/续写/纠错（含对比确认流程）
- 向量检索（关键词 + 语义混合）
- 知识库分类字典动态管理
- 拆文工具（手动标记分类）
- 正文回写知识库（候选→审核→生效）
- EPUB/PDF 导出
- 高级模式（分类管理、数据导入导出）

### 9.3 阶段三（P2）：高级 AI + 需求会话 + 自动化

**目标**：AI 深度参与写作流程，建立全自动化工具链。

- 剧情感受检查
- 需求会话（独立 Agent，扫描作品，支持跨作品）
- 自动拆文（URL 下载 + AI 自动拆解分类）
- XMind 导入（.xmind → 剧情架构树，事务性回滚）
- 大纲节点生成章节
- 一致性检查（规则引擎 + 实体链接 + 知识图谱 + LLM）
- AI 写作风格规则、全局知识库配置
