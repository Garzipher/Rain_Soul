# Rain_Soul 产品需求文档（PRD）

版本：PRD V1.0　日期：2026-10-08　状态：**开发规格初稿，派生自已统一基线**

依据：[项目立项方案 V2.0](Rain_Soul_项目立项方案_V2.0.md)、[工作台 Demo](demos/rainsoul-writing-style.html)。实现方法见[技术方案](Rain_Soul_技术方案.md)。

本文件把已确认需求细化成可开发、可验收的规格，不替代立项方案，也不改变阶段。范围和数据规则以 V2.0 为准，界面外观与已有交互以 Demo 为准。第 11 节明确区分本次提出的补充设计与此前已确认要求；新增范围须先修改基线，再同步本文件。

## 1 产品目标与发布范围

### 1.1 产品目标

让单机网文作者在 Windows 上完成“组织作品 → 写作 → 素材参考 → 作者审核 AI → 版本保护 → 导出”的完整流程。知识库保存值得学习的描写和写法，供作者学习、仿写，以及 AI 针对当前正文检索参考。作者对素材入库、正文修改和云端发送始终有决定权。

### 1.2 用户与约束

- Windows 10/11 64 位；普通用户可安装，不需要安装 Python、数据库服务或启动本地 AI 服务。
- 单机单用户、一次编辑一部作品；启动第二个实例聚焦已有窗口。
- 所有作品展列在唯一“作品集”中；“学习路径”也是普通作品，不另建学习合集。
- 写作、保存、搜索、版本、归档和导出离线可用；首版 AI 经逐次授权使用云端服务。
- 不设作品总字数、章节数或写作长度的产品上限。性能夹具是验收样本，文件解析安全限额不作为作品规模限制。
- 首版只要求开发团队完成验收，不设置真实作者试用门槛；资源、人力、预算、工期和发布渠道不在本稿中虚构。

### 1.3 范围矩阵

| 阶段 | 交付能力 | 发布条件 |
| --- | --- | --- |
| P0 | 作品集/档案、卷章正文、剧情架构、伏笔/引用、写作特点、知识/分类/标签/搜索、保存/版本/归档、手稿导入、基础 AI/参考/分析/回写、DOCX/TXT、Windows 安装升级 | 第 9 节全部 P0 验收通过 |
| 后置候选 | 需求会话、跨作品分析、手工/自动拆文、URL、XMind、向量检索、本地模型、EPUB/PDF、章节生成、AI 风格提取、搜索/AI 数据分析 | 每项独立证明需求、质量、安全、失败恢复与回滚条件，阶段另定 |
| 不在产品目标内 | 多人协作、账号/云端作品同步、一键生成完整小说、绕过反爬、内置版权内容库 | 不随 Demo 入口或技术选型自动加入 |

P0 的内部开发批次可以先完成离线能力，再完成 AI，但只有完整 P0 通过才可标为首版交付。Demo 展示的需求会话和拆书工作区仍属于后置参考。

## 2 术语与数据归属

| 名称 | 含义与边界 |
| --- | --- |
| 作品集 | 系统唯一书架，不是可创建多个的创作集 |
| 作品 | 独立正文、知识字典、大纲、伏笔、写作特点、版本的数据域 |
| 分卷 / 章节 / 段落 | 正文组织单位；分卷可选；段落有稳定 ID |
| 剧情节点 | 大纲中的卷、章、详细节点；与正文章节是不同对象，关联不生成正文 |
| 知识条目 | 一份完整内容＋主分类＋多个标签＋出处，无独立必填标题 |
| 引用书签 | 正文中的知识引用标记或伏笔标记；不计字数 |
| 伏笔证据 | 埋设、触发、回收的章节/段落位置和摘录；可以失效但不可误定位 |
| 写作特点 | 版本化 StyleProfile；作品默认，章节可覆盖 |
| 当前版本 / 快照 | 当前可编辑状态 / 某时刻整部作品的完整状态；恢复产生新版本 |
| 候选 | 尚未经作者确认的 AI 修改、建议或入库提案，不等于正式正文或知识 |
| 手稿导入 / 拆书 | TXT/DOCX 导入新作品正文 / 摘选优秀片段入当前作品知识库；两条不同流程 |

正文、知识、分类、标签、大纲、伏笔及其关联均按作品隔离。头像、笔名、云端服务设置和凭据是作者/应用配置；不随某部作品快照覆盖。跨作品复制知识后产生独立副本，保留原作品与条目来源，后续编辑互不联动。

## 3 主要用户流程

### 3.1 写作与导出

作品集创建/打开作品 → 设置写作特点 → 建剧情节点与卷章 → 编辑正文 → 实时字数与自动保存 → 插入知识/伏笔标记 → 快照或备份 → DOCX/TXT 导出。每个切换与输出动作先完成当前待保存内容。

### 3.2 素材参考与 AI 修改

选择正文范围和操作 → 选择上下文 → 查看相关知识内容及出处 → 核对实际发送内容、模型和费用提示 → 授权发送 → 候选对比 → 核对原文版本 → 自动快照 → 作者确认写入。取消、失败或版本变化都不能自动覆盖原文。

### 3.3 正文回写与分析

选择正文范围 → 授权生成知识候选/一致性或剧情感受建议 → 展示来源与证据 → 入库候选逐条接受/编辑/拒绝；分析建议独立展示，不自动改稿。入库内容记录产生它的正文版本，后续正文变化不冒充已复核事实。

### 3.4 导入与恢复

手稿：选 TXT/DOCX → 解析预览与复杂内容提示 → 修改拆章 → 确认 → 新作品。

归档：选 `.rainsoul` → 校验 → 预览 → 确认 → 新作品，原作品保留。

快照：查看旧版本 → 预览与确认 → 保存恢复前状态 → 生成新当前版本，历史保留；任一步失败保持原状态。

## 4 页面与交互基线

### 4.1 全局外观

- 白色 Codex 风格、天蓝色重点、第一版 RainSoul 字标与倾斜方框 Logo；细边框、克制阴影、小圆角。
- 每页仅一个主标题。侧栏默认收起，方框内三横线控制收放；设置固定底部，删除原底部说明文案。
- 展开侧栏显示本地头像与其下的笔名，直接显示名称，不显示“笔名”标签。
- 正文获得焦点不出现蓝色外框；其他交互控件保持可见键盘焦点。窄屏抽屉可通过遮罩关闭。

### 4.2 页面入口与操作

| 页面 | 保留内容 | 操作与禁止出现的重复元素 |
| --- | --- | --- |
| 作品集 | 作品卡、作品计数、空状态 | 新建作品、手稿导入、打开作品、右键删除；不显示“已保存”、重复介绍或“最近编辑优先” |
| 作品工作区 | 作品名；“正文 / 剧情架构 / 伏笔架构”标签 | 返回作品集；正文显示保存状态；不放新建作品按钮 |
| 正文 | 卷章树、独立章节标题、固定编辑区、字数 | 添加/改名/排序/删除卷章、引用、伏笔、AI；保存/版本/导出入口见第 11 节补充设计 |
| 剧情架构 | 卷章详细节点树、内容、关联章节/知识/伏笔 | 展开收起、同级排序、定位、删除；多选方式沿用 Demo |
| 伏笔架构 | 名称、状态、剧情归属、说明、证据 | 添加/编辑、证据定位/重新关联、删除、正文双向定位 |
| 知识库 | 可收起分类、一个搜索框、范围下拉、AND 标签、无标题卡片 | 新增知识、原位展开、当前作品编辑/删除、跨作品复制；顶部保留拆书入口 |
| 需求会话 | Demo 参考：作品作为项目、其下会话、消息流和输入区 | 不重复显示页名/新建作品/上下文框；会话删除按钮悬停/聚焦显示；正式 P0 展示后置提示 |
| 设置 | 纵向分组：个人资料、固定样式、知识字典、本机数据、云端 AI | 维护分类/标签、配置服务、导入导出；强制保护规则显示状态说明 |

### 4.3 共同交互规则

删除先关闭右键菜单再弹窗；标题准确为“删除作品”“删除卷及章节”“删除章节”等，明确目标和影响，取消不改数据。键盘菜单键或 `Shift+F10` 与右键等效；对话框限制焦点、Escape 取消、关闭后返回合理焦点。

加载中有状态，成功以实际持久化/任务结果反馈。空作品、无节点、无证据、无素材、无搜索结果和后置入口均有说明与可执行下一步。失败提示说明原因、仍保留什么、如何重试，不把内存更新当作已保存。

## 5 P0 功能规格

### FR-01 作品集与个人资料

- 新作品产生独立 ID，空内容起步，不携带 Demo 示例或他作草稿；名称修改不改变 ID/关联。同名对象的处理见第 11 节。
- 书架展示作品名、摘要/类型信息、章数/字数、最近编辑信息；统计从当前作品内容计算，不使用样例常量。
- 删除作品需确认并提供正式恢复路径；不清除其他作品、作者档案和服务凭据。无剩余作品时回到可创建作品的空书架。
- 支持本地头像上传及笔名编辑，头像失效有默认显示；编辑笔名不改作品名、旧正文或引用来源。
- 验收：两部作品写入不同内容、删除一部、恢复后仍隔离；刷新/重启保留已成功保存的数据。

### FR-02 卷章、编辑器与字数

- 结构为作品 → 可选分卷 → 章节 → 段落；无卷可直接建章。卷章支持创建、改名、同级排序、确认删除；删卷必须明确包含哪些章节。
- 正文样式固定：微软雅黑 12 pt、1.5 倍行距、`#242424`；章节标题微软雅黑 16 pt、加粗、`#1C1C1C`。不提供首版自定义样式。
- 标题与正文独立；粘贴外部内容清除外来样式和可执行 HTML，按受限正文结构保存。段落合并/拆分/移动后，原来源不可被错误复用。
- 按 Unicode 汉字、ASCII 英文字母和数字统计，逐字符计数；标点、空白、换行、知识/伏笔标记均排除。例如 `雨A1， B2\n[标记]` 的实际正文“雨A1， B2”计 5 字，标记节点计 0。
- 本章字数实时更新，卷与作品汇总按同口径计算；输入法组词期间不触发结构破坏，确认输入后正常保存。
- 验收：删掉全部正文不回填示例；跨章节切换不丢未到保存间隔的输入；输出样式与正文一致。

### FR-03 剧情架构

- 卷 → 章 → 详细节点，卷可省略；支持名称、剧情内容、展开/收起、同级排序、确认删除。
- 一个节点关联至多一个正文章节、多个当前作品知识条目、多个伏笔。节点是大纲对象，不自动创建/覆盖章节。
- 关联知识与伏笔均为右侧复选框多选下拉，按钮提示不属于选项；勾选即时显示下方，可连续选；取消与下方移除双向同步，已选项保留勾选。
- 每个伏笔至多属于一个剧情节点；选项预先显示原节点和“勾选后移到本节点”，勾选即确认转移。不勾选不转移，取消只解关联，不删证据。
- 定位知识打开其全文；定位伏笔/章节保持同作品。删节点及子节点仅解除关联，保留正文、知识和伏笔。
- 验收：多项勾选、移除、转移、节点切换、作品隔离、空候选、键盘、菜单滚动/视口边界均正确。

### FR-04 伏笔、证据与行内书签

- 五状态：未埋设、已埋设、已触发、已回收、废弃；人工修改状态不自动生成或删除证据。
- 埋设/触发/回收各可记录多条证据，包含章节、可选段落、摘录及来源版本。无证据显示“尚无证据”。
- 删除章节/段落使相关证据失效并保留原出处；定位被禁用或提示失效，可清理或重新关联。重新关联记录新来源，不改写原来曾来自何处。
- 从工具栏或段落菜单插入已有知识/伏笔；默认光标所在段落，多段正反向选区都取文档顺序首段。未选正文或无可选对象时给出可操作提示。
- 行内标记可点击/键盘打开详情并返回原段落；插入、删除、移动和编辑正文遵循稳定段落与目标 ID。删除标记只移除当前位置关联。
- 知识软删除显示“已删除条目”与可追溯信息；伏笔删除后现行书签/关联按删除规则清理，历史保留。
- 验收：段落移动仍能定位，段落删除不跳到同名章节或相邻段落；标记不计字数，正文其他内容不被误删。

### FR-05 写作特点

- StyleProfile 保存人称、节奏、禁用项、参考作品等；每次生效修改有版本，显示作品默认/章节覆盖关系。
- 无章节覆盖时采用作品默认；覆盖不能因修改其他章节而改变。历史 AI 操作保留当时使用的配置版本。
- 作为 AI 上下文携带时纳入发送清单；配置不保证模型百分之百遵守，漂移结果只能作为有证据的建议。
- Demo 尚未提供完整页面；入口补充不改变已有三个作品标签，建议位置见第 11 节。
- 验收：默认、覆盖、修改、快照恢复和 AI 请求均能识别实际生效版本。

### FR-06 知识内容、分类、标签与复制

- 一份完整内容，无必填标题；默认卡片最多两行，点击原位展开全文，再次点击收起。标签和右下角出处始终可见，长出处换行。
- 默认分类包括人物描写、景物描写、内心描写、经典引用、剧情与伏笔；动态层级分类可新增、改名、排序、移动，禁止移入自身/后代形成环。
- 每条知识一个主分类、多标签；分类/标签维护集中设置，新增知识只能选择已维护标签，保留标签内空格。未分类是兜底分类。
- “未分类”为系统保留项，不可删除；删除有条目的分类前先迁移条目。父分类有子分类时先处理子分类及所有受影响条目，再删除父分类，不能未经确认级联删除。删除已使用标签需确认，只解除标签关系，不删内容。
- 范围为当前作品、另一作品、全部作品；仅当前作品可编辑。读取其他作品不切换正在编辑的作品，不授予写入权限。
- 跨作品复用执行复制：新条目归当前作品，保留原作品/条目和出处，字典映射按第 11 节；此后不实时同步。
- 内容编辑让正文引用显示最新版本；删除保留占位、ID、摘要、出处和历史完整内容，不造成悬空指向新条目。
- 验收：多标签组合、同名分类跨作品、修改/删除引用、复制后来源与编辑隔离、分类迁移失败回滚。

### FR-07 搜索

- 知识页只保留一个模糊搜索框，搜索内容、出处、标签；“模糊”指关键词/子串，不承诺语义、拼写纠错或向量检索。
- 分类、作品范围、关键词、多标签 AND 共同作用；没有选标签等同不限制标签，选择标签后所有标签都须满足。
- 全文搜索默认当前作品，覆盖正文和知识，返回来源类型、作品/章节或条目、命中片段和定位；不得定位已失效来源。标签 AND 仅筛选知识结果，正文章节没有标签关系，不因此被隐藏或标为标签命中。
- 关键词含中文单字、双字、长词、标点和无结果时行为明确；清空搜索返回筛选后全部结果，旧慢查询不能覆盖新查询结果。
- 知识库跨作品查询只读；正文全文搜索仅当前作品。新增/删除/重命名、恢复快照后及时更新结果。跨作字典 ID 不混用，切换范围时失效筛选清除或明确提示。
- 验收按 NFR-02 固定数据、设备与方法；产品不根据夹具规模限制创作。

### FR-08 自动保存与失败门禁

- 每次编辑使状态变为待保存；停顿约 500ms 自动提交，持续输入每最长 5 秒必须提交，不因持续输入不断延期。
- 保存对象包含正文/标题，以及其他作品资产修改。状态必须与本地提交结果一致：未保存、保存中、已保存、保存失败。
- 切换章节/作品/离开编辑、删除、快照、备份、导出和正常关闭前等待当前最新修改保存成功；旧保存完成不能把更新内容误标“已保存”。
- 保存失败保留最新内存草稿，显示原因/重试；禁止上述离开或输出动作。仍可继续输入，重试写入最新草稿。
- 自动保存不可关闭。应用可以拦截正常关闭；不能保证拦截任务管理器强杀、断电和系统崩溃，必须区分已确认落盘与未落盘内容。
- 验收：磁盘满/只读/数据库异常、输入过程中重试、并发修改回执顺序、持续输入、关闭和导航拦截；已确认落盘内容重启完整。

### FR-09 快照与恢复

- 手动快照保存整作品：结构、正文、知识、分类/标签、引用、剧情、伏笔/证据、写作特点；不递归包入所有历史快照，不包含服务凭据/作者头像。
- 创建前完成保存；快照有名称或原因、时间和版本。恢复先预览范围并确认。
- 恢复前的当前状态先成为可访问快照，再用所选快照生成新的当前版本；原快照与全部历史不覆盖、不丢失。
- 任何一步失败回滚，恢复前的当前状态与历史不变；恢复后字数、索引、书签、字典和生效写作特点一致。
- 验收：修改正文和知识后恢复旧快照，两种状态均可访问；在恢复事务中注入失败，原状态完整。

### FR-10 项目归档

- 用户选位置导出 `.rainsoul`，包含作品有效数据、版本/快照及清单、格式版本和校验；不含 API Key、完整日志或其他作品。
- 导入先校验格式、内容、安全、版本和关联完整性，预览后确认创建新作品；不覆盖既有作品，不执行包内代码。
- 原作与导入作独立编辑；内部关联重映射/归属新作品，外部来源仍保留原出处，不因重名指向本机错误对象。
- 导出/导入失败清理临时产物，保持原项目完整；选路径取消不形成半个作品。
- 验收：归档往返、损坏/截断/伪造校验、未来不支持版本、重复导入、非法路径/压缩炸弹、失败回滚、凭据排除。

### FR-11 TXT/DOCX 手稿导入

- 始终创建新作品，不写入当前正文；预览前不出现正式作品卡。
- 识别常见章节标题，作者可在预览修改名称、拆分与顺序；识别不到则整份作为一章。可识别卷标题保留卷章关系，不能可靠识别时让作者调整。
- DOCX 只导入正文段落/可识别标题，图片、表格、其他复杂对象明确提示不导入；保留文本内容，统一固定样式。
- TXT 编码建议见第 11 节；预览乱码需能取消或改编码，不能静默接受乱码。
- 解析失败显示原因、保留可重试条件；确认写入失败不创建残缺作品，也不影响原作。
- 验收：标题识别/不识别、中文编码、特殊字符、大文件、DOCX 图表、取消、失败、新作品隔离。

### FR-12 云端服务、授权与密钥

- 作者配置服务、模型、地址和凭据；客户端不内置用户 API Key，不要求 Python/FastAPI 才能运行。
- 每次实际发送前展示服务/模型、操作、正文范围、写作特点/大纲/知识等实际附件和费用/计费提示；可查看发送内容和取消。
- 无可用报价时显示“费用无法可靠估算，请查看服务计费规则”，不编造免费或精确价格；费用提示不可隐藏。
- 授权仅对所展示的请求有效，内容变化或新增范围须重确认；分块展示全部内容与请求数后再执行，不静默截断或追加上下文。
- 断网不发起、不排队；网络恢复、超时、额度不足、服务错误均由作者手动重试，每次重试重新核对授权，不自动重发。
- API Key 由 Windows 凭据设施或 safeStorage/DPAPI 保护，不进正文、归档、日志/错误报告；允许关闭云端 AI，启用不代替每次授权。
- 验收：未授权/取消无请求，发送清单等于真实 payload；凭据保护与归档排除、断网不排队、超时不重复计费式重试。

### FR-13 AI 正文候选

- 支持单句润色、段落润色、续写、纠错；作者选择目标及当前章节/前章衔接/全卷/自定义上下文。
- 前章按实际正文顺序确定，首章提示无前章；当前章节不属于分卷时禁用“全卷”；自定义只能选择当前作品章节，实际范围在授权前列明。
- 续写插入到作者选定位置；其他修改替换被选范围。单句边界不确定时要求作者确认选区，不能替换整章。
- 展示候选与原文差异、来源版本；流式未完成内容不自动写入，取消或失败保留原文与可标识的未完成候选。
- 原文变化则原候选标过期，重新生成或重新对比；再次确认前验证包含尚未自动保存输入的最新正文，不能沿用旧选区偏移，也不能把重复出现的同一句定位到另一处。
- 接受前自动快照并完成持久化，正文修改和新版本一起提交；快照/提交失败不应用候选。知识/伏笔标记不得随候选静默丢失，需列明变化。
- 验收：候选取消、生成中改文、确认前尚未落盘的新输入、重新对比后再改文、同段重复句、快照失败、插入位置、标记保护、重复点击确认不重复写入。

### FR-14 知识参考与正文回写

- 作者以当前正文触发知识检索；P0 先使用当前作品关键词参考，显示命中内容与出处，作者可选入 AI 上下文。
- 参考用于比较、学习与改写建议；不能未经作者判断直接搬用原句，也不能因知识中的指令改变授权范围。
- AI 从正文生成摘要、角色、事件、伏笔等候选；显示建议分类/标签、正文章节/段落/版本、提取内容。
- 逐条审核后入库，作者可编辑或拒绝；未审核内容不参加正式知识检索。正文已变时标明旧来源，重新复核后才可接受。
- 摘要、角色、事件、伏笔等回写候选先成为知识条目，不自动新建正式伏笔、修改伏笔状态或剧情树；需要关联时由作者在相应架构中操作。
- 入库是新建条目还是更新已有条目须明确展示，禁止仅凭相同名称覆盖知识/角色；更新前保存版本。结构化角色/事件的 P0 载体见第 11 节。
- 验收：接受部分/拒绝其余、内容编辑、来源变化、同名目标、失败恢复、引用不被未确认候选污染。

### FR-15 一致性与剧情感受

- 一致性覆盖角色、时间、地点、伏笔、大纲偏离、写作特点漂移；选择检查范围并遵守云端授权。
- 规则结果仅报告规则可以证明的问题，附具体正文/设定/证据位置；没有结构化事实不编造确定性矛盾。
- AI 结果统一标“AI 建议”，列原因、相关证据和不确定性；剧情感受评价衔接、合理性和剧情偏离，不把文学主观判断标为错误事实。
- 建议可以定位原文、关闭/忽略或另行发起修改候选，不自动改正文、状态或知识。源内容变化时提示结果可能过期。
- 验收：六类样例覆盖、引用证据确实存在、无证据/资料不足情况、结果过期、取消/超时不写数据。

### FR-16 DOCX/TXT 导出

- 导出前完成保存，读取一个一致的已保存版本，期间继续输入不混入本次输出；按该版本卷、章、段落顺序，无卷直接按章节；不丢 Unicode 正文，不依赖云端。
- DOCX 映射固定样式与标题层级；TXT 纯文本，建议 UTF-8；不把编辑器/界面样式代码输出成正文。
- 同一知识 ID 多次引用复用 `[n]`，按首次出现顺序在文末列一次完整引用内容/出处；已删除目标保留可追溯占位。
- 当前作品导出冻结本次读取的知识内容；历史快照导出使用当时知识内容，不替换成当前版本。
- 伏笔正文保留 `[伏笔：名称]`；文末附名称、状态、章节/段落证据清单。标记不改变产品字数统计。
- 输出失败明确提示，原数据/版本不变；已有输出文件覆盖需确认，失败不把完整旧文件换成半个新文件。
- 验收：重复引用编号、已删除知识、伏笔证据、无卷/空章/特殊字符、DOCX 实际打开样式、TXT 编码、磁盘失败。

### FR-17 设置、离线、安装与升级

- 设置纵向分组，个人资料可维护，固定编辑样式只读，分类/标签按当前作品维护；不产生额外“知识库”集合层级。
- 自动保存、单实例锁、AI 费用与逐次授权是强制规则，不把 Demo 开关作为可关闭权限；云端 AI 总开关可关闭。
- 默认 `%LOCALAPPDATA%\RainSoul\Projects`；用户选择备份/导出位置。P0 不承诺任意搬移活动数据目录或云同步。
- 普通用户安装/更新；默认卸载保留作品，明确选择删除才清除；删除数据前能备份，并说明会丢失哪些本机数据。
- 数据库前向迁移前备份；失败恢复备份并阻止进入写作，不自动降级。诊断只含必要错误信息，无正文/完整提示词/Key。
- 验收：Windows 10/11 干净用户环境、单实例、断网完整闭环、安装升级卸载、迁移失败、配置隔离。

### FR-18 后置工具与演示边界

- 正式后置入口显示“后续开发：本功能尚未交付”、当前阶段和返回按钮，不空白、不显示伪成功。
- 拆书未来流程：选有权使用的优秀作品 → 解析 → 逐段勾选 → 核对分类/标签/真实出处 → 当前作品知识入库；不创建手稿作品。
- Demo 拆书是固定样例、会话是模拟数据、保存是内存状态。正式产品不携带“示例入库即真实解析/调用 AI”的误导。
- 需求会话按作品开会话，跨作消息隔离、会话删除确认；XMind 后置目标覆盖所有 XMind 版本，实际交付能力以兼容矩阵与逐版本样例验证；先临时草稿，部分失败尽量保留。
- URL 保持公开授权内容、协议/私网/重定向/大小/超时边界；向量/本地模型等逐项进阶。
- 验收：正式 P0 后置入口正确；未来工具独立评估后制定功能测试，不把 Demo 样例测试当真实交付证据。

## 6 状态与异常规则

| 对象 | 状态与转移 | 必须防止 |
| --- | --- | --- |
| 保存 | 已保存 → 待保存 → 保存中 → 已保存；失败 → 保留最新草稿 → 手动重试 | 旧回执覆盖新状态、未落盘标成功、失败绕过导航 |
| AI | 草稿 → 待授权 → 生成中 → 候选/建议；可取消、失败、过期、已应用 | 未授权发请求、自动重试、取消后回调写入、过期候选覆盖原文 |
| 入库候选 | 待审核 → 接受/编辑后接受/拒绝；来源变化需复核 | 未审核可检索、重复接受创建重复内容、旧来源冒充最新 |
| 导入 | 解析/校验 → 预览 → 确认 → 新作品；失败保持原数据 | 预览创建正式作品、覆盖同名项目、部分解析静默成功 |
| 快照恢复 | 保存当前 → 预览确认 → 事务恢复 → 新当前版本 | 丢失恢复前状态、覆盖历史、失败只恢复部分资产 |
| 删除 | 说明影响 → 确认 → 可恢复删除/关联清理 | 右键菜单残留、取消改数据、误删同名前缀对象/跨作品资产 |

错误按保存/文件/解析/版本冲突/网络/额度/迁移等分类；显示可理解原因与下一步，技术错误码可放诊断详情。任务取消后停止后续步骤，已提交状态不能伪装成已撤销；长任务有阶段进度，但不虚构百分比。

## 7 数据规则与非功能要求

### 7.1 不变量

1. 对象与书签使用稳定 ID；标题、文本偏移和列表顺序都不是唯一身份。
2. 所有关联校验同作品，跨作品复用只能复制并保留来源；其他作品查询始终只读。
3. 知识引用同步当前有效内容，历史快照及历史提取来源使用当时版本；失效证据保留原出处。
4. 恢复、AI 接受、分类迁移和导入确认要么完整成功，要么保持原数据；字数/索引不得与正文长期不同步。
5. 凭据与作者档案不进入作品快照，凭据不进项目归档；日志与诊断不存正文、完整候选或提示词。

### 7.2 非功能要求

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 | 核心闭环完全离线、无远程字体/脚本必需依赖 | 拔网后创建、写作、搜索、快照、归档、DOCX/TXT 往返 |
| NFR-02 | 搜索 UI P95 ≤ 1 秒 | 四核/8GB/SSD Windows；100章/100万统计字/1000知识；固定20查询各10次，预热另计，200样本 nearest-rank 第190个 |
| NFR-03 | 500ms停顿/持续5秒提交，提交成功才算保存 | 可控时间测试＋真实磁盘故障注入；拥塞/失败明确告警 |
| NFR-04 | 无规模产品上限，长作品按章读取和展示 | 长章/长作品/大量卡片压力实验；不加载整作品到编辑器 |
| NFR-05 | 数据保护与可恢复删除，失败不破坏旧状态 | 事务中断、进程中断、归档损坏、迁移失败对照恢复 |
| NFR-06 | WCAG 2.1 AA 所需键盘、焦点、可访问名和对比度 | tab/方向键/Space/Escape、读屏、放大、窄窗口、原位展开 |
| NFR-07 | 云端数据最小化、逐次授权、凭据保护 | 检查真实请求清单、脱敏诊断、未授权网络为零、归档扫描 |
| NFR-08 | Windows 10/11 x64 普通用户安装/更新/卸载 | 打包后干净系统测试，不以开发浏览器通过代替 |

性能夹具、查询文本、随机种子和生成器版本进入版本控制；查询涵盖单字/双字/长词/无结果/标签筛选。产品字数口径与夹具一致，不能更换数据或测量边界来掩盖回归。输入延迟、冷启动和内存另外测量记录，暂不编造基线已确定之外的 SLA。

## 11 补充设计建议与待落实事项

下列是把基线转成实现时的**推荐默认**，不是此前已逐条确认的新增需求。文档可据此评审，开发任务应在对应模块启动前落实页面/规则；改变已确认范围仍需先同步 V2.0。

| 编号 | 事项 | 推荐默认与边界 |
| --- | --- | --- |
| D-01 | Demo缺少的P0入口 | 作品工作区菜单放“写作特点、全文搜索、版本/快照、导入导出”；不增添第四个主标签、不恢复写作页新建作品按钮，详细布局开发前评审 |
| D-02 | 同名与空名称 | 稳定ID允许同名作品/章节，通过位置区分；创建空名称提示输入、重命名空值拒绝，内含空格保留；原型自动添加后缀不作为唯一身份规则 |
| D-03 | 删除恢复入口 | 作品/卷章/伏笔采用可恢复删除，设置本机数据提供可发现的恢复入口；不自动永久清理，不另加大型回收站模块。恢复时保留失效证据提示，不能把同名对象当原对象 |
| D-04 | 跨作品字典映射 | 复制预览选择当前作品主分类，标签按当前字典匹配；未匹配标签由作者在设置维护后再选择，不暗中创建或修改他作字典 |
| D-05 | TXT编码 | 默认UTF-8并识别BOM，解析疑似乱码时提供GB18030预览切换；导出UTF-8，编码变更不改原文件 |
| D-06 | AI提取与规则事实载体 | P0用带类型的知识条目/可追溯事实记录表示角色、事件等；AI事实逐条审核，未知或相冲突事实不自动成为规则依据；细字段见技术方案 |
| D-07 | 超长与分块授权 | 先展示分块数量、各块范围和预计发送；只执行已授权集合。修改正文的跨块结果需整体对比与作者确认，不能逐块静默应用 |
| D-08 | 历史/归档范围 | 快照不包含自己的历史链；归档默认含当前作品及其版本快照，排除作者配置/服务凭据/缓存；是否提供瘦归档由后续单独需求决定 |
| D-09 | 恢复一致性 | 恢复后旧AI候选/分析只作历史，不直接应用；后置会话若将来实现，需另定是否随作品快照恢复 |

实施约束须落实：开发负责人和可用投入、Windows 10/11 验证设备、至少一组可授权的云端测试配置、发布渠道与签名安排。它们影响排期和真实验证，不阻止先做 B0/B1 本地实验。本稿不承诺未验证模型质量、未测性能或发布日期。
