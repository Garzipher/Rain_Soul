## 结论

**当前结论：需求已统一，V2.0 可作为开发基线；资源仍待定，应用尚未实现。** 首版目标是在 Windows 10/11 64 位上完成 V2.0 完整主流程：写作特点、大纲、知识库与分类、伏笔、基础 AI、剧情感受、一致性检查、正文回写、版本/备份和 DOCX/TXT。写作、保存、搜索、版本、备份和导出必须离线可用；AI 经逐次授权使用云端适配层。作者自行决定作品终点，作品字数和章节数不设产品上限，性能测试样本不构成写作上限。

原评审提出的技术栈冲突、P0 依赖不清、数据模型缺口和验证不足，已在 V2.0 中完成需求层统一或转为实施风险。负责人、人力、预算、工期、发布渠道和真实作者试点资源仍需另行确定；本报告的建议不能替代 ADR、测试和发布验收。

## 3. Design：P0 作者旅程与交互

历史评审曾担心作品入口、大纲、分类、引用和归档被错误地拆到不同阶段。V2.0 已将这些能力和 AI 主流程统一纳入 P0；当前应按下列路径实现并做端到端验证：

```text
作品列表（新建作品 / 导入项目归档）
  → 作品工作区（可选卷/章树 + 当前章节编辑器）
  → 插入引用（知识搜索 + 标签 + 条目列表）
  → 版本历史（创建 / 比较 / 恢复为新版本）
  → 备份项目 .rainsoul 或导出成稿 DOCX/TXT
```

全部入口均可见：已交付功能正常进入，后置功能统一显示“后续开发：本功能尚未交付”、当前阶段和返回按钮，不进入空白页。系统只有一个“我的作品”作品集，作品以书架形式展列；“学习路径”是普通作品。头像可上传，头像下方显示并可编辑笔名。基础引用应有可见“插入引用”命令和键盘入口，以光标所在段落为目标，不能只靠“不选中时右键”。

| 场景 | 初始/进行中 | 失败与恢复必须可见 |
| --- | --- | --- |
| 无作品或章节 | 直接显示“新建作品/导入项目”或“新建章节”；卷可选。 | 删除章节前自动快照并确认；非空卷不能直接删除。 |
| 编辑与切换 | 每章实时字数；“保存中/已保存”及最后保存时间。 | 保存失败保留当前输入、提供重试；阻止切换、快照、归档、导出与关闭。 |
| 搜索与引用 | 结果标明“章节/知识”，显示片段、来源、高亮及跳转；弹窗保留焦点。 | 无结果可清除筛选；已删除知识显示占位和最后来源。 |
| 版本 | 可按章节比较，恢复前预览旧版本。 | 失败不改变当前稿；恢复前状态和全部历史仍可访问。 |
| 交稿与备份 | 区分“导出成稿”和“备份项目”，显示目标、格式与进度。 | 错误显示目标路径与重试，不显示虚假的成功。 |

设计完备度评分仅针对**方案文本**：信息架构 4/10、交互状态 2/10、作者旅程 4/10、设计系统 2/10、桌面可访问性 1/10。需要补最小窗口、125%/200% 缩放、窄窗口侧栏、键盘卷章排序、对话框焦点恢复和非颜色保存提示；仓库尚无 `DESIGN.md`。视觉效果不能在没有应用时评分。

## 4. Eng：P0 推荐实现与数据约束

### 4.1 架构选择

历史评审曾根据早期方案把 Tauri 2 + FastAPI + SQLModel + sqlite-vec 称为“已确认”，与[早期首版技术设计](E:/soulrain/docs/superpowers/specs/2026-09-28-rain-soul-mvp-design.md:42)的 Electron + React/TypeScript + SQLite 冲突。需求统一后，V2.0 [第 8.1 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:315)已将 Electron + React/TypeScript + SQLite 定为当前基线，Python/FastAPI 仅用于学习与验证；下表保留替代路线的实施风险，不表示当前存在技术栈冲突。

| 路线 | P0 判断 | 必须验证的代价 |
| --- | --- | --- |
| **Electron + React/TS + SQLite** | 沿用既有决策；主进程负责文件/数据库，受限 preload 暴露业务命令。编辑器候选为 Tiptap 开源核心。 | 原生 SQLite 模块重编、主进程阻塞隔离、安装包体积和 Windows 安装升级。 |
| Tauri 2 + Rust + SQLite | 仅作为未来另行论证的 ADR 备选，不属于当前首版路线。 | Rust 开发/维护、WebView2 依赖、插件兼容、实际包体和性能。 |
| Electron + FastAPI/Python sidecar | 当前 P0 客户端不依赖本地 FastAPI 服务；Python/FastAPI 纳入学习和验证路径，云端 AI 适配也不预绑定 FastAPI。 | 若未来确需 sidecar，需单独评估 Python 打包、启动/退出、端口鉴权、崩溃恢复、杀毒误报和升级同步。 |

当前首版技术栈已统一为 Electron + React/TypeScript + SQLite，主进程负责本地文件与 SQLite，React 负责界面，preload 仅开放明确的业务命令。先做“安装 → 离线写一章 → 保存/异常恢复 → DOCX/TXT → 升级”的 Windows 纵向验证；重点检查原生 SQLite 模块重编、主进程阻塞隔离、安装包、迁移和恢复。Python/FastAPI 用于 Rain_Soul 的 AI 学习与验证，不要求首版客户端启动本地服务；任何换栈需另立 ADR 并比较同条件样例。

```text
React/受限编辑器 → preload 业务命令 → IPC 参数与路径校验
                    → 单写入队列/SQLite 事务 → 提交 revision 回执
                    → UI 显示该 revision 已保存
快照/导出/归档 → 先 flush 待保存内容 → 一致读 → 临时产物 → 校验/替换
```

### 4.2 各功能的最小可靠实现

| P0 功能 | 推荐实现与关键边界 | 验收证据 |
| --- | --- | --- |
| 作品、卷、章 | 每项目目录与稳定 UUID；`chapter.work_id NOT NULL`、`volume_id NULL`，约束卷与章同作品；根章和卷内章分别排序，移动/删除整事务。早期评审曾发现章节字段缺少 `work_id`，无法可靠归属无卷章节；V2.0 [第 7.1 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:286)已补齐该字段，实施时仍需验证约束。 | 不建卷也可增章、移动、排序、归档和恢复；错卷引用被拒绝。 |
| 固定编辑器 | Tiptap/ProseMirror 限定标题外置、段落、纯文本和引用原子节点；章节结构化 JSON 是正文唯一事实源。段落/引用各有稳定 ID，搜索文本和引用关系为事务内派生数据，避免 `paragraph.content` 与位置 `anchor` 双写漂移。 | 输入法、粘贴清洗、撤销、拆段/合段/移动/复制后的 ID 与引用正确。 |
| 字数、自动保存 | Unicode 码点规则计汉字、字母、十进制数字，排除引用节点、标点、空白与标题；约 500ms 停顿保存，连续输入最长 5s 落盘；按递增 revision 串行提交。WAL/同步级别用断电测试决定。 | 即时字数与落盘值一致；旧保存回执不能覆盖新状态；磁盘满/只读时保留输入并阻断旧稿导出。 |
| 知识与搜索 | 知识条目稳定 ID、软删除与最后标题/来源；标签用关系表。正文和知识共用来源标注搜索结果。可先验证 SQLite FTS5 trigram 对三字以上连续串的候选能力，一/二字走确定的短词路径并精确复核；未达到延迟基线再加一/二元索引。标签 AND 用关联表聚合，非知识结果在有标签筛选时不显示。 | 汉字单字/双字/长词、无结果、筛选、高亮跳转正确；固定样本 UI P95≤1s。 |
| 行内引用 | 引用节点保存 `citation_id + knowledge_id`，编号导出时按首次出现顺序生成；随节点拆合与移动，删除仅影响当前正文，快照保留历史。条目编辑显示最新值，软删除显示可追溯占位。 | 拆分、合并、复制粘贴、移动、删除及重复引用后无悬空/重复 ID。 |
| 手动快照与恢复 | 同一事务保存作品结构、正文、引用和知识的一致不可变版本；恢复前 flush 且保存当前状态，再复制旧状态为新当前版本和新快照，失败整体回滚。用 SQLite backup API/一致读生成归档，不能直接复制 WAL 模式主 DB 文件。 | 可比较两版；恢复旧版后当前前态及原历史均可访问；注入中断后原稿不变。 |
| 项目归档 | `.rainsoul` 包含格式版本、校验信息和项目依赖；先临时生成再发布。导入校验格式、校验和、条目大小、ZIP 路径与解压总量，迁移后创建**新项目 ID**，不覆盖旧项目。 | 往返核对正文、知识、引用、快照；损坏包、旧版包和路径攻击均可解释地失败。 |
| DOCX/TXT | 从同一导出中间结构按卷章顺序渲染；DOCX 固定中文字体/标题样式，TXT UTF-8；正文保留引用编号，文末按首次出现生成清单，已删除条目标状态；临时文件成功后再替换目标。 | 用 Word 和纯文本阅读器打开，核对排序、样式、编号、清单；失败不损坏源数据和旧目标。 |
| Windows 发行 | 固定 `%LOCALAPPDATA%\RainSoul\Projects`，单实例锁、版本化前向迁移与升级前备份；普通账户离线安装。卸载默认留数据，删除需明确选择；发布前决定签名与分发渠道。 | 干净 Win10/11 x64 安装、重启、升级、卸载留数和断网验收。 |

知识库作用域已由 V2.0 [第 6.5 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:211)和[第 6.6 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:220)统一：知识条目按作品保存，手动快照包含作品及知识状态；全局页面只读汇总，跨作品复用时复制并保留来源作品和原条目 ID。实施时需验证归档往返、快照恢复、全局只读权限及复制来源信息，确保恢复一个作品不会修改另一个作品。V2.0 的数据字典位于[第 7.1 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:278)，应按每种实体的实际生命周期约束字段，不要求所有表机械地添加类型、状态、版本和来源字段。

### 4.3 P0 验收门槛与故障注入

V2.0 [第 10.1 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:376)列出 P0 产品验收，[第 10.3 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:415)列出开发验证要求。以下补充实现阶段应固定的测试证据，不增加真实作者试用门槛：

1. 干净 Windows 10/11 x64 普通账户、断网安装并完成创建、编辑、引用、快照、DOCX/TXT、归档往返；原位升级后已保存数据不变。
2. 保存失败时保留未保存内容，阻止切换、关闭、快照、导出和归档；异常退出仅保证恢复到最后一次成功落盘，并显示时间，不承诺未落盘输入零丢失。
3. 搜索固定样本为 100 章、100 万统计字、1000 条知识；四核/8 GB/SSD Windows 机上，预热一次、20 条固定查询各 10 次，UI 发起到结果显示 P95≤1s。覆盖单字、双字、长词、无结果、标签 AND；样本**不是**作品大小上限。
4. 引用在拆/合/移动段落后仍指向正确知识，软删除可追溯；恢复旧快照生成新版本且保留恢复前状态；归档导入为新项目。
5. 由开发团队使用固定样例和故障注入验证保存失败、快照恢复、归档往返、迁稿识别、搜索及导出；真实作者试用可作为后续可选研究，不是首版门槛。资源排期前仍需明确负责人、人力、预算与周期。

测试分层：单元测字数、排序、标签和引用编号；数据库集成测 revision 竞争、迁移、知识隔离、磁盘满、快照回滚；文件集成测 DOCX/TXT、损坏/恶意归档；Windows E2E 覆盖安装到交稿。项目尚无应用源码、构建与这些测试，不能把文档评审视为产品验收。

## 5. P0 实施风险与后置扩展评估

写作特点、大纲、知识库与分类、伏笔、基础 AI、剧情感受、一致性检查、正文回写、版本/备份和 DOCX/TXT 均属当前 P0。表中这些 P0 项的实现建议用于降低纵向集成风险；其余扩展须逐项补充用户问题、使用证据和质量门槛，通过独立评估后再决定阶段，不因列入候选而自动排期。开发验证以固定样例、回归测试和故障注入为主，不要求真实作者试用。

| 功能与阶段 | 进入条件 | 推荐实现与禁止的捷径 |
| --- | --- | --- |
| P0 写作特点与大纲 | 保持版本和证据关联，避免计划数据与正文脱节。 | StyleProfile 版本化，支持作品默认和章节覆盖；大纲按卷→章→详细节点组织，使用同作品关联并约束树无环，不自动生成章节。 |
| P0 伏笔与行内书签 | 书签在段落编辑、拆合和移动后仍可定位。 | 伏笔采用五状态；埋设、触发、回收分别记录章节/段落证据。知识引用和伏笔书签保存稳定目标 ID，不用字符偏移。 |
| P0 AI 润色、续写、纠错与正文回写 | 云请求必须逐次授权，候选不能覆盖作者的新修改。 | 候选保存原文 revision、选择范围、上下文清单与模型参数；对比后确认，原文变化则重生成或重新对比，确认前自动快照。回写经逐条审核并保留来源章节、段落和正文版本。 |
| P0 一致性检查与剧情感受 | 分清可核验规则和主观 AI 判断。 | 检查角色、时间、地点、伏笔、大纲偏离和写作特点漂移；规则结果给证据，AI 结果显示依据与不确定性并标为建议，不自动改稿。 |
| P0 知识分类、引用与全文搜索 | 验证中文单字/短词、标签 AND 和来源定位。 | 知识条目按作品维护；一个主分类、可多标签，分类删除前迁移条目；书签关联稳定 ID。用固定查询集验证 FTS5/短词策略及 UI P95≤1 秒。 |
| 后置：需求会话、跨作品分析 | 单独证明需求、数据权限与版本边界。 | 默认只读分析，按章节分块并引用证据及 revision；只生成明确变更提案，作者确认后才写库，可取消，不给 Agent 任意数据库权限。 |
| 后置：手工拆文、URL 输入 | 作者明确需要导入来源并完成版权、安全边界验证。 | 先显示候选供确认；网页仅限作者有权使用的公开内容，限制协议、私网地址、重定向、大小和时间，不突破反爬并保留出处。 |
| 后置：XMind、EPUB/PDF、本地模型、向量检索 | 各项分别有格式/查询样本、隐私分析和质量门槛。 | XMind 解析后先形成临时草稿，确认才写入大纲；EPUB/PDF 复用导出结构并验证兼容性；本地模型和向量索引可独立关闭/重建，关键词检索保持可用。 |

AI 由作者配置云端模型后可用；每次发送前显示内容范围、模型服务与预计费用，默认不自动发送。V2.0 [第 8.3 节](E:/soulrain/docs/Rain_Soul_项目立项方案_V2.0.md:338)已规定密钥使用 Windows Credential Manager 或 Electron `safeStorage`/DPAPI，且不进入归档、日志或错误上报；实施时仍需验证凭据清理、错误路径和打包环境。渲染进程禁 Node、启用上下文隔离和 CSP，所有 IPC 命令校验参数与文件路径。

**后置评估门槛：** 每项单独评估真实需求、安全、失败恢复和质量指标；向量检索需证明关键词不足且有可测增益，自动导入需用标注样本校准误收率。没有足够证据时保持人工确认，不预设 P1/P2 阶段。

## 6. DX：开发与交付体验

Rain_Soul 的用户是作者，不是 SDK 或 API 使用者；DX 只评价开发团队能否稳定构建、迁移、调试和交付。当前 `package.json` 仅有 Playwright 浏览器配置测试，没有应用启动、Lint、类型检查、数据库迁移或 Windows 生产构建。学习卡应是内部知识产物，不能替代运行手册、ADR、可复现开发环境和发布验收。

建议在 P0 开工时建立：固定 Node/包管理器版本和锁文件；`dev`、单元/集成、Lint、类型检查、Windows 打包命令；测试数据库和示例作品；SQLite schema 版本化前向迁移、升级前一致备份与失败恢复演练；Electron 原生模块重编、安装升级与签名检查；错误日志记录阶段、错误码和项目 ID，排除正文与密钥。学习卡可解释实现和实验，但不作为作者验收门槛。当前测试只检查 Chrome 启动及访问百度，不能验收离线写作；开发首次启动时间在应用出现前不可测。
