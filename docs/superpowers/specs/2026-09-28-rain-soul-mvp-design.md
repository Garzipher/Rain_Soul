# Rain Soul 首版立项评审与设计

日期：2026-09-28

## 立项评审

评审对象为 `Rain_Soul_项目立项方案_V1.0.docx`。附件脚本已运行并生成该文件；文档结构检查得到 130 个段落、15 张表，Word 导出的 13 页预览未发现裁切、重叠或表格溢出。

结论：**建议有条件通过需求立项，不按 V1.0 的 P0 范围直接排期开发。** 首版以真实作者能在 Windows 上离线完成一部自定作品并导出为目标。本设计是收敛后的需求基线，预算和交付日期不在此次评审中批准。

V1.0 与已确认目标的冲突如下：

| 位置 | 问题 | 本设计的处理 |
| --- | --- | --- |
| 第 3、6 章 | 将 AI 重写、正文回写、一致性检查放入写作主链 | 主链只包含写作、知识引用、版本、导出 |
| 第 4 章、附录 A | 向量检索、AI 重写、学习路径进入 P0；全文搜索反在 P1 | 全文搜索进入首版，其余移出首版 |
| 第 7.1 章 | 同时承诺 Windows、macOS、Linux | 首版仅支持 Windows 10/11 64 位 |
| 第 11、12 章 | 阶段与验收仍包含 AI、伏笔、语义检索、学习路径 | 按本设计的端到端验收替换 |

原文还缺少负责人、人力、工期、预算和试点作者安排；这些需要项目负责人在资源排期前补齐。版式上，目录字段需要在 Word 中更新，跨页表格应重复表头。这两项不影响内容评审结论。

## 产品边界

首版面向单机单用户，一次只编辑一部作品。目标平台为 Windows 10/11 64 位，普通用户可以安装、启动和使用；断网时全部首版功能可用。默认项目数据目录为 `%LOCALAPPDATA%\RainSoul\Projects`，不自动上传作品内容。

首版闭环：创建/打开作品 → 可选分卷与章节编排 → 编辑正文并自动保存 → 手工维护知识条目 → 全文搜索与标签筛选 → 在段落插入引用 → 手动快照、比较及恢复 → 导出 DOCX/TXT。用户可选择位置导出项目归档，并从归档恢复为一个新项目。

首版不设置人工章节数或字数上限。AI 润色/改写、模型接入、向量及语义检索、自动知识抽取、伏笔与剧情分析、学习地图、多人协作、macOS/Linux 均属于后续范围，不构成首版验收条件。

## 结构与交互

作品结构固定为“作品 → 可选分卷 → 章 → 正文段落”。可创建、重命名、排序和删除分卷与章节；无分卷的章节直接位于作品下。非空分卷须先移走或删除其中章节，不能直接删除；删除章节前先生成快照并要求确认。章节标题独立于正文；编辑器采用受限所见即所得格式，正文统一使用微软雅黑 12 pt、1.5 倍行距、`#242424`，章节标题使用微软雅黑 16 pt、加粗、`#1C1C1C`。首版不开放任意富文本样式。

每章实时显示字数，只统计 Unicode 汉字、字母和数字，不计标点、空格及换行；作品总字数为各章之和。编辑器即时更新显示值，自动保存成功后持久化统计值。

知识条目由用户手工创建、编辑、软删除，包含标题、内容、来源、标签及更新时间。搜索同时覆盖章节标题、正文和知识条目标题、内容；结果标明章节或条目来源，展示匹配片段并高亮命中词。多个标签按“同时满足”筛选；选择标签时只显示匹配的知识条目，空标签筛选显示全部搜索结果。中文单字、短词及连续字串都要能命中，点击结果定位到章节或条目内的命中位置。

引用是正文中的独立行内标记，拥有稳定引用 ID，并以稳定条目 ID 关联知识条目；所属段落也有稳定 ID。拆分段落时引用跟随标记所在一侧，合并或移动段落时引用随标记移动，删除标记或其所在内容时仅从当前正文移除引用，历史快照仍保留。条目编辑后，引用显示最新内容；条目软删除后显示“已删除条目”，同时保留最后一次标题、来源与条目 ID 以供追溯。删除条目不会删除正文引用。

## 技术设计

采用 Electron + React/TypeScript + SQLite。React 渲染界面和受限编辑器；Electron 主进程处理数据库、文件、归档与导出；预加载层只暴露明确的业务命令。渲染进程不直接访问文件系统或数据库。关闭 Node 集成、启用上下文隔离与内容安全策略，并校验 IPC 参数和目标路径。

SQLite 保存作品、分卷、章节、结构化正文、知识条目、标签、引用和不可变快照。数据库启用外键、WAL 与版本迁移。DOCX 和 TXT 都从同一份结构化正文生成，导出文件不是源数据。中文搜索使用经过测试的 n-gram 索引方案，短查询有确定的匹配路径；不得假设默认 FTS 分词器能完成中文短词搜索。

编辑停顿约 500 毫秒后，以事务保存当前更改；持续输入时最多间隔 5 秒落盘一次，切换章节、关闭窗口、快照、导出和归档前立即保存。界面显示“保存中 / 已保存 / 保存失败”；保存失败时保留编辑器内未保存内容并允许重试，快照、导出、归档及关闭窗口必须中止，不能把旧落盘状态当作成功结果。异常退出后恢复到最后一次成功落盘的状态，重启时显示该次保存时间；不能承诺未落盘输入零丢失。

手动快照保存作品结构、正文、知识条目和引用的一致状态。版本列表可查看创建时间并按章节比较文本。恢复旧快照前先完成当前内容保存，并保存当前状态为不可变快照，再把旧状态复制为新的当前版本及新快照；任一步失败都中止恢复，原历史不覆盖。归档使用带格式版本和校验信息的 `.rainsoul` 文件，导出须取得一致数据库快照；导入先在临时位置检查格式、校验和与路径安全，再创建新项目，失败时不覆盖现有项目。

DOCX/TXT 按分卷及章节顺序输出标题和正文。DOCX 映射固定正文与标题样式，TXT 使用 UTF-8 编码；两种格式均在正文保留引用编号，并在文末按首次出现顺序生成引用清单，包含条目标题与来源，已删除条目显示删除状态。导出先写临时文件，成功后再替换目标；磁盘不足、路径无权限、文档生成失败均明确提示且不修改源数据。

## 验收与质量门槛

1. 在干净的 Windows 10/11 64 位普通账户中安装并首次启动，断网创建作品、可选分卷、章节和段落；重启及原位升级后，已成功保存的正文、顺序、字数、知识、引用与版本保持一致。卸载默认保留用户作品数据，删除数据须由用户明确选择。
2. 在编辑停顿约 1 秒内观察到已保存状态；持续输入期间仍定期落盘；模拟异常退出后恢复到最后一次成功保存并显示保存时间。注入保存失败，验证快照、导出、归档及关闭窗口被阻断，未保存编辑内容仍可重试。
3. 创建、修改、软删除知识条目；按多个标签 AND 筛选；搜索正文和知识条目，验证中文单字、短词、无结果、空查询、来源标记、片段高亮及跳转定位。固定性能样本为 100 章、100 万统计字、1000 条知识条目；在四核 CPU、8 GB 内存、SSD 的 Windows 测试机上，预热一次后以预先固定的 20 条查询各执行 10 次，覆盖单字、双字、长词、无结果及标签筛选，测量从发起查询到结果显示的 P95，不超过 1 秒。该样本仅用于回归测试，不是作品上限。
4. 在指定段落插入引用，拆分、合并、移动或删除段落后检查引用归属；修改条目后引用更新，软删除后仍显示可追溯占位；创建至少两个手动快照，查看差异并恢复旧快照，验证恢复前状态和全部历史仍可访问。删除非空分卷被阻止，删除章节前自动快照可恢复。
5. 导出 DOCX/TXT，在目标阅读器中打开，检查分卷、章节顺序、正文、标题样式、引用编号与文末清单；导出失败不得损坏项目。归档导出后导入为新项目，逐项核对内容与版本。
6. 至少一位真实作者在试用前记录作品目标及完成条件，随后独立完成并导出；通过条件为目标达成、文件可打开且已成功保存的内容无不可恢复丢失。记录故障与使用反馈，不以预设章节或字数限制作者。

实现时按项目规范为核心逻辑编写单元测试，并覆盖数据库迁移、保存恢复、搜索、引用、版本、归档和导出集成路径；对完整离线写作闭环做端到端测试。交付前运行完整测试、Lint、类型检查和 Windows 生产构建；所有新增功能按项目规范提交。

## 主要风险与立项条件

- 中文检索的短词正确性与 P95 性能需用固定样本实测；默认 SQLite 分词行为不足以直接作出承诺。
- 受限编辑器到 DOCX 的样式和引用映射需以实际 Word 打开结果验证；中文字体替换也要检查。
- Electron 的 IPC 边界、原生 SQLite 模块打包与 Windows 安装升级需进入构建和安全检查。
- 自动保存只能保证最后一次成功落盘的内容；项目归档承担用户主动备份与迁移，不能替代实时保存。
- 负责人、人力、预算、工期和试点作者需由项目负责人确认后再做资源排期；本设计不虚构这些数字。
