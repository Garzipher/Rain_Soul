# URL 素材导入、自动拆文与本机语义检索设计

日期：2026-10-10；状态：书面规格已于2026-10-10获用户确认，Demo界面基准已确认；实施计划待审阅，正式功能尚未实施。

依据：立项 V2.0、PRD FR-19～21、1.2.0 拆书与知识参考实现。本文是扩展设计，不另建立项方案，不宣称全部 P1 或发布门禁完成。

## 1 目标与成功条件

作者导入有权使用的公开文章或本地 TXT/DOCX，预览可信原文，获得 AI 摘录与写法讲解，审核后加入当前作品知识库；写作时用本机语义与关键词查找参考，阅读出处、选择素材并决定是否改稿。作者还能学习写作手法和仿写练习。

用户已选择本机生成向量。嵌入和检索不得外发知识文本、查询或作品正文；下载固定模型时只发送下载请求。现有云 AI 拆文、写作仍按照已有逐次授权规则运行，只有完整预览、明确确认的材料才能发往所选服务。本机检索不等于本机生成式 AI，界面必须分别说明。

## 2 方案比较与选定方向

| 方案 | 优点 | 成本与取舍 |
| --- | --- | --- |
| 本机 CPU 嵌入 + SQLite 缓存 + 混合排序（采用） | 离线，无独立服务，素材留在本机，跟随现有桌面架构 | 模型安装和内存占用须验收，首次索引需要等待 |
| 本地 Ollama 嵌入服务 | 模型切换方便 | 普通作者需额外部署服务，与现有安装目标不符 |
| 云嵌入服务 | 客户端较轻 | 需要外发知识和查询，不符合本轮选择 |

网页走独立安全 GET 与无脚本正文解析；不能复用读取凭据和 POST 的 `sendAiCompletion`。只复用经审查后的公开地址检查与固定 IP 连接底座。语义模型在独立 Worker 运行，不与写作保存数据库 Worker 争用长任务。

## 3 URL 导入

拆书工具提供本地文件、公开网页和粘贴正文三种来源。网页输入清楚提示会联网访问目标网站；点击获取后显示进度和取消，绝不把网页载入应用 WebView。

首批只支持 HTTPS、443 端口、无用户名密码的公开 HTML 页面；拒绝 IP 私网、环回、链路本地、保留地址及本地域名。每次重定向重新检查域名、DNS 全部结果和目标协议；最多三次重定向，固定经过检查的 IP 建连，TLS 验证原域名。不携带 Cookie、云 API Key、作者资料或登录信息。

全程上限 30 秒，包括 DNS、重定向与响应；取消立即中断连接，不被文件串行队列阻塞。响应压缩前最多 2MiB，解压后最多 5MiB；流式限额，不能只看 Content-Length。只接受 HTML/XHTML 文本，编码支持 UTF-8、GB18030，未知或乱码拒绝并提示粘贴正文。解析禁止脚本执行、外部资源和实体解析，节点数与解析耗时受限。

正文去掉导航、广告和脚本；保留段落边界，不自动将页面声明的作者当成已验证作者。提取为空、登录页、反爬或复杂动态页时解释原因，提供粘贴正文或本地文件入口；不绕过访问限制。获取网页不是获得使用权，作者沿用现有素材权利确认。

获取结果冻结为预览：来源种类、原始网址、最终网址、页面标题、获取时间、规范正文 SHA-256、段落 ID/序号/文本及段落哈希。渲染层只提交预览 token 与段落 ID，不能替换网址或原文。作者可编辑显示标题、作者与摘录，主进程保持原始获取记录，既有 TXT/DOCX 出处不改写。

网页原文上限二十万Unicode code point、两千个非空段落；URL最多2048字符、页面标题最多200字符，超限拒绝并解释，不静默截取。保留原始解压字节哈希与规范正文哈希。hashVersion=1规定：提取的每段文本CRLF/CR转LF，删除trim后为空的段落，其余文本保留首尾空白、不再Unicode正规化；顺序不变。正文哈希是 `SHA256(UTF8(JSON.stringify(段落文本数组)))`，段落哈希是 `SHA256(UTF8(冻结单段文本))`，避免不同段落边界得到同一哈希。重启、复制和归档不再重新提取原页面。

审核入库时在同一作品事务新增 `source_document`、`source_segment` 和知识来源关联，保存冻结正文与段落证据；未审核素材仅存临时草稿。知识的现有 `origin_json` 继续专用于跨作品复制，不混装网页来源。作品schema升级为v6，先备份再事务迁移与完整性校验，失败恢复旧库。同步快照、历史、复制及归档schema白名单与往返测试；旧知识保持原source，新增来源关系为空，不能从文字猜造URL。删除知识沿用软删除，来源仅在无有效引用且历史策略允许时清理。

作品schema版本与快照payload版本独立：保留既有payload1及v4/v5归档导入；先核对旧payload原哈希，再按该旧schema固定表集合验证，转换内存模型时补空来源和学习注释关系，不改原历史hash。新快照使用payload2与v6表集合，读取同时支持1/2。禁止旧快照按新表集合直接校验而失效；必须覆盖“升级前快照→v6恢复→导出归档→新作品导入”的完整路径。

## 4 分批自动拆文

单批沿用现有最多二十段及模型容量限制；作者先选范围，再看到各批原文、服务模型、输入/输出 token 预算与计费提示。默认逐批确认，每批完成暂停，作者可检查建议再确认下一批；一次操作不自动发送整书。

段落无法装入模型时不静默截断，提示缩小范围；首批不拆开单个超长段落。执行串行，支持取消，未知回执先查询本机结果、不重复发送。建议逐字匹配冻结原段，分类和标签只能来自当前作品有效字典。伪造或拼接摘录整批不能采纳。

成功候选进入本机临时拆文草稿，按批次和请求哈希记录。取消、断网及应用重启保留已完成结果和审核草稿；未完成请求不自动恢复联网。没有配置云服务仍可手工摘选。每次入库最多一百条，复用现有修订/CAS、operationId 幂等及原子事务；任何失败不产生部分知识条目。

草稿持久化完整冻结预览、原始来源、段落身份/hash、批次请求hash及生成时分类标签证据。重启作废旧发送授权，仅恢复本机完成候选；应用前重新验证原段和当前有效分类标签，作者重新审核后取当前revision执行CAS。前一批入库引起的revision变化不要求剩余候选重新联网生成，来源变化则不能直接采纳。发送入库确认前先原子持久化冻结operationId、请求内容/hash与committing状态；作品事务提交和草稿更新不共享事务，重启先核对原operationId回执。未知结果使用同一操作身份核对/幂等重试，禁止生成新身份重复创建知识。

AI 对写法、适用场景和仿写练习的说明作为可编辑学习注释，与原文摘录区分保存；保留实际来源。不自动纳入作者正文，不把 AI 讲解当原著内容。归档应带入已确认学习注释，快照恢复遵循作品资产规则；未入库拆文草稿不属于已确认知识资产。

## 5 本机模型与部署门禁

首选候选为 BAAI/bge-small-zh-v1.5 的 CPU ONNX 导出（512 维，512 token 输入窗口），运行适配候选为 `@huggingface/transformers` + `onnxruntime-node`。这是实施验证方向，不是已安装或已验证性能声明。

实现前用固定模型修订和固定运行库版本验证：上游许可证及导出分发溯源、Tokenizer 与向量池化/归一化一致性、中文查询前缀、真实 Windows x64/Electron 44 启动、离线执行、原生依赖打包与第三方许可。若转换模型分发依据不完整，从上游固定权重导出，不以模型卡缺失信息推定许可。

模型使用 CLS pooling + L2 归一化，查询前缀为“为这个句子生成表示以用于检索相关文章：”，文档不加查询前缀。指纹包含固定修订、ONNX/tokenizer哈希、量化类型、池化、前缀和分块版本，512窗口包含前缀及特殊token。候选量化模型镜像元数据约22.90MiB（非本机已下载验证）；不能据磁盘大小推定运行内存，不能使用默认mean pooling替代原模型方法。

设置显示模型名称、版本、许可证、实际下载大小、所需空间和运行状态。作者明确安装后下载，或导入受支持的离线模型包；每个文件由随应用固定的清单校验 SHA-256、长度与允许路径，不运行包内代码、不接受任意远程模型脚本。下载临时文件，校验通过后原子激活；取消或失败保留原可用模型。

模型放在 `%LOCALAPPDATA%/RainSoul/Models`，向量缓存放在 `%LOCALAPPDATA%/RainSoul/Retrieval`，不会进入作品归档或日志。禁用运行库隐式远程模型请求与遥测；断网测试必须证明没有网络连接。无模型、空间不足或加载失败不阻断写作、保存、关键词搜索和导出。

## 6 索引与检索

首批索引各作品的有效知识条目，正文只是本机查询来源，不建立全书正文向量索引。按实际 tokenizer 对长条目分块，每块最多四百 token、重叠五十 token；查询正文最多四百 token，另计前缀与特殊token且总计不得超过512。超限返回缩小范围提示，不静默截断整章，作者可指定选中段落或输入检索意图；关键词查询仍保持原规则，不因语义失败丢失结果。

SQLite 派生缓存主键包含作品 ID、条目 ID、正文哈希、模型版本、分块版本与块序号，Float32 归一化向量同时记录维数。源正文是事实来源。生成任务获取正文与哈希副本，提交时再次核对；作者编辑、删除、恢复或切换模型后旧向量立即不得被检索，不等待重建才排除。

缓存提交携带索引代，切换模型用代号CAS拒绝晚任务。缓存和源作品库不共享事务，因此返回检索结果前必须经源数据库按条目ID、正文hash、未删除状态与作品仍有效做批量校验，回执附源校验修订；导航或作者编辑使修订不符时丢弃/重查。选为云参考前主进程再次校验当前源数据并冻结，不依赖缓存提交前单次检查避免TOCTOU。

条目更新做增量索引；归档导入、快照恢复和模型升级重建，重启可继续未完成索引而不联网。重建采用新代缓存，完成后原子切换，索引损坏可删除派生缓存重建，不能修改或删除知识正文。索引队列低优先级、有限批次，前台查询优先，不影响 500ms/5 秒保存约定。

首批采用分块余弦相似度扫描，聚合到条目后与关键词候选通过 RRF（k=60）融合；避免增加尚未证明必要的向量数据库原生扩展。分类（含子类）和标签 AND 在两路候选获取前应用；按 `(workId, entryId)` 去重、稳定排序。结果显示匹配方式、相关摘录和出处，分数不称为正确率，低相关时明确告知没有可靠参考；完整模型指纹而非仅模型显示名参与缓存隔离。

知识页支持关键词/语义/混合，正文全文搜索保留既有语义。全局知识汇总用各作品索引并保持所有者身份，不能跨作品修改；写作 AI 默认只推荐当前作品。跨作品参考先复制到当前作品，保留来源。

写作 AI 改用异步本机检索结果，作者选择最多五条，完整正文和来源进入既有发送预览；主进程重新校验当前作品、条目未删除和修订。移除渲染层 `relatedAiKnowledge` 旧关键词列表过滤，不能使正确语义匹配在发送时丢失。检索响应带查询序号、作品 ID、内容版本，切作品和旧查询回执不得覆盖新结果。

## 8 产品可用性修正与验收

已确认两项缺口：`App.tsx` 知识范围请求清空状态后显示后置功能占位，失败没有就地重试；`ai-workspace.tsx` 只有两段纯文本对照，缺少 PRD AC-14 所要求的候选差异。本批增加真实加载/错误/重试状态和可访问的增加/删除差异高亮；单句、段落、续写分别显示目标范围，原文过期不得确认写入。

检索命中不局限于自动推荐前五条：知识卡提供“用于写作参考”，当前作品选择最多五条并保留写作选区；其他作品先复制。切到知识库核对再回正文时保留当前作品待审核候选与生成时原文，过期重新核对；作品切换严格隔离。审核入库成功提示放到不被卸载的外层，并保留同一拆文任务未处理材料、已处理标记和继续入口，不能为了处理第101条重选整份素材。

知识空态区分尚未储备、分类/标签无结果、检索无结果；分别提供导入素材、清除筛选和改写查询入口。实际作者试用仍是后续可选证据，不改变此前开发团队测试发布规则；团队任务测试必须记录首次使用体验，不能宣称已验证真实作者文学收益。

开发团队执行七条任务：空作品首次写作；网页获取并审核入库；离线手工入库；表达不同的中文检索并定位来源；AI 选用参考预览取消及确认改稿；保存/索引/下载/云响应失败恢复；作品归档往返与导出。记录每条的步骤、用时、错误与截图，不能用功能数量或替身成功代替产品效果。

发布本轮功能必须通过：

- 网络攻击夹具覆盖 DNS 重绑定、私网/IPv6、跨域重定向、压缩炸弹、伪 Content-Length、编码及取消，全程不泄露凭据；浏览器或 Electron 不执行素材脚本。
- 索引生命周期覆盖编辑中提交、软删除、恢复、导入新作品、模型切换、损坏与 Worker 崩溃；旧知识或跨作品条目不能出现在当前 AI 授权中。
- 固定中文知识夹具至少一百条、三十条查询，其中十五条语义改写、五条无相关项；人工标注后评估 Recall@5，语义改写组混合 Recall@5 至少 0.8 且不低于关键词；不以生成的随机向量证明质量。
- 无相关项不计算Recall；另报告五条无相关查询中错误宣称可靠语义参考的查询比例，最多一条误报。可靠参考相似度阈值用独立校准集选择并记录到模型清单，最终验收集不能参与阈值拟合；低分候选可供作者探索，但不能标为可靠推荐或自动选入云请求。
- 保留既有关键词 P95≤1 秒门槛；模型预热后千条知识、二百查询样本的混合结果 P95≤1 秒，首次加载单列；默认 CPU 同时索引时写作保存不能超出既有五秒落盘要求。
- 新核心功能纳入覆盖率 80%门禁；全部单元/集成/桌面/Demo、类型、Lint、构建与独立安全/代码审查通过，再小步中文提交。
- 实际新包证明 CPU 模型离线执行和许可完整，不用开发目录或旧包替代；真实云和干净 Windows 安装升级卸载外部门禁仍单独记录。

模型容量、首载时间、内存峰值和磁盘占用必须以实际 Windows CPU 测量记录，报告CPU型号/核数、内存、系统与应用版本。首批单一模型激活文件上限512MiB、冷加载上限30秒；同一受控场景中，检索宿主进程RSS相对启用检索前基线的增量峰值上限1.5GiB（worker_threads共享进程，不能将进程RSS视为单线程RSS）。不得阻塞应用首屏，超时或超预算终止Worker并回退关键词。上述均为验收目标，不是已经达到的数字，也不新增写作功能硬件最低要求。未达标先优化工作调度与缓存，不静默降低质量门槛或改用云嵌入。

## 9 实施顺序与学习记录

书面规格审阅通过后编写独立实施计划，按安全网页导入→批次审核持久化→本机模型/索引→知识页和写作接线→可用性修正→全量及包验收推进。网页来源与检索协议先冻结，互不改同文件的核心任务可并行，集成按依赖顺序完成。

同步立项 V2.0、PRD 和技术方案的阶段状态，新增明确验收条目，不把待验模型或代码标为已交付。在“项目全流程开发学习”追加对应教材章节：HTTP/SSRF、正文解析、token/嵌入与相似度、RRF、缓存一致性、Worker/TDD，以及项目源码讲解、截图、跟做和拓展练习。课程更新保留作者已修改的学习正文。
