# 一次性受限网页渲染设计

日期：2026-10-12；更新：2026-10-13。状态：用户已批准规格与实施，源码及专项验证进行中；正式能力开放须满足本文门禁。

## 1 目的与现有边界

让作者在拆书工具中获取依赖 JavaScript 的公开文章，预览后继续现有摘选、AI 讲解和人工审核入库。受限渲染不是日常浏览器，不负责登录、人机验证或整站爬取。

现有无脚本获取保留为默认路径。本规格只改变作者显式选择的渲染路径，取代此前设计中对该路径“绝不执行素材脚本”的限制；默认路径继续禁止脚本。网页线路故障、验证码、跨源依赖仍可能导致失败，不能承诺普遍消除超时。

依据：用户于本日选择“一次性隔离渲染”，同意禁止登录、Cookie、下载、弹窗、WebSocket 和私网访问，失败回退；随后确认具体设计并授权编写本文。

## 2 方案与选定方向

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 复用 Electron，HTTPS 受控获取通道（选定） | 无第二份 Chromium；复用来源冻结和审核 | 网络旁路必须实测；首批同源限制降低兼容性 |
| 独立无头浏览器 | 可独立维护引擎 | 增加部署体积、进程和隔离成本 |
| 普通内嵌浏览器 | 更多站点能显示 | 不满足当前网络与凭据边界 |

Electron 的 HTTPS 协议处理不是系统防火墙。下述组合是待实现、待反例验证的安全设计；任一网络旁路门禁失败，正式功能保持禁用，不用“隔离会话”名称替代证据。

## 3 作者流程与接口

网页地址旁保留“获取并预览”，增加“受限浏览器渲染”。首次及每次操作前显示：访问网址、执行该站点脚本、同源限制、40 秒上限和取消入口；作者点击确认才运行。普通获取失败后可展示该入口，但不能自动启动。

一个客户端同时只运行一个网页获取任务。新任务、切换作品、替换来源或退出时中止旧任务，迟到结果不得替换当前预览。已有审核草稿按现有更换素材确认规则处理，不因获取失败丢失草稿。

在现有 `fetchWebExtraction` 请求中增加可选 `mode`：`static` 或 `restricted-browser`，省略时为 `static`；只允许主应用可信 IPC 调用。取消仍使用 `operationId`。渲染页面没有 preload 和 RainSoul API，不允许发送作品命令。

设置和界面区分“当前构建未通过渲染验收”“可以运行”“正在获取”“已取消”“失败”。未通过门禁时禁用渲染按钮并提供粘贴/本地文件，不展示可点击但必定失败的假能力。

## 4 获取与网络隔离

先由 Node HTTPS 通道获取初始 HTML。只接受 HTTPS/443、无网址凭据的公网域名；每跳解析全部 DNS 结果并验证，固定已验证 IP 建连，TLS 校验原域名，最多三次重定向。初始阶段最多 30 秒，包含 DNS 和解压。

最终网址确定后锁定 origin，建立新的非持久 session 与隐藏 BrowserWindow。启用 sandbox、contextIsolation、webSecurity；关闭 Node、preload、WebView、扩展和 DevTools。加载前后核对该任务 renderer 进程独立于作者界面且不与其他任务共享，无法确认则拒绝运行。权限检查与申请全部拒绝，认证挑战直接取消，拒绝弹窗、外部协议、下载和后续主页面导航。

所有 HTTPS URLLoader 请求由该 session 的 `protocol.handle('https')` 接管。首个文档响应使用已校验的原始 HTML；其他允许请求经 Node 资源代理获取，不调用 Chromium 网络 fetch 或其绕过协议处理选项。

子请求只允许最终 origin 的 GET，包含脚本、CSS、JSON、纯文本及 fetch/XHR；拒绝 POST、带凭据网址、跨源 CDN/接口、iframe、字体、图片、媒体和下载。重定向逐跳检查，子资源始终不能跳出最终 origin。分别检查请求类型、方法、网址和响应 MIME；协议处理的 GlobalRequest 没有 resourceType，不能仅依靠该接口猜测资源类型。

Node 资源代理只发送固定 Accept/编码等必要头，不转发页面 Cookie、Authorization、代理凭据、客户端标识或上传正文。不读取云 Key、作品库和作者资料。每次 DNS 校验后固定 IP，子请求共用取消与总期限。私网、上传、凭据、导航逃逸或网络旁路尝试终止任务；常见图片/字体/媒体等非正文资源拒绝加载但可继续提取，并在预览注明资源限制。任何 script、fetch/XHR 请求被禁止或获取失败均停止并解释不兼容，包括统计类接口；不猜测哪个接口属于正文。CSS失败可继续并注明样式缺失，其他禁止类型按安全失败处理。

在导航前设置该 session 的固定拒绝代理并等待完成：只拒绝 HTTP/CONNECT，禁止 DIRECT、PAC 和系统代理回退，显式移除隐式 loopback 绕过；关闭已有连接后再加载。代理在随机 loopback 端口，仅供阻断兜底，不代理到公网。普通网页无法借此访问其他本机服务。

webRequest 独立拒绝 WebSocket 与禁止类型；HTTP、WS/WSS、FTP、file、RainSoul 应用协议等不能进入网络通道。页面内部不联网的空文档也不得获得应用协议或 IPC 权限。

响应头增加不可由 DOM 移除的限制 CSP：脚本只限同源和必要 inline，禁止 eval；禁止 worker、frame、object、表单提交、媒体/图片/字体；connect 限同源 HTTPS。保留原站 CSP 作为交集，不放宽原限制；过滤 Set-Cookie、Refresh、Link、认证、Report-To、NEL 等可能产生状态或额外请求的头。Node 已解压的响应不得保留压缩编码/原 Content-Length；重算响应长度，规范 HTML 编码并保留经过验证的内容类型与必要安全头。记录初始原字节 hash 后才作编码转换，不因转码改变证据含义。

CSP、权限拒绝和 `disable_non_proxied_udp` 都不能单独证明 WebRTC 隔离。WSS、WebRTC/STUN、QUIC/WebTransport、预连接、DNS 预取、专用/共享/Service Worker 的旁路要在实际 Electron 包中验证；发现未能阻断的机制先关闭功能并解决，不降级为直连。

CSP可能在网络拦截前拒绝请求，因此不能以“broker没看到失败”判定完整。加载前建立宿主监管与隔离世界的受限错误观察，核对 CSP violation、脚本加载/执行错误、fetch/XHR失败和导航拒绝；向主进程仅回传有界失败类型，不开放应用API。实际包必须覆盖在webRequest之前被CSP拒绝的跨源script/connect路径。观察建立失败、无法验证完整性或页面篡改导致无法可靠核对时拒绝本次结果，不把网页自行声明成功当证据。

## 5 限额、提取与清理

| 项目 | 首批上限 |
| --- | --- |
| 总期限 | 40 秒，初始获取最多 30 秒；所有请求和提取共用期限 |
| 请求/并发 | 最多 80 次，最多 4 个并发；排队也计入总期限 |
| 单响应 | 压缩前 2 MiB、解压后 5 MiB，流式校验 |
| 全任务响应 | 压缩前 12 MiB、解压后 24 MiB，包含初始文档与重定向正文 |
| DOM | 节点与属性合计最多 20,000，序列化 UTF-8 最多 5 MiB |
| 正文 | 现有 200,000 Unicode 字符、2,000 非空段落 |

文档加载后，允许已开始的脚本完成；等待允许请求安静 500ms，最多额外等待 5 秒且不得超过总期限，再截取 DOM。不自动滚动、翻页或点击“加载更多”；仅捕获这一页当次可得到的文章。初始文档中外链资源被阻断时解释兼容边界，不悄悄放宽同源规则。

DOM 是不可信输入，先有界遍历计数和累计字节，再构建有限序列化结果，禁止先生成任意大 outerHTML 再检查；结果交给现有有界 Readability worker，只作为文本预览，网页 DOM 不加载到主应用。未找到文章、验证码/登录页或超限时不入库，不自动重试。为防死循环，生命周期监管必须运行在不受页面 JavaScript 阻塞的主进程，期限后销毁对应 webContents并核对退出；必要时安全终止已确认独立且仍属于该任务的 renderer，绝不终止作者界面或仅按旧PID杀进程。记录渲染进程退出/崩溃结果。

成功、取消、超限、解析失败、崩溃及应用关闭均走统一 finally：中止全部 Node 请求和队列、销毁窗口、关闭 session 连接、清除临时数据、取消协议处理并关闭拒绝代理。先关闭网络连接再撤销阻断规则，禁止留下后台页面。清理失败不能继续接受下个任务。

## 6 来源证据与兼容

保留原始 HTML 的 `rawHash`，现有 `bodyHash` 仍按冻结段落数组计算；增加受限捕获记录：`captureMethod='restricted-browser'`、`capturedAt`、`renderedDomHash`、`policyVersion=1`。渲染 DOM 哈希不是服务器原文哈希；界面显示“受限渲染捕获，可能与完整网页不同”。普通网页明确记为 `static`，旧网页捕获方式未知，不能伪造历史时间或方式。

受限捕获记录采用独立、白名单验证的来源元信息关系，以来源 ID 为键；作品库从 v7 前向迁移到 v8，备份和失败回滚沿用当前规范。新快照 payload3 携带新关系，旧 payload1/2 继续先验证原哈希再内存补空关系；归档支持旧 v4～v7 和新 v8，不能修改历史原始字节/hash。

冻结来源、草稿恢复、知识复制、快照/历史导出和归档往返都必须保留该证据。升级前完成的普通来源和旧知识不变。未审核预览不生成知识；作者审核入库仍使用原 operationId/CAS 事务，不把网页捕获和云授权混为一次确认。

## 7 实现边界

- `restricted-web-renderer.ts`：窗口/session 生命周期、安静等待、有界提取与清理。
- `render-resource-broker.ts`：同源 GET、DNS 固定 IP、响应头/MIME 和共享限额。
- `render-network-guard.ts`：拒绝代理、请求/权限/协议拦截与旁路监测。
- `restricted-render-policy.ts`：固定政策、能力门禁与限额；不能由网页改变。
- 现有网页命令、shared/preload、拆书组件：显式模式、取消和失败回退。
- 来源 schema/codec、迁移、归档和复制：新增捕获证据；无关数据库接口不重构。

## 8 验收与发布规则

核心逻辑先写失败测试。静态路径回归必须继续通过。动态夹具验证 inline、同源 script/fetch/XHR 注入文章，结果与真实渲染一致；不以 mock 窗口证明 JavaScript 实际执行。

最终 EXE 中验证 DNS 重绑定、私网/环回/IPv6、跨源跳转、WSS、WebRTC/STUN、QUIC/WebTransport、preconnect/dns-prefetch/prefetch、所有 worker、iframe/srcdoc、blob/data、弹窗、下载和认证挑战。使用受控监听目标与系统网络观察，证明禁止目标零连接/零上传；代理关闭时不得改用直连。记录包 hash、Electron 版本、系统、测试输入和实际网络证据，不能仅断言页面报错。

验证 Cookie/Key/作品信息不继承，超限、取消、死循环、崩溃后窗口和连接全部结束；坏 MIME、压缩炸弹、伪长度、坏编码、来源过期、草稿恢复及 v7→v8/旧快照/归档/复制完整往返。

完整单元/集成、桌面和 Demo 测试、覆盖率、类型、Lint、生产构建、独立安全/代码审查通过后小步中文提交。真实公开网页至少一个静态站和一个确需同源 JS 的站点成功预览；失败如实记录，不冒充审核入库或云质量。未完成的真实云和干净 Windows 矩阵继续单独 pending。

功能启用依据固定构建的受限渲染资格记录；只有反例、清理、真实包证据全部通过才允许正式按钮运行。能力检测失败时默认关闭，不留生产绕过开关。
