# RainSoul 全应用交互动效设计

日期：2026-10-15。状态：用户已确认推荐方向并要求整理书面规格；本文待审阅，尚未实施。

## 1 目标与边界

让点击获得及时反馈，让页面、菜单、弹窗、侧栏和卡片的出现、变化与消失具有连续感。保留已经确认的白色界面、天蓝色强调色与 Demo 标志，不增加一套视觉主题。

“所有操作”落实为应用内每类可操作控件都有反馈，而不是每次点击都切换整页。正文输入和光标移动保持稳定；保存、停止生成、取消网络请求与窗口关闭不等待动画才能执行。

系统文件选择器、安装器和 Windows 窗口动画由系统控制；本方案覆盖其应用内触发按钮、等待状态及返回后的反馈。

本轮遵循用户“不进行测试”的要求，不运行自动化、功能、视觉或性能测试。不把代码审阅、构建成功或动画存在写成体验已验收；后续由用户实际查看效果。

## 2 现状与根因

现有版本为 React 19.3、TypeScript、Electron 44、Radix Select。尚未引入 Motion。

- `src/renderer/styles.css` 已为分卷、章节栏和部分图标提供双向 CSS 过渡。
- `App.tsx` 的页面、`context-menu.tsx` 的菜单和多个知识工作区子面板在状态改变时立即卸载，退出动画没有可承载的 DOM。
- 原生 `<dialog>` 在关闭或卸载时立即 `close()`，只补入场 CSS 无法解决退出问题。
- Select 仅有箭头旋转，没有展开和收起的统一内容动效。
- 全局减少动态效果规则只关闭 `transition`，没有完整覆盖关键帧、伪元素和脚本动画。

## 3 方案比较与选定

| 方案 | 用途与代价 | 结论 |
| --- | --- | --- |
| CSS 令牌 + 按需 Motion + 原生页面过渡 | CSS 负责轻反馈；Motion 处理保留退出节点、卡片重排；原生视图快照承载页面转换，需要统一协调 | 采用，避免每个组件分别维护卸载计时器 |
| CSS + 自建 WAAPI 生命周期 | 无额外动画依赖，但要自行处理取消、重入、嵌套、焦点和退出完成 | 不作为全应用主方案 |
| 所有场景都使用 View Transitions | 页面转换方便，但不能替代菜单、模态和业务生命周期 | 仅用于页面转换增强 |

引入 `motion` 的 React 入口，使用 `LazyMotion` 和按需功能；不同时加入 GSAP、Anime.js 或另一套弹窗系统。不采用 React 实验性 ViewTransition 组件。

## 4 统一动效语言

| 场景 | 动效 | 时间 |
| --- | --- | --- |
| 按钮、图标、标签 | 按下轻微位移或缩放，释放复位；键盘操作也显示激活反馈 | 按下 80–100ms，释放 140–160ms |
| 下拉、右键与更多菜单 | 从触发方向淡入，4px 位移；关闭反向收敛 | 进入 160ms，退出 140ms |
| 模态及遮罩 | 遮罩淡入；内容从 y=8px、scale=.98 收敛 | 进入 220ms，退出 160ms |
| 主侧栏、章节栏、会话列表、知识分类 | 桌面宽度与内容透明度连续变化；窄屏抽屉平移并出现遮罩 | 180–220ms |
| 分卷、剧情树、卡片全文 | 高度展开/收起，箭头同步旋转；避免从两行摘要直接跳成整块全文 | 180–220ms |
| 页面与分页 | 短距离淡入淡出；正文编辑区域不缩放 | 180ms |
| 新建、删除与排序 | 提交成功后条目出现/退出，邻项平滑补位；排序后保持当前定位 | 160–220ms |
| 提示、错误、生成状态 | 原位状态淡入，尺寸平滑变化；生成过程使用克制的活动指示 | 140–180ms |

常规进入曲线为 `cubic-bezier(.16,1,.3,1)`，退出为 `cubic-bezier(.4,0,1,1)`。轻微弹性只用于导航选中指示器和图标反馈。长文、设置表单与删除过程使用收敛曲线。

导航采用连续移动的选中指示器；菜单的展开中心对应触发点；新建和删除通过邻项补位解释内容去向。这些效果共同表达空间关系，不增加与操作无关的装饰运动。

## 5 组件与生命周期

建立统一动效令牌文件和共享动效组件目录，集中维护时长、缓动、减少动态效果及保留退出节点的行为。各业务组件传入状态与回调，不自行复制 `setTimeout`。

### 5.1 模态

统一状态为“关闭 → 进入中 → 已打开 → 退出中 → 关闭”。保持原生 `<dialog>` 的 top layer、焦点约束和 Esc 行为。通过退出完成回调关闭底层 dialog，再卸载；退出中禁止重复提交。

保持遮罩和模态语义至退出完成。提交失败时保留原表单和错误内容，不能先播放成功退出再显示失败。退出时再次打开，应取消旧退出，旧回调不能关闭新实例。关闭后向有效触发器还焦点，触发器已删除时转向所属列表的稳定入口。

工具弹窗关闭后需要保留的 AI 候选、正文选择和工具状态继续由业务状态拥有，不能因视觉卸载被清空。涉及嵌套 Select 时，Esc 先关闭内层；Portal 继续落入最近 dialog，避免被 top layer 遮挡。

### 5.2 菜单、侧栏与卡片

Radix Select 使用官方 `data-state` 关键帧机制，由 Radix 等待退出完成再卸载。右键和更多菜单采用共享 presence；选择操作立即执行，退出壳不再接收点击，也不再拥有可访问性焦点。

折叠内容在不可见时使用 `inert` 和恰当的 `aria-hidden`，先将内部焦点移回展开按钮。卡片摘要与全文由同一个条目承载；列表重排仅动画条目布局，避免对整页或编辑器树启用昂贵的布局测量。

### 5.3 页面

对已经通过保存保护的页面转换，使用平台 `document.startViewTransition`：以旧页面快照表达退出，随后提交 React 页面状态，展示新页面。实际业务组件只挂载一份，避免两个编辑器并存、重复请求和脏状态回调。

能力检测失败、API 调用失败或正在处理中文输入法组合时，使用轻量入场/即时转换回退；页面切换本身不能失败。快速连续导航结束上一次视觉过渡，最终页面必须对应最后一次有效导航。不要为了等待动画保留网络请求或解除既有保存保护。

## 6 可访问性与执行约束

- 监听 `prefers-reduced-motion` 及其运行时变化，统一覆盖 CSS、Motion、页面快照和伪元素；关闭位移、缩放、弹簧和循环运动，可保留短促透明度反馈。
- 减少动态效果、后台节流或组件卸载时都必须能完成关闭；不能只依靠可能不触发的 `animationend`。
- 按钮 busy、错误和生成状态必须有可读文字，动画不能成为唯一反馈。不可操作的按钮不播放暗示成功的效果。
- 保存、停止、取消和退出命令在事件发生时立即进入业务流程，动画只是其反馈；应用关闭不能因某个动效回调丢失而永久挂起。
- 不在主进程运行 UI 动画，不为动效增加全局业务锁，不对每次正文输入执行列表布局动画。
- 运行时失败降级为无动画操作，保持焦点、数据和错误提示正确。
