## 随开发学习卡

### 保存回执与幂等

问题：SQLite 可能已提交而前端没有收到回执。直接用新草稿和旧版本重试会永久冲突。

实现联系：编辑草稿 → SaveCoordinator → preload → StoreService → 数据库 Worker → `operation_log`。同一操作冻结正文和 expectedRevision；未知提交状态先重取原操作回执，再写最新草稿。前端校验失败尚未发请求，用 SaveValidationError 区分。

练习与证据：阅读 `tests/unit/save-coordinator.test.ts` 的“回执丢失”与“校验失败”用例，再对照仓储的重复请求/版本冲突用例。明确确认的是数据库提交，不能把界面计时结束当成保存成功。

### 关闭与页面切换

问题：flush 后如果仍可输入，切换或关闭会丢掉随后出现的新草稿。

实现联系：App 同步操作锁 → 等待当前页面操作 → useWritingSession flush → preload 携关闭 token 确认 → 主进程等待存储队列 → 关闭窗口。输入法组词期间拒绝关闭，失败解除锁且留稿；Ctrl+R/F5 等入口禁用。

练习与证据：组件测试人为延迟 save、listWorks 和 addChapter，检查锁定与失败解锁；桌面测试不等待自动保存便正常关闭，然后重启检查正文。

### 原生数据库与打包

问题：开发用 Node 能加载数据库驱动，不能推断 Electron 或包内程序也能加载。

本次判断：锁定驱动版本的 Node-API 预编译文件可供 Node 与 Electron 共用；保留 Worker 单写者，在目录包从真实入口再次执行建库和重启。技术方案记录了具体版本及实测结果，不对将来驱动版本套用相同假设。

Compound Engineering：上述推理已写入开发记录和技术方案，按耐久性门槛不重复写知识库；Claude Mem 不可用，不写 gbrain。完成作品集后再按用户要求整理为普通“学习路径”作品。
