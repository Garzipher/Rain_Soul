# 作品与卷章管理执行记录

来源：已统一立项 V2.0、Demo、PRD FR-01/02/08/17 与技术方案。沿用既有 Electron/React/SQLite 工程，不增加产品范围。

## 本批交付目标

- 创建可选分卷，卷章改名、同级上下排序；章节可移到指定卷或无卷。
- 作品、卷、章节右键与键盘菜单；确认前关闭菜单，取消不写入。
- 作品和卷章软删除，可在设置的本机数据区发现并恢复，不自动永久清理。
- 删除卷将本次仍存在的子章一起保留；恢复卷只恢复同批子章，之前单独删除的章节仍待作者恢复。单章恢复时若原卷仍被删除，恢复到无卷位置，稳定 ID 与正文不变。
- 管理操作通过最新草稿保存门禁、版本条件与操作去重。保存失败保留草稿；结构或新增章回执未知时保留原请求，暂停编辑、离开和关闭，作者手动重取回执后继续。
- v1 作品库迁移前保存一致备份，事务内升级到 v2 并检查，失败回滚并阻止启动。目录库继续使用可重建缓存。

## 学习卡：结构管理与保存如何对接

界面操作依次经过 `App → preload → StoreService → Database Worker → WorkRepository`。预加载层只提供明确命令，服务层校验输入与当前作品权限，Worker 串行处理本地存储，仓储在事务内核对版本及操作指纹。名称可以重复，引用与恢复始终使用稳定 ID。

| 设计理由 | 实现与验证 |
| --- | --- |
| 请求失败不等于数据库没提交；改用新请求重试可能重复新增 | 保留 operationId、expectedRevision 和完整参数；作者重试同一请求取回回执。卷、章、作品删除的丢回执测试使用真实 SQLite |
| 结构操作也改变作品版本；只更新章节列表会让后续保存永远版本冲突 | `acceptWork` 同步 revision 与卷归属，正文回执保留章节结构字段；移卷后继续编辑有回归 |
| 删除整卷前已单独删除的章，不属于这次整卷恢复 | deletion_batch 区分删除来源；卷恢复只恢复同批子章，单章恢复检查原卷有效性 |
| WAL 模式下直接复制主库可能漏掉已提交正文 | 迁移用 VACUUM INTO 一致镜像；夹具关闭自动检查点，单独打开备份核对原稿 |

迁移、回执和恢复的知识已记录在此学习卡、技术方案及测试中；Compound Engineering 不再向全局知识库写入重复条目。待知识卡、伏笔与大纲功能可用后，按已确认要求统一汇入名为“学习路径”的作品。

## 打包故障记录

本机 electron-builder 在刚重命名的 RainSoul.exe 写 ASAR 完整性资源时出现 `UNKNOWN/open`，独立 E 盘/C 盘输出均可复现，稍后文件可正常写入。限定 Windows 和该错误码/调用的重试原函数后实际构建成功。新增打包入口核对锁定工具版本，最多 5 次、间隔 1500ms，其他错误原样抛出；不修改 node_modules、不禁用完整性校验。8 项回归先失败再通过；新的 `npm run pack` 整体退出码 0。
