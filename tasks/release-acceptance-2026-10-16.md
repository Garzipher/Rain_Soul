## 环境问题与后续处理

Electron safeStorage 密文除 Windows 用户身份外，还与 Electron profile 的 Local State 有关；复制 `ai-settings.json` 到另一 profile 不能证明凭据可用。本轮先保留原密文，再通过隔离辅助进程在内存中解密并使用日常 profile 重新加密；保留服务配置，未覆盖日常 Local State，未创建明文密钥文件。原密文备份留在本机应用数据目录，不进入仓库或发布包。

压缩安装器和覆盖率并行时资源竞争会放大复杂组件测试耗时，因此正式回归与压缩分开执行。分页测试保留全部断言和原超时，仅将已标注标签的表单查询改为按标签定位，减少对整页重复计算可访问名称。

首轮桌面套件还发现旧测试对 Radix `role=combobox` 调用原生 `selectOption`，以及默认仍进入作品库、会话仍寻找二次发送确认的过期操作。修复限于测试定位与交互步骤，不修改业务源码、不放宽性能门槛，旧失败材料保留。

本轮提交前对当前 Git 跟踪且不超过 5MB 的 1178 个文件检查 OpenRouter Key 文本特征，命中数为 0；未发现被跟踪的云配置、Local State、数据库和常见环境凭据路径。证据为 `v136/tracked-secret-scan.json`；这是限定规则检查，不等于全面秘密审计。
