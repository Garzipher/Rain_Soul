# 第三章 删除后怎样恢复原来的内容

本章状态：作品、卷、章节软删除与设置页恢复已实现；永久清理、手动快照和归档恢复尚未实现。

学习目标：区分“从当前列表隐藏”与“物理删除”，理解恢复整卷为什么必须追踪同一批删除的章节。

读取 `src/workers/database/project-schema.ts`。`deleted_at` 表示删除状态，`deletion_batch` 表示这次操作的删除批次；正文与稳定ID继续保留。

再读 `src/workers/database/structure.ts` 的 `deleteVolume`、`restoreVolume`、`restoreChapter`。删卷只给当前未删除子章设置本批ID，恢复卷只恢复属于该批的子章。

例子：第一卷有A和B。作者先单独删A，再删整卷；恢复整卷应恢复B而继续保留A的删除状态。否则整卷恢复会擅自撤销作者之前的独立决定。

实践步骤：

1. 在测试库执行上面的顺序，记录两章的deletion_batch。
2. 恢复卷后确认B出现、A仍在恢复列表。
3. 再删卷，单独恢复A，检查它被放到无卷区，避免挂在不可见父卷下。
4. 重启应用，验证删除和恢复状态来自数据库，不只是React内存。

整作品删除只标记work_meta，作品集不再展示，但设置页仍可发现。操作和回执仍使用作品ID，同名作品不会互相影响。

界面入口在 `src/renderer/components/recovery-panel.tsx`。读取已删除作品与所选作品的卷章，错误时提供重新读取；恢复调用通过正常StoreService权限与版本检查。

```text
删除确认 → 保存门禁 → 事务软删除 → 从当前列表隐藏
设置恢复 → 校验ID/状态/版本 → 清除对应删除标记 → 重新加载
```

确认框取消不产生删除事务。打开确认框前关闭右键菜单，避免用户看到悬浮的“删除作品”文字还叠在弹窗附近；键盘焦点优先放在取消按钮。

证据入口：`tests/unit/repository-structure.test.ts` 覆盖同批恢复与单章降级到无卷；`tests/unit/renderer-structure.test.tsx` 覆盖取消、失败和焦点；`tests/desktop/structure.spec.cjs` 验证同名作品与重启。

练习：建立“先删章A→删卷→恢复卷→恢复A”的状态表，列出每步A、B、卷的可见性与ID。再写一个回归断言，证明恢复不生成新章ID。

边界：软删除不等于快照。修改过的正文不能通过删除恢复回到旧内容；历史版本恢复与 `.rainsoul` 归档需单独实现并验收。
