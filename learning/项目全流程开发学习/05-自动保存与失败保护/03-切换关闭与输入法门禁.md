## 2. 门禁是什么意思

门禁给切换或关闭动作增加前置条件。
成功流程是“输入结束→flush→收到回执→离开”。
失败流程是“保留草稿→解释问题→留在原处”。
先关窗口再await保存，回调可能还没完成进程就退出了。
只等待500ms也不够，因为请求可能发出后还在排队。

| 动作 | 需要等待 | 失败结果 |
| --- | --- | --- |
| 切换章节 | 当前正文flush | 留在当前章 |
| 改卷章结构 | 当前草稿与在途操作 | 不执行新结构修改 |
| 关闭窗口 | IME结束、结构操作、正文flush | 保持窗口存在 |

## 3. IME组词阶段为何特殊

中文输入经历compositionstart和compositionend。
候选词或拼音显示在屏幕上时，未必已经成为正式正文。
关键操作若此时读取文档，可能得到组词前的版本。
因此源码在组词期间拒绝flush并给出可操作提示。

```typescript
const flush = useCallback(async () => {
  if (composing.current) {
    throw new Error('输入法正在组词，请先确认输入后再操作');
  }
  await coordinator.current?.flush();
}, []);
```

作者确认候选词后，就可以再次切章或关闭。
这里不需要禁止日常输入，只需保护需要一致正文的操作。

## 5. 主进程如何阻止直接关闭

主进程的allowClose默认false。
第一次close事件到达时，event.preventDefault保留窗口。
它生成新的随机token并通知渲染进程准备关闭。

```typescript
window.on('close', event => {
  if (allowClose) return;
  event.preventDefault();
  closeToken = randomUUID();
  window?.webContents.send('rainsoul:close-request', closeToken);
});
```

token把确认与某一轮关闭请求绑定。
旧请求的迟到确认不能授权新一轮关闭。
主进程还检查事件发送者是可信窗口的主frame。
来源不明的页面不能冒充“草稿已保存”。

## 6. 渲染进程需要等什么

在use-writing-session.ts找到onCloseRequested。
它检查composing，然后设置closing锁。
接着等待operations.beforeClose和协调器flush。
前者处理结构操作收尾，后者处理正文草稿。
若失败，catch释放closing状态，作者仍能继续处理内容。

```text
操作系统请求关闭
→ 主进程保留窗口并发送token
→ 渲染进程确认输入已结束
→ 等待结构操作和正文flush
→ 预加载层发送同token确认
→ 主进程drain存储队列
→ allowClose=true，再次关闭
```

StoreService.drain等待已进入主进程队列的请求。
它不能代替渲染进程flush。
尚未发送的dirty正文根本不在那个队列里。

## 7. 为什么需要closingRef

setClosing(true)之后，当前旧闭包还可能持有false。
如果立即发生下一次编辑事件，光看state可能仍允许输入。
closingRef.current=true能立刻阻止update入口产生新草稿。
否则保存已完成后又增加输入，关闭保证就失效了。

不是每个状态都应改成ref。
界面需要state触发重渲染；关键门禁需要即时ref。
两者在源码中共同使用，是为了服务不同读取时机。

## 9. 故障诊断

| 现象 | 源码入口 | 可能原因 |
| --- | --- | --- |
| 组词期间能切章 | composition事件连接 | composing未及时置true |
| 关闭卡住无提示 | onCloseRequested错误传播 | 异常未回到界面 |
| 保存失败后不能再编辑 | catch释放closingRef | 失败锁未释放 |
| 重开少了最后一句 | flush与关闭顺序 | 进程提前退出 |

输入法提示需要先确认候选词。
磁盘问题需要处理空间或权限，再手动重试。
移除门禁虽然让窗口能关掉，却会重新引入丢稿风险。

## 10. 练习与答案提示

练习一：主进程drain为什么不能保证未发送草稿已保存？
答案：它只知道已排队请求，不知道渲染进程的dirty内容。

练习二：为什么每轮关闭重新生成token？
提示：隔离不同轮次，拒绝迟到确认。

练习三：怎样验收“最后一句后立即关闭”？
答案要点：隔离测试目录、真实正常关闭、同目录重开、核对完整正文。

## 延伸实验：错误后的可恢复性

在隔离测试中让保存函数拒绝一次，观察关闭是否被阻止。
恢复模拟存储后，由作者手动重试，再正常关闭。
需要同时断言窗口继续存在、原文没变、输入锁已释放和最终可以关闭。
只验证关闭失败不够，因为一个永远锁死的界面同样会通过那条断言。
