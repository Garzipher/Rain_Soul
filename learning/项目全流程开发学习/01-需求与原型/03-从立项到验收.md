# 第三章 把需求接到 PRD、技术方案和测试

本章状态：立项、PRD、技术方案已建立；完整 P0 尚未完成。学习目标是让每项实现能回答“为什么做、怎么做、怎样证明”。

三个文件承担不同责任：立项规定范围和数据规则，Demo规定交互外观；PRD把它们变成页面规则、功能编号和验收；技术方案说明进程、表、协议、实验和实施批次。后两份是派生文档，不能偷偷降低首版范围。技术建议也不能自动成为已完成能力。

例如 FR-08 是自动保存。需求要求输入停顿 500ms 自动保存，持续输入最多 5 秒落盘，失败保留内容并阻止离开。实现涉及保存协调器、主进程队列和数据库事务。证明则包含假时钟测试、迟到回执测试、真实 SQLite 与正常关闭重启。只有某一层测试通过，还不能证明整个动作满足要求。

实际开发按小批次推进：第一批建立桌面基础和离线写作；第二批增加分卷、排序、移卷、软删除恢复和 v1→v2 迁移。这些属于 P0 的部分实现，不是把首版重新缩成只有编辑器。后续 B2～B6 仍需实现知识/剧情/伏笔、数据保护、云端修改和完整验收。

实践步骤：

1. 选一个 PRD 编号，例如 FR-02 卷章正文。
2. 找触发入口：作品集打开作品，卷章树选择章节。
3. 找数据契约：`WorkDetail`、`Chapter`、`WritingDocument`。
4. 找实现与测试：编辑组件、保存 Hook、仓储、对应单元与桌面测试。
5. 记录未覆盖部分，例如长篇载入或系统断电，不用一项通过代替所有门槛。

示例验收矩阵可写为“FR-02 / 无卷章写作 / `renderer.test.tsx`、`writing.spec.cjs` / 正常关闭重启已验证 / 千段落性能待验证”。它把证据与限制放在同一行，比单独写“已完成编辑器”更准确。
