# 第二章 沿完整P0继续而非停在编辑器

本章状态：本章是后续开发路线；剧情、伏笔、知识、搜索、快照、归档与正式导入导出尚未因本书存在而完成。

学习目标：把大目标拆成可以验证的本地业务闭环，理解每个功能如何接入现有稳定ID、作品隔离和保存门禁。

正式依据是 `docs/Rain_Soul_项目立项方案_V2.0.md`、`docs/Rain_Soul_PRD.md` 和 `docs/Rain_Soul_技术方案.md`。Demo是交互参考，内存样例和下载提示不能代替持久化与文件格式验收。

下一步本地模型包括剧情节点树、伏笔及章节/段落证据、作品私有知识、层级分类和标签。它们都要通过preload明确命令、StoreService授权、Worker事务和版本迁移接入。

例子：一个伏笔关联正文段落。正文被拆分后，段落稳定ID能帮助定位；若证据失效，界面应提示重新关联，不能悄悄定位到另一段相同文字。

实践步骤：

1. 阅读PRD的FR-03/04，列出节点、关联、删除和证据规则。
2. 给新模型画数据关系，注明哪些对象按作品隔离。
3. 先写真实SQLite失败测试，再实现事务与schema迁移。
4. 接入组件后验证键盘、空态、错误态和保存失败门禁。

知识库保存优秀描写与写法，供作者学习仿写和AI参考。默认分类包括人物描写、景物描写、内心描写、经典引用等；条目展示摘要和出处，点击原位展开，不能把它误做只有角色设定的数据库。

搜索首版走关键词全文检索，正文与知识结果标注来源，标签按AND筛选，中文短词需要实际命中测试。P95≤1秒必须有明确数据与测量环境，不能以一条小数据查询代替性能验收。

```text
本地模型与迁移 → 仓储测试 → 明确IPC
→ 真实UI操作 → 保存/删除/恢复回归 → 性能与桌面验收
```

版本与文件模块需要另一条闭环：整作品手动快照、恢复为新版本、`.rainsoul`归档校验后导入新项目、TXT/DOCX导入预览与导出。每条都要保护当前数据，失败不能覆盖原作品。

引用导出复用首次出现编号，文末列清单；伏笔保留名称标记与证据清单。受限文档增加书签节点时，验证器、字数、编辑渲染、快照和导出必须一起更新。

证据入口：当前可查看PRD验收追踪和技术方案批次；未来实现后再补对应源码与测试。本章不把设计文字当运行证据。

练习：选一个知识条目的删除操作，列出正文占位、搜索、快照、导出和全局汇总分别应如何变化，再把它拆成独立测试。

阶段边界：需求会话、拆文/URL工具、XMind、跨作品分析与向量检索仍后置；P0内部先做本地闭环不意味着可以漏掉已确认的AI主流程。
