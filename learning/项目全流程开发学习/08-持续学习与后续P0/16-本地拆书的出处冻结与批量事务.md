# 本地拆书的出处冻结与批量事务

你读到一篇作品中的雨景写法，想把两段文字收进“景物描写”，再加上“雨夜”和“车站”标签。下次写类似场景，自己可以复习手法，AI也能在你选择参考资料时查到这张知识卡。本章实现的是本地 TXT/DOCX 解析、逐段摘选和作者审核，不把整本书自动上传给模型。

2026-10-09 的首批 P1 实现复用现有手稿解析与作品知识事务。URL下载、自动AI拆文、XMind和向量检索不在这条流程。实际功能状态与测试结果以当轮交付记录为准，下图来自本轮真实Electron中的合成练习材料。

## 1. 先分清解析、摘选、加工与出处

解析把文件转换为章和段落，尽量保留可识别正文。摘选是作者选择哪些段落值得学习。加工是作者删减、记录写法或整理知识卡内容。出处回答材料从哪里来：作品名、作者、文件名、章段位置和原始内容指纹。

这四件事不能合并成“复制一段字符串”。例如知识卡改成“雨景用短句加密节奏”，它已经不是原文摘录；出处仍指向被参考的原始段落，不能声称改后的内容是作者原句。

SHA-256 把一段字节计算为64位十六进制指纹。它便于确认后续比较的是不是同一份材料，不能证明版权许可、书名和作者的真实性，也不能把整理后的卡片变成原文。

| 数据 | 谁提供或生成 | 能证明什么 |
| --- | --- | --- |
| sourceTitle/sourceAuthor | 作者审核填写 | 作者声明的作品出处，需自行核实 |
| filename/fileHash | 主进程从实际文件生成 | 本次读取的文件名称和字节指纹 |
| chapterIndex/paragraphIndex/text | 解析器输出后冻结 | 本次解析得到的章段定位与原段落 |
| 段落hash | 主进程对冻结原文生成 | 原段落文字指纹，不随知识正文编辑改变 |
| body/categoryId/tagIds | 作者逐段审核 | 将要入库的整理内容、主分类和标签 |

## 2. 系统边界决定数据从哪里取得

React没有任意读磁盘权限。点击选择文件后，预加载桥调用主进程原生对话框，由主进程读取批准文件。渲染层得到预览段落和token，不负责提供文件路径、原始字节或出处hash。

```text
知识库“拆书工具” → BookExtractionWorkspace
→ chooseBookExtraction(workId, encoding)
→ 主进程原生选文件 → 已有限额的文件读取器
→ TXT/DOCX解析 → 章段预览 → 主进程冻结fileHash/segments/token
→ 作者编辑body、主分类、标签、书名/作者，逐段勾选审核
→ confirmBookExtraction(token, workId, expectedRevision, operationId, items)
→ 主进程用segmentId查冻结段落，构造source
→ StoreService确认当前作品 → 仓储整批事务 → 返回最新知识库
```

`src/shared/book-extraction.ts` 使用严格Zod协议。确认请求只带段落身份和审核内容，不能传任意source。`permissionConfirmed: true`记录作者确认有权使用材料；它不是程序自动核实授权。每次最多100条，单条知识正文最多20000字符，避免一次审核过大。

## 3. 阅读文件解析的实际实现

`src/main/book-extraction-commands.ts` 的 `chooseBookExtraction` 复用 `parseTxtManuscript` 和 `parseDocxManuscript`，将章段平铺成带稳定临时身份的segments。TXT支持显式UTF-8或GB18030；编码不对时应回到选择阶段改编码，不把乱码写进知识库。

DOCX是ZIP包装的XML。已有解析器限制归档大小和XML结构，只提取可支持的标题、正文及换行，图片、表格等未支持内容给出预览警告。普通文档导入的章识别规则因此也适用于拆书；无法识别的文件不会凭空获得真实章节编号，章段位置表示本次解析结果。

```typescript
// BookExtractionCommands构造预览时的关键字段
fileHash: createHash('sha256').update(file.bytes).digest('hex')

// 作者确认后，段落指纹来自冻结段落而非修改后的body
createHash('sha256').update(segment.text).digest('hex')
```

选择文件后再修改磁盘原文件，已经打开的预览仍对应旧字节指纹。重新选择才会获得新token和新指纹；旧预览不能和新文件混用。

## 4. 为什么body可编辑，而source不能自由伪造

`confirmBookExtraction` 先校验token和workId，再按segmentId寻找冻结段落。如果该段落不在预览中，立即拒绝。主进程将作者确认的书名/作者与真实文件名、章段位置、fileHash、段落hash组合为source。

卡片body可以是摘录、删减后的片段、写法分析或仿写练习；修改body不能改变冻结原段落的指纹。当前source保存文本出处及哈希，没有把整份原书打包进作品，也不能凭哈希还原原段落。需要完整原文复查时，作者应保留获准使用的原文件，并对照文件与段落指纹。

与正文AI回写一样，出处材料不能自动变成提示指令。后续AI参考采用当前作品关键词检索和作者选择，卡片进预览后再授权发送。收进知识库不意味着模型自动获得整本源书，也不意味着每次云操作都授权发送所有卡片。

## 5. 批量入库为什么只提交一次

`src/workers/database/book-extraction.ts` 的 `importBookExtraction` 使用 IMMEDIATE 事务。先检查作品还存在、expectedRevision是否一致和operationId是否已处理，再创建入库前安全快照。

```typescript
db.transaction(() => {
  // 先校验作品、回执和当前版本
  createSnapshot(db, '拆书入库前安全快照', 'safety');
  for (const item of request.items) {
    applyAsset(db, { type: 'createKnowledge', ...item }, meta.revision + 1);
  }
  // 同事务更新作品修订，并记录请求哈希与回执
}).immediate();
```

这是源码节选，完整函数还包含校验与SQL。`applyAsset`复用现有分类/标签和搜索索引逻辑，不能把其他作品的标签ID当作当前标签。如果第二条分类无效，第一条知识、安全快照、作品版本和回执一起回滚，原知识库不变。

同operationId同输入重试不再创建知识；同ID不同内容明确拒绝。成功后每条知识获得新ID，不覆盖既有条目。返回最新 `WorkDetail` 让界面同步知识和作品修订，搜索命中新卡应走正常的作品索引。

## 6. 可以照着做的本地练习

先自己新建UTF-8文件 `练习材料.txt`，内容如下。这是合成教学材料，可以放心用于测试，不需要从真实作品取未授权文字。

```text
第一章 雨夜
雨水沿站台边缘落下，像一排迟迟未停的钟声。

他握紧那把旧钥匙，指节抵着口袋的缝线。
```

1. 新建隔离测试作品，打开知识库顶部“拆书工具”，选择TXT和UTF-8编码。
2. 检查章名、两段内容和解析警告。书名填“练习材料”，作者填“本地练习”，明确确认材料使用权限。
3. 第一段主分类选“景物描写”，勾选当前作品标签；第二段选“人物描写”。若需要标签，先在知识库维护，不输入他作品的标签ID。
4. 将第一条body追加“学习点：用声音比喻延长等待感”，然后逐条勾选审核。注意卡片正文已是加工材料，原段落hash仍对应原句。
5. 点击确认入库。知识库增加两条新卡，右下角出处含文件与章段信息；搜索“钟声”应命中新卡。
6. 导出项目归档后导入新作品。卡片与出处仍在，两个作品编辑互不影响；原TXT不因拆书被改写。

这是手动练习步骤，不表示已经在所有Windows系统执行。自动验收见 `book-extraction-commands.test.ts`、`book-extraction-database.test.ts` 和界面回归用例。

## 7. 失败实验：观察库何时会变化

| 实验 | 执行办法 | 应当观察到 |
| --- | --- | --- |
| 取消文件选择 | 在原生对话框取消 | 没有新增知识 |
| 取消摘选 | 选中后返回并确认放弃 | 审核草稿丢弃，原库保持 |
| 修改磁盘文件 | 预览后改TXT，再确认原预览 | source仍绑定原fileHash；重新选择才换指纹 |
| 伪造segmentId/source | 在命令测试传未知段落或额外source字段 | 严格拒绝，不构造任意出处 |
| 跨作品分类 | 用隔离第二作品categoryId入第一作品 | 事务失败，整批不提交 |
| 陈旧版本 | 预览后另一操作增加作品revision | 提示刷新审核，旧版本不覆盖 |
| 回执重放 | 数据库测试重复同operationId与输入 | 知识、快照与修订不重复增加 |

从项目根目录运行 `npx vitest run tests/unit/book-extraction-commands.test.ts tests/unit/book-extraction-database.test.ts`，观察临时库断言。不要直接修改作者真实数据库或为了让测试通过去掉版本校验。

## 8. 拓展练习与答案要点

练习一：设计“原文摘录”和“作者学习笔记”两个字段。答案要点：分别保存冻结原文与编辑笔记，出处hash只绑定原文；迁移、归档、搜索、AI预览和导出都要明确是否包含两字段，不能只加一个输入框。

练习二：为何文件hash和段落hash都需要？答案要点：文件hash定位整份字节材料，段落hash定位解析出的文字；DOCX元数据变动可能改变文件hash而不改段落文字，两者不能混为一谈。

练习三：把本地拆书扩展到URL时先做什么？答案要点：明确可使用公开网页，限制协议、私网地址、重定向、大小和时间；解析失败留草稿、确认前不入库，不突破反爬。不能直接给React一个任意URL下载权限。

练习四：设计AI自动建议分类。答案要点：AI输出是候选，必须映射当前作品有效分类并经作者逐条确认；新的云发送有自己的范围/费用预览，不能把本地文件选择当云上传许可。
