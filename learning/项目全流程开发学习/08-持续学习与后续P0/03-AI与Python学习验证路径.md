# 第三章 先保护作者再接入AI

本章状态：本章描述已确认需求和后续学习方案；正式云端AI、候选接受、回写与一致性检查仍待开发验收。

学习目标：区分桌面客户端架构与AI实验路线，理解作者授权、凭据保护和版本保护是AI功能的一部分。

客户端采用Electron、React/TypeScript与SQLite。Python/FastAPI纳入AI学习与验证路径，用来理解模型调用、服务接口和评测；不因此让离线写作依赖Python进程或远端服务器。

阅读PRD的FR-12至FR-15。每次实际云端发送前展示服务、模型、操作、实际正文范围、附带知识与费用提示，作者确认后才发送。断网仍能写作、保存、搜索和导出。

例子：作者请求润色当前段落。AI上下文可以包含作者选定的描写参考，但知识内容只是素材，不能把素材中的指令当成授权，扩大正文发送范围。

实践步骤：

1. 用不含真实未发表作品的样本文本学习模型请求与响应。
2. 定义输入输出DTO与超时、取消、额度不足错误。
3. 实现云服务适配层，再用测试替身模拟成功与失败。
4. 用Python/FastAPI写独立实验，比较流式输出、费用与结果质量。
5. 将验证结论写入新学习章，再决定是否进入客户端实现。

API Key计划使用Windows凭据或Electron safeStorage/DPAPI，不进作品归档、日志与错误报告。UI不能显示完整密钥，打包源不能包含开发者私钥。

AI正文候选先对比，作者确认前先完成自动快照；原文变化要重新生成或重新对比，不能用旧候选覆盖新草稿。保存或快照失败时不应用修改。

```text
明确范围 → 作者授权 → 请求模型 → 显示候选与证据
→ 检查原文版本 → 自动快照 → 作者确认后事务写入
```

一致性覆盖角色、时间、地点、伏笔、大纲与写作特点；剧情感受结果标明AI建议、证据和不确定性。正文回写先产生候选，逐条审核后入知识库，不自动创建正式伏笔或修改剧情树。

超时、断网与额度不足保留原文和候选状态，只允许作者手动重试，不自动重发付费请求。超长上下文提示分块或缩小范围，不能静默截断后声称检查完整。

证据入口：当前为PRD与技术方案设计；正式实现需增加授权范围、取消、密钥不入归档、旧候选冲突、失败不改稿等测试，再更新本章状态。

练习：写一个模型适配器接口草案，给超时和取消分别设计测试；说明哪些字段可以记录日志、哪些必须删除或脱敏。

进阶依据：先用真实查询和质量问题判断是否需要向量检索或本地模型，不因技术流行就增加维护负担。学习路线可以探索，产品能力仍按独立质量门槛交付。
