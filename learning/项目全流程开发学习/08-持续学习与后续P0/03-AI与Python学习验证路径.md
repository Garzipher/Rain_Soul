# AI与Python学习验证路径

AI应该帮助《雨落之后》改进表达，而不是绕过作者改稿。
本章先设计一次受控云端调用，再安排Python的学习位置。
完成后，你能解释授权、候选、证据和确认写入之间的边界。

**状态说明（2026-10-09）：**Electron 客户端与云端 AI 适配已经实现；基础 AI、候选写入、正文回写、剧情感受与一致性建议已接线并用测试替身验证。
Python/FastAPI是AI学习验证路径，不是现有客户端必需服务。
真实模型效果、计费及供应商兼容性仍待作者针对所选服务验收。

## 技术基础：HTTP、token、模型与检索参考

### HTTP 请求包含哪些部分

HTTPS 请求包含地址、方法、头部和正文。当前云适配向兼容服务的 `chat/completions` 发送 POST，Authorization 头携带主进程读取的凭据，JSON 正文带模型和消息。HTTP 200 只说明协议处理成功，不保证文学判断或结构化结果正确。

401/403 通常表示认证/权限问题，429 可能表示额度或速率限制，超时表示在等待预算内没有完整结果。不同供应商可能采用自己的错误结构，因此适配器必须把可解释错误返回 UI，不能直接展示可能含敏感信息的原始响应。

### token 与上下文窗口

模型把文字转换成 token；一个 token 不等于一个汉字，也不等于一个英文单词。输入正文、系统说明、参考知识和预留输出共同占用上下文窗口。项目估算值是容量与费用提示，精确切词和价格由供应商决定。

超长范围不能悄悄截断。只有少量上下文时，模型无法可靠判断远处伏笔和倒叙；UI 必须让作者知道实际发送范围，而不是声称理解整部作品。

### 检索与生成是两步

知识检索先找可能相关的描写，模型再参考授权素材生成建议。当前 `ai-reference.ts` 使用本作品关键词与已关联资料，不是向量数据库。作者决定哪些条目进入预览，不能把检索命中视为必须上传。

提示词是对模型的文本要求，不是安全边界。参考素材里“忽略规则”等文字要被当作材料；权限、发送确认、候选写入和证据核验仍由程序执行。

### Python/FastAPI 实验如何入门

Python 可以先离线读 JSON 样本、核对必需字段与证据，不需要直接用真实 Key。FastAPI 则用路由函数把实验包装为 HTTP 服务。当前没有被客户端依赖的 Python 服务；不要把学习框架变成作者安装前置条件。

独立实验先固定三条自写样本：正常雨景、含倒叙的时间冲突、无冲突反例。给人工参考答案，再比较结构、证据与不确定性。这样才知道模型改善了哪个问题，而不只是“回答很长”。

## 2. 一次AI操作的产品流程

作者选中“雨停以后，站台还在滴水。”并请求润色。
先显示模型服务、将发送哪些正文和预计费用或计费提示。
作者可以取消；确认后才允许发送。
返回结果是候选，不是自动覆盖原文。
作者比较后确认写入，写入前自动保护当前版本。

```text
选择正文
→ 组装明确上下文
→ 显示服务、范围、费用并授权
→ 发送请求
→ 得到候选与证据
→ 与当前原文重新核对
→ 自动快照保护
→ 作者确认写入
```

每一步都应能解释是谁做了什么决定。
AI建议不代表事实正确，也不代表作者已经授权保存。

## 3. 上下文不是整部作品默认上传

用户确认四种范围：当前章节、前章衔接、全卷、自定义。
请求时显示最终实际发送范围。
超长内容需要提示，分块或让作者缩小范围。
静默截断会让AI缺少关键情节却给出过度确定的建议。

| 范围 | 适合问题 | 风险 |
| --- | --- | --- |
| 当前章节 | 段落润色、局部纠错 | 不了解远处设定 |
| 前章衔接 | 开头承接是否顺畅 | 仍缺全卷信息 |
| 全卷 | 主要事件与角色一致性 | 费用与长度较大 |
| 自定义 | 针对特定证据 | 作者可能漏选关键来源 |

知识库提供相关描写供取长补短。
它的来源、作者权限和使用方式仍应可追溯。
不要把检索到的句子直接拼接进小说而隐藏出处。

## 4. 设计练习：请求契约

下面只是本章练习的JSON样本：

```json
{
  "action": "polish",
  "scope": "currentChapter",
  "sourceRevision": 7,
  "selectedText": "雨停以后，站台还在滴水。"
}
```

它帮助你思考需要冻结哪些输入。
不应把这段JSON发给一个杜撰的/api/polish接口。
正式契约已包含身份、授权范围、取消和结果状态，位于 `src/shared/ai.ts` 与 `src/shared/contracts.ts`。
sourceRevision用于识别请求期间原文是否变化。
如果原文变化，必须重新生成或重新比较，不能盲目覆盖。

## 5. 一致性与剧情感受怎样表达

规则结果应指出具体证据。
AI结果标为建议，并说明不确定性。
角色、时间、地点、伏笔、大纲偏离、写作特点漂移都可能涉及判断。
“有问题”必须让作者知道来自哪章哪段、为什么认为可能冲突。

设计输出示例：

```text
建议：核对主角到站时间。
证据：旧站台段落A写傍晚，雨声段落B写同一时刻为清晨。
不确定性：可能存在倒叙或不同日期，请作者确认。
操作：查看来源；不自动改稿。
```

这不是模型已达到的能力承诺。
测试应核对证据引用、标注和失败处理，不只评估文风好不好。

## 6. 正文回写知识库怎样保护作者

AI可以提取摘要、角色、事件与伏笔候选。
候选逐条审核后才入库，保留原正文来源。
重复候选应能辨别，错误候选应能拒绝。
批量提取不代表批量自动确认。

稳定段落ID帮助来源定位。
但段落删除、恢复和合并后，证据仍需要明确状态。
“找到了相似文本”不能作为偷偷重绑来源的理由。

## 7. 为什么Python放在学习路径

React/TypeScript负责正式桌面界面。
Electron主进程管理本地文件、授权边界与模型适配。
SQLite负责作品持久化。
Python适合独立实验提示词、评价数据和模型结果。
FastAPI可用于学习服务接口，但会增加启动、打包、端口和进程维护成本。

先用独立实验回答真实问题：

1. 一个固定样本是否能稳定指出具体证据？
2. 换模型后哪些契约保持一致？
3. 超时与额度不足如何影响候选状态？
4. 哪些能力值得进入正式客户端？

只有验证需要独立服务，才决定是否集成。
学习Python不要求先给桌面应用增加必需后台。

## 8. 密钥与失败处理

API Key不能明文进作品SQLite、归档、日志或错误报告。
项目确认使用Windows凭据或Electron safeStorage/DPAPI保护。
renderer不应获得不必要的原始凭据。
服务配置和凭据读取应通过明确的主进程命令边界。

断网、超时、额度不足时保留原文与候选状态。
显示原因，由作者手动重试，不自动重发可能计费的操作。
重试前重新确认发送范围与费用条件。
本地写作仍应正常工作。

## 9. 实际测试与云端验证边界

| 场景 | 预期 | 证据 |
| --- | --- | --- |
| 作者取消授权 | 不发请求 | 适配器调用次数为0 |
| 超时 | 原文保留，不自动重发 | 状态与调用计数 |
| 期间原文改变 | 不直接写入旧候选 | revision与比较提示 |
| AI引用来源 | 可查看具体章段 | 稳定ID与展示 |
| 密钥保存 | 不出现在日志归档 | 敏感信息扫描 |

先用可控假服务测流程，再对授权云端样本做人工评估。
不能把“模型接口返回200”当作小说质量达标。

## 10. 练习与答案提示

练习一：为什么润色候选生成后还要再看原文版本？
答案：请求期间作者可能继续写，旧候选不再基于当前原文。

练习二：为什么AI失败不能阻止普通保存？
答案：写作离线能力独立于云端服务，是首版基础承诺。

练习三：Python实验应先选什么样本？
提示：小而具体，有已知证据、反例与人工判断，不先跑整部长篇。
