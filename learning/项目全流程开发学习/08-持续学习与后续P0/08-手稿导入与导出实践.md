# 手稿导入与导出实践

本章把作者已有的 TXT/DOCX 手稿变成新作品，再把完成稿导出供其他软件阅读。导入要确认结构，导出要固定一份完整版本；这两条路径都涉及系统文件对话框，但它们不能获得任意读写作者文件的权限。

**本章状态（2026-10-09）：**TXT/DOCX解析与导出codec、新项目入库、命令协调和客户端入口已实现；codec、导入事务及真实 Electron 导入导出流程已验证，整套客户端交付门禁仍在进行。EPUB/PDF、网页下载、自动拆书后置；本作品正文的 AI 知识候选审核见本卷第十章。本章导入整部手稿，不等于从优秀作品抽取知识的拆文工具。

## 1. 导入先成为草稿

`src/shared/manuscript.ts` 中的 `ManuscriptDraft` 没有作品 ID，只保存标题、格式、编码、卷章和警告。选择文件后先解析，作者预览并修改章名，确认后才创建独立新作品。

```typescript
{
  title: '雨落之后', format: 'txt', encoding: 'utf-8',
  warnings: [],
  chapters: [{ title: '第一章 雨夜', volumeTitle: null,
    paragraphs: ['雨落在窗沿。', '', '他看见一把旧钥匙。'] }],
}
```

空行不能被随意删掉。原来的小说排版习惯与节奏可能依靠这些空行；没有可识别标题时，全文归为一章，作者仍可在导入后整理。

![真实 TXT 手稿导入预览](images/manuscript-import.png)

预览识别“第一章 旧车站”和“第二章 雨停”，允许改名与补分卷。只有点击创建新作品才入库，原 TXT 文件继续保留。

## 2. TXT：编码错误不是一句乱码提示

`src/main/manuscript-text.ts` 使用 `TextDecoder` 的 fatal 模式，非法 UTF-8不会悄悄替换成问号。UTF-8 BOM、UTF-16LE/BE BOM可识别，GB18030由作者显式选择；输入大小、控制字符与空文件也要检查。

```typescript
const decoder = new TextDecoder(encoding, { fatal: true });
const text = decoder.decode(bytes);
```

常见标题包括“第一卷”“第十二章”、阿拉伯编号和 `Chapter 1`。超过合理标题长度的整段正文不能被当标题。识别是初始建议，预览中的人工确认才决定最终卷章结构。

## 3. DOCX：压缩包与XML都有边界

DOCX是ZIP，正文在 `word/document.xml`。`manuscript-docx.ts` 使用 yauzl 按项流读取；`manuscript-xml.ts` 用 saxes解析命名空间、段落和标题样式。样式继承通过 `basedOn` 与 `outlineLvl` 识别。

| 层次 | 需要拒绝/限制的输入 |
| --- | --- |
| ZIP | 非法路径、重复路径、链接、加密、CRC损坏、过多条目、总展开过大 |
| XML | DTD/外部实体、格式错误、超深嵌套、过多节点 |
| 内容 | 只读可识别标题与正文，图片/表格/文本框等生成警告 |

仅读取正文不代表执行文档中的域或宏。表格里的文字不能悄悄混进小说正文，作者在预览中应看到“表格未导入”等明确警告。导入不会修改原DOCX文件。

## 4. 从预览到全新SQLite

```text
作品集“导入手稿” → 系统文件选择器
→ 主进程读取受限字节 → parseTxt/parseDocx
→ token + ManuscriptDraft返回预览
→ 作者改卷章标题并确认
→ ManuscriptCommands验证token/format/encoding
→ StoreService → Worker → createImportedProject
→ 新暂存目录建schema、卷章、稳定段落ID与索引
→ 事务提交并关闭 → rename为新项目目录
→ 书架显示新作品
```

源码分别在 `src/main/manuscript-commands.ts` 和 `src/workers/database/manuscript-import.ts`。预览token防止旧对话框确认错误文件；operationId用于回执未知时重放，并成为新作品ID。相同操作ID携带不同草稿要拒绝，不能覆盖已有作品。

暂存目录不是临时草稿的长期保存位置。数据库全部成功后才进入书架；异常关闭并清理本次暂存目录，已有作品与原始手稿保留。

## 5. 导出先冻结同一版本

作者点击导出后先等待当前自动保存完成，再通过 `freezeWork` 读取已提交正文与资产。`freezeExport` 制作独立DTO，导出codec不读取数据库，也不在导出过程中混合新旧稿。

```typescript
const frozen = freezeExport(work);
const bytes = format === 'txt'
  ? exportTxtManuscript(frozen)
  : await exportDocxManuscript(frozen);
```

导出函数在 `src/main/manuscript-export.ts`。DOCX统一字体、字号、颜色和1.5倍行距，标题加粗放大。TXT保留正文与卷章顺序，使用CRLF换行；纯文本不能呈现字体与字号。

知识引用按正文首次出现分配编号，同一条知识重复出现复用编号，文末列一次。已删除条目保留历史内容和删除说明。伏笔书签呈现为 `[伏笔：旧钥匙]`，文末附状态与章节/段落证据，失效证据仍有原摘录。

这些附加标记不计编辑器正文的汉字/字母/数字统计。导出文件看起来更长，不代表作者正文写作字数增加。

## 6. 跟做：一次有警告的导入与往返

1. 用文本编辑器创建UTF-8文件，包含“第一卷 雨”“第一章 雨夜”、两段正文、空行与“第二章 归来”。
2. 在作品集选择“导入手稿”，预览章名并修改一个章名，再确认。
3. 检查导入形成新作品，原作品没有被追加或覆盖，空行与中文正文保留。
4. 用Word创建带标题、正文、图片和表格的小文件；导入时核对警告，图片和表格不进入正文。
5. 打开导入作品，插入一个知识引用与伏笔标记，等待保存完成。
6. 分别导出TXT/DOCX，在系统文本编辑器与Word中核对标题顺序、重复引用编号、伏笔清单与正文。
7. 取消一次导出文件对话框，确认正文和当前作品仍保持。

文件对话框必须由主进程拥有。渲染层传格式与workId，不能传任意输出路径。对原文件名生成建议名称时，应去掉Windows非法字符。

## 7. 真实故障与回归测试

导出模块曾在TDD阶段只有测试接口而没有实现，导致导入模块无法解析。这是正常Red阶段，不能把它作为完整版本交付。补齐DTO、编号映射和DOCX生成后，测试还需用真实ZIP重新解析结果，不能只验证“返回非空Buffer”。

解析模块审查发现过非法限额未校验、ZIP累计大小错误递增、回调缺类型等问题。修复时先验证有限正整数，再计条目数量与累计字节数；不能用 `NaN` 或负值绕过限制。


正常路径之外，还要验证截断ZIP、坏CRC、错误编码、XML实体、缺失引用目标、重复段落ID、非法XML字符与导入操作重放。当前测试采用临时目录和构造文档，不读取真实作者数据。

## 8. 练习与检查点

练习一：为什么“标题识别失败”不应该拒绝整部TXT？答案：无标题仍可作为一章，作者可后续整理，正文不能因结构建议失败而被丢弃。

练习二：导出期间知识被编辑，会影响已经冻结的稿件吗？答案：当前导出DTO应保持调用时的数据，后续导出再读取新版本。

练习三：为同一知识两次引用设计断言，正文必须出现同编号，文末对应引用只出现一次；再软删除知识，断言仍可追溯。

检查点：你能分别画出导入与导出流程，解释预览token、operationId与revision分别保护什么，并在真实生成文件里核对最终内容。
