# 历史稿导出与手稿整理补充

本章深入第七、八章：作者可以直接导出旧快照，不必先恢复；导入预览可以按段落拆章、合并相邻章和排序，再创建新作品。包内读本统一更新，已安装作者正文保持不变。

**本章状态（2026-10-09）：**历史快照导出与导入预览结构整理已实现；真实 Electron 已验证旧稿 TXT/DOCX 导出且当前稿和历史不变。实际 Microsoft Word 打开、干净 Windows 安装和真实云端联调仍是外部验收项。

## 技术基础：纯映射、草稿整理与稳定行身份

### 纯映射为什么适合只读导出

纯函数只根据输入计算输出，不修改数据库或外部状态。`snapshotManuscript` 把校验后的历史 payload 映射为 ExportManuscript，codec 再生成文件；当前库不必被“临时恢复”为旧稿。

冻结 DTO 把正文、知识与伏笔放在同一时间点。若正文从 A 取、引用从当前 B 取，文件虽然能打开，历史语义仍然错误。测试应比较正文、引用和当前数据库不变三个方面。

### 临时数组操作与落盘规则一致

`slice(0, point)` 与 `slice(point)` 保留全部段落，只改变分章边界。合并连接两个数组，保留前章标题与分卷。空段也是节奏信息，不能先 filter(Boolean) 再拆章。

预览必须采用和入库一致的结构：无卷在前，分卷按首次出现排序，同名卷合并组，同卷保持相对章序。`normalizeManuscriptOrder` 使用 Map 维护分卷首次出现顺序，`canMoveManuscriptChapter` 限制上移下移只在同卷。

### 行身份为什么不能用数组下标

改分卷名会导致列表重新分组排序。若输入事件仍按旧下标找章，可能把下一次标题修改写到另一个章。预览行要有稳定身份，把事件绑定到对象；显示顺序可以变化，身份不变。

下面拆、合、改卷、排序都只发生在临时 ManuscriptDraft。取消预览不增加作品，最终确认才原子创建新库。

## 1. 为什么旧稿导出必须只读

如果为了导出A，先把当前B恢复成A，再导出，再恢复B，操作会增加历史、改变版本，并可能打断当前写作。只读导出只解析快照当时的关系图，不修改当前数据库。

```text
写作右上角“版本历史” → 旧快照“导出 TXT/DOCX”
→ App保存门禁
→ exportManuscript(workId, format, snapshotId)
→ ManuscriptCommands → freezeSnapshot
→ Worker校验快照hash/格式/作品身份
→ snapshotManuscript映射旧稿ExportManuscript
→ TXT/DOCX codec → 系统保存对话框
```

映射代码在 `src/workers/database/snapshot-export.ts`。它从快照当时卷章顺序构造正文，使用快照内知识、伏笔和证据生成引用清单。当前知识改过，不能让历史稿引用清单变成今天的内容。

## 2. 如何证明没有偷偷恢复

`tests/unit/snapshot-export.test.ts` 导出前后比较数据库序列化结果，要求完全一致。测试还先保存旧知识再修改当前知识，导出旧稿仍应出现旧内容；返回非空文件不能证明这一点。

DOCX用真实ZIP重新读取，Worker测试走正式消息入口。取消系统保存只是取消导出，不应创建新快照。损坏hash、无效文档或错误卷章关系拒绝导出，不做部分输出。

跟做：创建第一稿快照，改掉当前章标题与知识，再在快照行选择导出。对比旧稿和当前稿的文件内容，确认当前编辑器、版本号与历史数量没有变化。

## 3. 导入预览里的整理动作

`src/renderer/components/manuscript-dialog.tsx` 保存本次临时 `ManuscriptDraft`。上移下移交换章对象，拆章在指定段落边界切数组，合并把下一章正文完整接到本章。

```typescript
const first = paragraphs.slice(0, point);
const second = paragraphs.slice(point);
```

拆分点必须满足 `1 <= point < paragraphs.length`，至少两段才能拆。空段也是真实段落，不能先过滤掉。新章继承分卷标题并可修改，默认章名加“（续）”。

合并明确保留前一章标题与分卷；后一章标题不当作正文偷偷插入。页面先显示这一规则，让作者决定是否合并。整理期间没有作品库写入，只有最终确认才创建新作品。

## 4. 跟做与故障检查

1. 准备三章TXT，每章至少两段，含一处空段。
2. 在预览选择第一章的段落边界拆成两章，核对空段保留。
3. 修改新章标题与分卷，把新章上移，再合并下一章。
4. 核对显示顺序与正文总段数，再创建新作品。
5. 取消另一次预览，书架不增加作品，原TXT保持不变。

后台确认期间所有结构按钮禁用；焦点循环包含新增select，不能让键盘用户陷在弹窗中无法选择拆分位置。相关测试：`tests/unit/manuscript-dialog.test.tsx` 与 `tests/unit/renderer-manuscript.test.tsx`。

## 5. 练习与检查点

练习一：历史稿正文正确但引用用了当前知识，算导出成功吗？答案：不算，正文与关系必须来自同一历史版本。

练习二：为何合并默认保留前章分卷？答案：合并后的章只能属于一个分卷，规则应在确认前明确，作者可再修改。

练习三：给拆章测试加空段，并断言拆分后两章拼接与原段落数组相等；给历史导出测试检查revision与快照数量完全不变。

检查点：你能区分“只读历史导出”“恢复历史稿”和“预览结构整理”，知道哪一个会写当前作品库，以及如何用测试证明边界。
