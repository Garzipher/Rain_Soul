# AI辅助拆书的授权与学习建议

本章把第16章的“手工摘选”扩展成“模型推荐、作者审核”。目标是读懂优秀段落如何组织声音、动作和节奏，把可核对的摘录和自己的学习笔记整理进知识库，供后续写作参考。AI不能替作者决定某种写法一定优秀，也不能把生成句子冒充原作者的句子。

先完成第16章，理解文件解析、出处指纹和整批事务；再阅读第三卷的IPC、第五卷的异步回执，以及第10章的云端授权。本章对应2026-10-10用户确认的PRD FR-21，整书自动上传、URL下载和向量检索仍属后续范围。

## 1. 为什么先把原文变成段落，再交给模型

TXT的字节要按编码解码，DOCX的ZIP/XML要转换成支持的标题和正文。模型接收到的不是磁盘路径，也不是完整DOCX文件，而是解析后明确选中的原始段落。每段有临时ID；文件预览有token，标记这次实际读取。

与第16章的入库勾选不同，AI分析勾选只表示“希望分析这段”。AI返回建议以后，作者仍需决定是否带入审核、是否修改，以及是否勾选入库。把两种选择合并，会让“想听建议”变成“同意写数据库”。

| 层次 | 输入 | 输出 | 可以做什么 |
| --- | --- | --- | --- |
| 本地解析 | 作者选择的TXT/DOCX | 冻结原段与预览token | 读取获准文件，不联网 |
| AI准备 | token、段落ID、使用许可 | 服务/材料/费用预览 | 构造请求，不发送 |
| AI执行 | 明确确认的token/hash | 原始回答与校验结果 | 发送所披露原段和分类标签 |
| 带入审核 | 作者采纳的合格建议 | 可编辑学习卡 | 改审核草稿，不写数据库 |
| 确认入库 | 已审核内容与出处声明 | 新知识条目与保护快照 | 完成既有原子事务 |

本批每次分析1—20段。原文总长度或模型容量不足时要求缩小范围，程序不截断原文，也不自动发送第二批。数字表示单次请求和审核的边界，不限制作者作品长度。

## 2. TypeScript契约与Zod校验分别解决什么问题

TypeScript在开发阶段检查对象类型，例如建议必须有excerpt和technique。编译后的JavaScript不会自动阻止非法IPC数据或模型返回。Zod在运行时逐字段检查对象；严格模式拒绝额外字段，防止渲染层把路径、凭据或自称出处混进请求。

`src/shared/book-extraction-ai.ts`定义四项桥接方法：prepare、execute、getResult、cancel。准备只接受作品ID、真实预览token、所选段落ID和许可确认，没有任意正文或文件路径字段。

```typescript
// 受限协议节选，完整定义见shared/book-extraction-ai.ts。
const request = {
  workId,
  token: preview.token,
  segmentIds: selectedIds,
  permissionConfirmed: true,
};
await api.prepareBookExtractionAi(request);
```

`BookExtractionCommands.getPreview`验证作品和token后返回`structuredClone`副本。克隆保证服务处理副本时不能改主进程的冻结原文；不能因为渲染层传回同名字段就信任它。

## 3. 在源码中追踪一次分析

按下列次序打开项目文件，能看到界面、权限、网络和审核如何连接，而不是只读一个按钮函数。

```text
book-extraction-workspace.tsx
  → BookExtractionAiPanel：独立分析选择
  → shared/contracts.ts：DesktopApi继承受限AI拆书接口
  → preload/index.ts：rainsoul:command IPC
  → main/index.ts：BookExtractionAiCommands分派
  → getPreview：重建可信原段
  → freezeWork：读取当前作品版本及有效分类/标签
  → BookExtractionAiService.prepare：冻结请求、生成授权身份
  → StructureDialog：作者核对服务、材料与费用
  → execute + beforeSend：再次检查预览/作品/服务配置
  → ai-transport.ts：受限HTTPS与完整响应校验
  → 建议校验 → 临时缓存 → 响应后状态检查
  → 带入审核 → confirmBookExtraction → 原有知识事务
```

主进程云命令独立于文件命令队列。这是本章一个容易忽略的异步问题：如果“执行请求”和“取消请求”都排在同一串行队列，取消会等执行完成后才开始。独立请求集合和AbortController使取消能够在请求进行中生效。

AbortController发出取消信号，传输层停止继续处理；它不能承诺服务端没开始计费。程序因此不会自动重发，界面也会提示手动核对结果。

## 4. 请求hash与一次性授权

SHA-256请求hash把所选原文、字典、作品版本和服务配置绑定起来。授权token是一次性的随机身份；每次新的显式准备形成新的请求身份。这样，同一执行回执的重放不能再次联网，而作者重新预览并确认后可以主动重试同一材料。

准备与执行分开，准备不读取明文Key、不请求模型。真正发送前再次校验是因为这两步之间可能隔着几分钟：作品分类变化、素材预览被取消或服务地址改变都会让旧授权失效。

`ai-transport.ts`复用既有安全边界：只接受公开HTTPS端点，解析并检查地址，固定请求到已核对的IP，TLS仍验证服务域名；拒绝重定向、超大响应、认证失败、额度不足和明确被截断的回答。API Key从系统加密配置读取，不进入授权截图、知识卡、作品归档或正文。

授权材料包括原段和当前作品有效分类/标签名称及ID。它不包含作者正在写的正文、既有知识卡或大纲。分类名称也是发送内容，必须出现在完整预览中。

## 5. 模型回答为什么还要逐字核对

模型按JSON返回建议，但符合JSON语法不代表内容真实。服务先验证格式与字段限额，再验证段落、分类和标签身份，最后核对excerpt是不是对应原段的连续原文。

```typescript
// 校验逻辑节选；完整代码在book-extraction-ai-service.ts。
const segment = frozen.request.segments.find(item => item.id === suggestion.segmentId);
const originalQuoteMatches = segment?.text.includes(suggestion.excerpt);
const categoryExists = frozen.request.categories.some(item => item.id === suggestion.categoryId);
const tagsExist = suggestion.tagIds.every(id => frozen.request.tags.some(item => item.id === id));
```

这三个检查回答不同问题：模型是否引用了获准段落、是否使用当前作品已有分类、是否伪造了摘录。任何一项失败都让整批建议不可采纳。原始回答保留为纯文本，供作者查看或复制；HTML样式的字符串不会执行为网页。

写作手法、适用场景和练习仍是AI建议。例如“声音比喻延长等待感”是解释，不能当成原作者已发表的评论。带入审核的body把原文摘录和解释分别标明，避免来源混淆。出处由原文件、章段位置和哈希重建，模型无权提供权威source。

## 6. 网络回答、IPC回执和数据库写入是三回事

模型已经返回答案，IPC却可能失败；如果作者因此再点一次发送，会产生第二次调用。`BookExtractionAiCommands`把完整结果先放入本机临时缓存，再检查版本和配置。后验变化会标记不可应用，但不丢弃原始回答。

按请求hash核对结果会返回三种状态：running表示请求还在进行，ready表示可查看已收到回答，missing表示本机没有完成结果。核对只查本机，不请求模型。ready仍再次核对当前状态；旧结果不能因为重新打开核对就变得有效。

本批缓存只在主进程运行期间存在。正常离开受草稿和请求保护，强制结束进程后不能承诺恢复未入库答案。缓存有上限，达到上限要求先完成核对或明确放弃，不静默淘汰未决回答。

## 7. 跟着操作：整理一张写法学习卡

使用自己编写的合成文本练习：

```text
第一章 等雨
细雨落在窗上，远处的灯被拉成一条暖色的线。

他把话咽了回去，只用指尖慢慢抚平信封的折角。
```

1. 创建练习作品，打开知识库的拆书工具，选择上述TXT。检查章段和编码；填写书名与作者，并确认有权使用。
2. 在AI分析范围里只勾选第一段。检查下面的“审核通过段落1”仍未勾选。
3. 准备AI推荐，逐项阅读服务、模型、原文与字典、计费提示。第一次点击取消，确认未生成推荐、知识库未变化。
4. 再次准备，确认发送。没有自己的云配置时会明确提示配置；不需要配置也可继续手工摘选。真实云操作可能产生费用。
5. 阅读推荐的摘录、写法、场景和练习，点击带入审核。审核框会分别标明四种内容，仍未勾选入库。
6. 自己修改分析语句。再次带入AI建议时应先出现替换确认；取消后手工内容保持原样。
7. 检查分类与标签后勾选审核，确认入库。知识卡保留真实文件和段落出处；重启后卡片仍在，未入库的临时模型答案不承诺保留。

## 8. 故障实验与测试阅读

| 实验 | 如何验证 | 正确行为 |
| --- | --- | --- |
| 返回不存在于原段的摘录 | 服务单元测试替换模型JSON | 原始回答可看，整批不可采纳 |
| 分类ID来自其他作品 | 命令/服务测试设置陌生ID | 不应用，不写知识，不伪造分类 |
| 授权后更改服务 | 准备后修改测试settings | 发前拒绝，零网络调用 |
| 收到完整回答后作品变更 | fetch替身改变revision | 缓存仍在，结果不可应用 |
| 执行回执丢失 | UI替身拒绝IPC，主进程保留结果 | 本机核对，不重新收费 |
| 请求仍在进行时核对 | 阻塞测试transport后lookup | 返回running，保留请求保护 |
| 取消后晚回复 | 挂起execute再取消 | 晚回复不覆盖当前建议 |
| 已审核手工内容被采纳替换 | 先编辑和审核再点击带入 | 先确认替换，再清除审核勾选 |

核心测试在`tests/unit/book-extraction-ai-service.test.ts`、`book-extraction-ai-commands.test.ts`、`book-extraction-ai-panel.test.tsx`和`book-extraction-workspace.test.tsx`；IPC桥接在`book-extraction-ai-preload.test.ts`。桌面测试在`tests/desktop/book-extraction-ai.spec.cjs`。

```powershell

npx playwright test --config playwright.desktop.config.cjs book-extraction-ai.spec.cjs
```

桌面测试前执行`npm run build`。读测试时先找mock在哪里：单元测试替换fetch；桌面测试只在被启动的隔离Electron进程替换HTTPS响应，渲染层、IPC、原文冻结和SQLite仍是真实程序。它们分别证明局部逻辑与系统接线，均不证明真实厂商服务兼容。

## 9. 拓展练习与参考解答

练习一：在建议中增加“节奏”字段，需要改哪些地方？参考解答：先改模型结果schema和共享类型，再改提示词、UI和带入审核body；补正常/缺失/过长/非法结果测试。只加一个界面标签，不能保证主进程接受这个字段。

练习二：为什么不把模型返回的source写进知识库？参考解答：模型不能证明文件身份；正确的source应从冻结文件名、字节hash、原段位置/hash与作者审核出处生成。AI解释与原文摘录必须分别标明。

练习三：如何做“分析整章”？参考解答：先明确每批范围、模型容量与作者授权；每批保留自己的请求身份，失败不重发。不能把现有20段限制删掉，就宣称整书分析可用。

练习四：想跨重启恢复模型结果，需要什么？参考解答：设计独立受限候选存储、版本迁移、敏感内容保留策略、来源验证和恢复界面，先写失败测试。当前内存Map与作品知识库不是同一个存储，不能用自动入库来绕过恢复设计。
