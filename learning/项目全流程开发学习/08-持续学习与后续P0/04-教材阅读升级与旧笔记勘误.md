# 教材阅读升级与旧笔记勘误

本章是旧版学习作品的补充，说明为什么同一章会有两份可以阅读的内容。
旧版把教学源转为普通段落，读者可以写入自己的理解；本轮另提供保留代码与截图的图文读本。
你不需要删除旧笔记，也不需要重新导入整部作品。

**本章状态（2026-10-09）：**图文阅读、只读 Markdown 源文与作者笔记已实现；最终完整 P0 验收仍未完成。
本章不宣称所有用户自建作品已支持 Markdown 编写，也不宣称小说正文已支持插图。

## 1. 前置知识

读过第八卷第一章，认识课程清单的 key 与章节 ID。
知道 SQLite 中的正文属于作者数据，安装包内的 Markdown 属于发布教材。
知道同名不是同一个对象：判断课程身份使用固定作品 ID 和课程标记。

我们继续使用“雨落之后”作为贯穿小说案例。
你给小说写的段落仍在普通编辑器中保存。
你为学习写的笔记属于学习作品，不能被教材维护者更新包覆盖。

## 2. 更正旧版的阅读理解

旧版可编辑课程正文是首次导入后的普通段落，不能完整表达代码高亮、表格与系统截图。
因此“章节里有很多内容”不等于已经具备教材排版。
本轮把图文排版作为单独的只读视图，同时保留作者原来可编辑的正文。

| 视图 | 内容来源 | 可以做什么 | 更新时的保护 |
| --- | --- | --- | --- |
| 图文阅读 | 包内 Markdown 与批准截图 | 阅读、定位小节、查看代码 | 不写入作者正文 |
| Markdown 源文 | 同一份包内 Markdown | 核对语法与缩进 | 只读 |
| 作者笔记 | 当前学习作品章节正文 | 编辑、自动保存、记录练习 | 保留作者修改 |

已安装章的标题、正文、顺序、归属与删除状态仍归作者管理。
教材维护者需要更正旧教学时，追加像本章这样的补充，解释变化与原因。
新的只读读本可以随安装包更新；这不等于覆盖已导入的旧正文。

## 3. 在项目中找到两条链路

打开源码并找到这几处入口：

```powershell
Set-Location E:\soulrain
Get-Content .\scripts\build-learning-course.mjs
Get-Content .\scripts\build-textbook.mjs
Get-Content .\src\renderer\components\learning-chapter.tsx
Get-Content .\src\workers\database\learning-seed.ts
```

`build-learning-course.mjs` 将课程转换成受限普通文档，用于首次初始化和新章追加。
`build-textbook.mjs` 保留 Markdown 并校验截图，产生图文教材资源。
`learning-chapter.tsx` 根据学习作品和章节身份匹配教材；没有匹配时仍使用普通编辑器。
`learning-seed.ts` 负责导入跟踪与增量保护，不负责把新教材覆盖到旧正文。

```text
仓库 Markdown → 构建教材 → 图文阅读 / 只读源文
仓库 Markdown → 首次初始化或追加新章 → 作者笔记正文
作者输入      → 常规保存协调器           → SQLite 事务
```

不要把“只读源文”理解成编辑器保存后产生的 Markdown 导出。
它展示发布教材的原始语法；当前客户端没有任意教学作品的 Markdown 写作功能。
如果未来开发该能力，要另外定义作品模式、图片归属、导出和安全规则。

## 4. 跟做：证明教材与笔记互不覆盖

1. 启动客户端，打开“项目全流程开发学习”。
2. 选择本章，观察代码块和表格。
3. 切换到 Markdown 源文，观察代码围栏和表格符号；尝试编辑应没有写入行为。
4. 切换到作者笔记，追加“我能解释教材与笔记的区别”。
5. 等待真实保存成功，再切回图文阅读。
6. 正常关闭并重启，回到作者笔记核对追加内容。

预期：图文阅读仍是教材，作者追加内容只出现在笔记。
如果保存失败，切换不能悄悄丢弃输入；修复保存问题后再重试。
不要通过强制结束应用检验“正常关闭保护”，两种退出行为不同。

## 5. 维护者跟做：为旧安装追加补充

新章必须使用新的稳定 key。
不要修改旧 key 让它指向另一篇内容，也不要用旧章 ID 强行替换作者笔记。
将 Markdown 文件与清单变更放在同一个文档提交中，并进行构建校验。

```json
{
  "key": "continuation/04",
  "title": "教材阅读升级与旧笔记勘误",
  "file": "08-持续学习与后续P0/04-教材阅读升级与旧笔记勘误.md"
}
```

课程的既有删除状态优先于自动补章。
整部学习作品或目标卷已删除时，不为了“最新教材完整”擅自恢复。
作者自己恢复目标后，后续启动再按增量规则补入。

## 6. 排错与证据

| 现象 | 首先检查 | 错误处理方式 |
| --- | --- | --- |
| 看不到新章 | 新 key、目标卷删除状态、是否重新构建 | 不绕过删除保护 |
| 旧笔记变成教材 | 两视图是否复用写接口 | 立即停止覆盖并回归测试 |
| 图片在另一台机器丢失 | 是否引用 C 盘路径或未随包资源 | 使用批准本地 PNG |
| 教材版本与旧命令不同 | 对应批次与迁移测试 | 补充勘误，不伪改历史证据 |

教材中的 schema 版本、测试数和打包路径可能描述某一历史批次。
执行新版本前，检查当前迁移源码、任务记录和本轮验证报告。
不要因旧章写过一个版本号，就修改新数据库让它退回旧版本。

## 7. 练习与答案

练习一：为什么教材可以更新，笔记却不能同时被替换？
答案：教材属于项目发布资源，笔记属于用户数据；维护者无权推定作者编辑可以丢弃。

练习二：作者创建一个同名作品，它会自动得到本教材的图文模式吗？
答案：不会。课程匹配稳定身份，而不是标题文本。

练习三：普通小说里粘贴 Markdown 图片语法会显示系统截图吗？
答案：不会。小说正文仍受限，当前图文能力只用于包内学习教材。

本章检查点：你能在不删旧笔记的前提下追加补充章，并解释只读教材更新与用户数据更新的区别。
