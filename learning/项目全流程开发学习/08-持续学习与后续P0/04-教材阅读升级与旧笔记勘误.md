# Markdown 阅读原理与旧数据勘误

这一章解决两个不同问题：技术教材怎样保留代码与截图，以及修订教材怎样避免覆盖作者旧数据。先理解文本编码与 Markdown 渲染，再跟踪当前产品的数据来源。

**本章状态（2026-10-09）：**学习作品使用图文阅读与只读 Markdown 源文。旧版“正文—作者笔记”入口取消；此前安装的正文数据保留，读本更新不会重写作者 document_json。普通小说仍使用固定样式编辑器，当前没有任意作品的 Markdown 编辑和插图能力。

## 学习目标

- 解释乱码、普通正文展示和 Markdown 排版不足为什么是不同问题。
- 从源文件到包内资源追踪一个代码块和一张截图。
- 验证教学资源更新与作者数据库更新互不覆盖。

## 1. 技术原理：编码决定文字，Markdown 决定结构

### UTF-8 与乱码

文本文件本质是字节。编码规定字节如何对应字符，例如 UTF-8 使用一至多个字节表示 Unicode 码点。以错误编码解读同一份字节，会出现乱码；字符已经被错误替换并保存后，单纯切换字体不一定能找回原文。

另一方面，`# 标题`、三反引号和 `| 表格 |` 直接出现在普通段落里，不一定是编码坏了，而是没有经过 Markdown 渲染。排查要先看实际字符：中文不可读是编码或写入问题，中文可读但符号原样显示通常是阅读路径问题。

本项目 `readFileSync(path, 'utf8')` 明确读取源文编码。小说文档是受限 JSON，教材源文是 UTF-8 Markdown；不应让同一块界面把两份来源混作“正文—作者笔记”。

### Markdown 的解析链

```text
UTF-8 字节 → Markdown 字符串 → AST（语法树）
→ 标题/段落/代码/表格节点 → React 元素 → 屏幕阅读
```

`remark-gfm` 处理表格等扩展语法；`rehype-highlight` 为代码分类上色。代码高亮只影响展示，不执行示例。原始 HTML 不直接作为受信任界面执行，本地图片还要先经过构建校验。

### 为什么源码模式只读

源文模式用于核对代码缩进与标记语法，不是作者笔记编辑器。允许编辑包内教材会让“发布资源”和“用户稿件”混淆，重装后也无法知道该保留哪一份。若将来支持普通作者 Markdown 作品，必须另行定义图片归属、存储、版本和导出契约。

## 2. 项目剖析：同一稳定身份，两种数据寿命

| 数据 | 真源 | 当前用途 | 更新行为 |
| --- | --- | --- | --- |
| 图文读本 | learning 中的 Markdown 和批准 PNG | 标题、代码、表格、截图 | 随程序构建更新 |
| Markdown 源文 | 同一份包内 Markdown | 只读核对原语法 | 随读本一起更新 |
| 旧版导入正文 | 作品 SQLite 中的 document_json | 保留已有用户数据 | 不因读本修订覆盖 |
| 作者新建普通章节 | 作品 SQLite | 固定样式写作 | 常规自动保存 |

`course.json` 的 key 是教材逻辑身份，构建器由 key 产生确定性章节 UUID。显示标题可修订，已有 key 不得转给别的课程，否则同一数据库章节会匹配错误读本。

数据库跟踪表 `learning_seed` 保存已导入 key。`ensureLearningWork` 发现已跟踪章就保留正文、标题、顺序和删除状态；未跟踪的新章才增量加入。这个机制保护用户数据，不限制包内只读讲解继续完善。

## 3. 沿源码追一个代码块

```powershell
Set-Location E:\soulrain
Get-Content .\scripts\build-textbook.mjs
Get-Content .\scripts\textbook-vite-plugin.mjs
Get-Content .\src\renderer\components\learning-chapter.tsx
Get-Content .\src\renderer\components\textbook-reader.tsx
```

1. `compileTextbook` 读清单和每章 Markdown，保留完整代码围栏。
2. Vite 教材插件将 book 契约提供给渲染器，并把图片加入构建输出。
3. `LearningChapter` 按固定 workId 与 chapterId 找到本章，而非只匹配“项目全流程开发学习”标题。
4. `TextbookReader` 将 Markdown 解析为 React 元素；高亮处理代码，目录定位标题。
5. 切换源文时显示相同 Markdown 字符串，不把它保存回作者章节。

阅读源码时，圈出“匹配身份”“渲染内容”“写数据库”三种动作。前两种存在，不意味着第三种发生。

## 4. 图片为什么能离线看到

```markdown
![章节编辑界面](images/writing.png)
```

这段路径相对课程根目录，不相对当前章节文件夹。构建器只接受批准的 `images/名称.png`，验证路径边界、PNG 结构与尺寸，按 SHA-256 为内容生成包内名字。读本只使用批准映射；不能直接读取维护者机器上的 C 盘图片。

## 5. 跟做：核对当前读本

1. 打开默认学习作品与本章，确认没有“正文—作者笔记”入口。
2. 在图文阅读中找到上面的代码围栏与表格。

预期：两种阅读方式来自同一份教材；标题、源码和图片仍能离线查看，模式切换不修改作品正文。

## 6. 维护者实验：证明旧正文未覆盖

使用 `tests/unit/learning-seed.test.ts` 的临时数据库，不手改真实作者库。先初始化课程，修改某章 document_json，再用内容更新后的同 key 课程调用 `ensureLearningWork`。断言修改后的数据库正文保持原值；再追加新 key，断言只多出新章。

```powershell
npm run test:unit -- tests/unit/learning-seed.test.ts tests/unit/textbook-builder.test.ts
```

第一组证明作者数据保护；第二组证明读本编译、图片与安全边界。通过它们并不代表所有小说已能 Markdown 编写，也不证明真实安装升级已验收。

## 7. 排错

| 现象 | 判断路径 | 做法 |
| --- | --- | --- |
| 中文字形是乱码 | 检查源文件 UTF-8 与原始字符 | 修教学真源，重新构建；不删作品库 |
| 中文正常、代码围栏裸露 | 检查是否在源文或旧普通正文路径 | 回到图文阅读，检查课程身份 |
| 修改仓库后 EXE 没更新 | 查本次构建与启动包路径 | 使用新包；旧 EXE 不读仓库 |
| 图片另一台机器不见 | 检查批准映射和打包资源 | 修资源链路，不开放任意文件权限 |
| 更新后作者内容变化 | 检查 seed 是否覆盖已跟踪章 | 停止覆盖，补失败回归 |

## 8. 拓展练习与答案

练习一：给同一章节换一个显示标题，是否应换 key？

答案：不应。key 标识课程逻辑对象，显示标题只是属性。改 key 可能导致新章或身份错配；应保留原 key，修订包内读本。

练习二：一行“雨停了”可读，三反引号原样显示，是乱码吗？

答案：通常不是。先核对模式是否为源文/普通段落；Markdown 语法未解析与字符编码错误是不同故障。

练习三：为“教材修订不覆盖作者正文”写最小回归。

答案步骤：临时初始化 → 作者写自定义正文 → 同 key 换教材源文 → 再初始化 → 断言数据库自定义正文不变、卷章不重复；然后另编读本，断言其 Markdown 是新内容。分别检查用户数据与发布资源，才能证明两边都正确。

检查点：能解释字节、标记语法、只读资源与用户数据四个层次，知道修教材不能以删除作者内容作为代价。
