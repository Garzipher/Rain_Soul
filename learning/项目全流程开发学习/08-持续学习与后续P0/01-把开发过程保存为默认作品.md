# 把开发过程保存为默认作品

“开发日志有几行”与“读者能跟着做出系统”不是同一回事。
本章把教材源文、离线图文读本与作者笔记连接起来。
完成后，你能给“项目全流程开发学习”追加一章并理解更新保护。

**本章状态（2026-10-08）：**默认学习作品已实现。
本轮增加图文阅读、只读Markdown源文和作者笔记三种视图。
最终验证结果以本轮交付报告为准，不把正在编写的功能写成已验收。

## 1. 前置知识

认识Markdown标题、代码块、表格和图片语法。
理解第六卷的作品UUID与第七卷的构建资源链路。
需要知道“发布的教材原文”和“作者写的个人笔记”归属不同。
更新教材不能静默覆盖作者已经编辑的内容。

```powershell
Set-Location E:\soulrain
Get-Content '.\learning\项目全流程开发学习\course.json'
Get-Content .\scripts\build-learning-course.mjs
Get-Content .\scripts\build-textbook.mjs
```

## 2. 唯一教学源在哪里

完整正文存放在仓库learning/项目全流程开发学习/。
course.json列出卷、章、稳定key与Markdown文件路径。
文件夹名称用于人阅读，key用于生成稳定身份。
已经发布的key不能重新拿来代表另一个章节。

```json
{
  "key": "continuation/01",
  "title": "把开发过程保存为默认作品",
  "file": "08-持续学习与后续P0/01-把开发过程保存为默认作品.md"
}
```

这是当前清单中的真实章节条目。
修改显示标题不应重建章节UUID。
改变已有key却沿用旧对象，会破坏读本与笔记关联。

## 3. Markdown为何适合代码教材

代码块保留缩进，读者可以核对函数结构。
表格方便比较异常与排查方向。
标题形成章节内目录。

## 4. 两条构建链路

第一条链路把课程转成普通作品正文，用于首次默认初始化。
第二条链路保留Markdown，编译图文阅读资源。
二者使用同一份清单和稳定章节身份。

```text
course.json + Markdown
├─ build-learning-course.mjs → learning-course.json → SQLite默认作品
└─ build-textbook.mjs → 教材契约 + 本地PNG → Vite图文读本
```

普通正文支持作者原来的笔记与编辑。
图文读本呈现随包更新的教材原文，不覆盖那份正文。
这解决“课程修订了，但作者笔记必须保留”的冲突。

## 5. 读本资源如何进入包

compileTextbook读取清单和章节Markdown。
解析图片引用，拒绝越界路径与不允许的资源格式。
每张PNG按内容SHA256生成包内文件名。
textbook-vite-plugin.mjs通过虚拟模块提供教材契约。

```text
virtual:rainsoul-textbook
→ book.workId
→ chapters[id,key,title,markdown,images]
→ /learning/<SHA256>.png
```

相同图片内容可共用资源，不必每章复制一份。
阅读组件只接受编译器批准的图片映射。
原始HTML、任意外链和远端图片不会直接变成可执行界面。

## 7. 默认初始化如何避免重复

Worker启动先读取包内learning-course.json。
ensureLearningWork验证课程后初始化或增量补充。
学习作品使用固定UUID与course_key标记。
同名作者作品不能因为标题相同被当作默认课程接管。

已有课程只补没有跟踪过的新卷章。
learning_volume跟踪卷key，learning_seed跟踪章key。
已编辑标题、正文、顺序、归属与删除状态都要保留。
已删整书重启时不会擅自复活。

## 8. 跟做：追加一章的练习流程

以下是维护者练习，先在个人分支操作，不直接污染已发布清单。
新章必须有新key，不复制旧key充当身份。

1. 在对应卷目录新建Markdown。
2. 写学习目标、前置概念、步骤、代码与练习。
3. 在course.json追加对应条目。
4. 引用实际存在的批准截图。
5. 运行课程构建器与读本编译测试。
6. 构建后在隔离目录打开课程核对。

```powershell
npm run test:unit -- tests/unit/learning-course-builder.test.ts tests/unit/learning-seed.test.ts
npm run build
```

教材编译相关测试文件以tests/unit实际清单为准。
不要为了漏图而暂时删掉图片校验后发布。

## 9. 更正教材时如何处理旧笔记

已导入普通正文不能自动覆盖。
更正教学原文会更新只读图文读本；普通正文仍保留作者内容。
重要历史错误还应新增勘误或补充章，明确旧讲法与更正原因。
这样旧笔记上下文可解释，而不是悄悄改写历史。

未来知识、剧情与伏笔功能交付后，可把模块大纲与数据流关联进去。
在那些功能完成前，应先用教材正文解释，不能创建假入口冒充已有能力。
学习作品是普通作品，不要求作者完成课程才能写小说。

## 10. 诊断与练习

| 现象 | 排查方向 | 正确原则 |
| --- | --- | --- |
| 每次启动多一本课程 | 固定ID与标记 | 初始化应幂等 |
| 更新后笔记消失 | 教材与作者正文是否分开 | 不覆盖作者数据 |
| 包内截图缺失 | 编译批准路径与资源输出 | 本地图片随包离线 |
| 新章未出现 | key跟踪、卷或作品删除状态 | 尊重删除，不擅自复活 |

练习一：为什么不用作品标题判定默认课程？
答案：作者可能创建同名作品，也可能给默认课程改名。

练习二：读本更新与作者笔记更新是否同一事务？
答案：不是。读本是包内教材资源，笔记是用户作品持久化内容。

本章检查点：你能画出同源教材进入只读阅读与可编辑笔记的两条路径。
