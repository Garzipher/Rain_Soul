# 第一章 学习记录必须能在作品集中阅读

本章状态：课程源与默认学习作品已接入正式客户端，共8卷24章；具体验证范围以项目交付记录为准，后续持续追加。

学习目标：把需求、设计、代码、测试、评审和复盘写成可学习的作品，而不是只保存提交列表或阶段日志。

用户要求只有一个作品集。本书名为“项目全流程开发学习”，与小说一样按作品、分卷、章节组织，默认出现在作品集中；不另建学习合集，也不等知识卡或伏笔功能完成后才提供正文。

项目内真源保存在 `learning/项目全流程开发学习/`。Markdown正文便于Git评审，课程清单描述卷章顺序与稳定key；构建器生成受限WritingDocument，随应用打包，离线首次启动即可读取。

阅读 `scripts/build-learning-course.mjs` 与 `src/workers/database/learning-seed.ts`，理解两阶段职责：构建时解析可信课程源；运行时在本机SQLite初始化或追加课程。renderer不能获得任意文件读取能力。

本轮测试先行：课程构建测试先定义稳定身份、重复key和越界路径等失败案例，再实现SHA256派生ID与路径校验。运行期测试使用真实临时SQLite，先证明初始化、重复启动、作者编辑与增量冲突等行为，再接入Worker。

启动链路是Markdown与清单 → `build-learning-course.mjs` → 包内learning-course.json → Worker初始化 → WorkRepository扫描 → 唯一作品集。首次创建先写临时目录并事务提交，已存在作品用跟踪key识别新增章；同名判断不能代替身份与课程标记检查。

Logo与课程并行修正：先核对Demo的27px圆角蓝框、负9度旋转与中心点，再由 `scripts/generate-app-icon.mjs` 从SVG生成多尺寸PNG/ICO，接入窗口和EXE；测试资源格式后，还要运行真实目录包看图标。测试记录必须标明当时的范围和结果，不能沿用上批103项数字声称新版已通过。

实践步骤：

1. 从本书选一章，对照对应源码路径与测试文件阅读。
2. 在临时环境首次启动，检查作品集和卷章层级。
3. 编辑其中一章并重启，确认作者笔记保留。
4. 新增一个课程章节key后重建，验证只追加新章，不覆盖已有编辑。

例子：作者在“保存回执”章加了自己的理解，下一批加入“知识检索”章。升级应追加新章，不能用打包源重写作者笔记；同名普通用户作品也不能被接管。

新章的建议结构：

```text
状态与目标 → 用户需求 → 方案理由 → 实际代码联系
→ 操作或例子 → 测试证据 → 练习 → 边界与后续
```

修正既有教学源时要说明应用内既有章的更新策略。默认保留作者编辑，因此重要勘误适合追加专门章节，不能只改源文件便声称所有已安装作品已同步更新。

之前仅在 `tasks/desktop-foundation.md` 和 `tasks/structure-management.md` 写学习卡，却把应用内作品延后，未落实需求。本轮补齐默认作品，后续每批核心功能同步扩充课程，不阻断正常开发。

未来剧情架构可作为模块大纲，伏笔架构可记录接口、路由、前后端对接和数据流；这些正式能力未完成前，先在本书正文写清关系，不伪造已可操作的关联。

证据入口：课程构建与初始化测试检查确定性、身份、坏输入、重复启动和保留编辑；真实Electron学习验收检查首次默认展示与重启。

练习：为下一项功能拟一章学习卡，写出至少一条“为什么”、一条失败情形、一条真实测试和一个亲手操作任务，避免仅罗列改了哪些文件。

维护约定：状态写清已实现、正在验证或计划；测试数字有日期与范围；不把未开发的AI、搜索或快照写成已完成。
