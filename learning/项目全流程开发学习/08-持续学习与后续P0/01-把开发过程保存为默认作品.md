# 把开发过程保存为默认作品

“开发日志有几行”与“读者能跟着做出系统”不是同一回事。
本章把教材源文、离线图文读本与普通作品增量初始化连接起来。
完成后，你能给“项目全流程开发学习”追加一章并理解更新保护。

**本章状态（2026-10-09）：**默认学习作品与包内图文教材已实现。
客户端提供图文阅读与只读 Markdown 源文；旧版导入正文保留为用户数据，不再作为学习阅读入口。
最终验证结果以本轮交付报告为准，不把正在编写的功能写成已验收。

## 技术基础：Markdown、语法树与教材编译

### Markdown 为何能表达教学内容

Markdown 是轻量文本标记：`#` 表示标题，代码围栏保留程序缩进，表格组织对比，图片语法引用资源。源文仍是普通 UTF-8 文本，能被 Git 比较；渲染器将它转换成阅读界面，而不会自动执行代码块。

解析器先生成语法树（AST）。一行 `# SQLite 事务` 变成 heading 节点，三反引号围栏变成 code 节点。`react-markdown` 将这些节点转成 React 元素，`remark-gfm` 补表格等语法，`rehype-highlight` 为代码生成高亮标记。

这与小说正文树不同。小说只接受段落、文字、换行和书签；教材读本允许标题、代码和本地截图，但只读且经过资源白名单。不要把教材渲染器直接套进普通作者输入，绕过小说固定样式契约。

### 编译与运行分工

`compileLearningCourse` 根据 course.json 为卷章生成确定性 ID，生成普通作品初始化数据；`compileTextbook` 保留 Markdown，并解析、验证 PNG 引用。Vite 插件把读本契约与图片加入前端产物。

```text
维护者写 UTF-8 Markdown
 → 清单校验与稳定身份
 → AST 查图片、校验路径/PNG、计算内容 hash
 → Vite 包内教材
 → LearningChapter 按 workId/chapterId 匹配
 → TextbookReader 渲染标题、代码、表格与截图
```

### 两种更新为何必须区分

教材是随程序发布的只读资源，可以修订技术原理；已安装作品数据库是作者数据，可能编辑、移动或删除过卷章，不能覆盖。`learning_seed` 记录已经导入的 key，启动时只补未跟踪的新章。更新读本不会重写旧 document_json。

所以本轮可以把35章读本系统修订成教材，同时保留用户旧正文。旧版曾显示的“作者笔记”入口已取消；历史数据保留，不为了去掉入口而清空数据库。

## 2. 唯一教学源在哪里

完整正文存放在仓库learning/项目全流程开发学习/。
course.json列出卷、章、稳定key与Markdown文件路径。
文件夹名称用于人阅读，key用于生成稳定身份。
已经发布的key不能重新拿来代表另一个章节。

```json
{
  "key": "continuation/01",
  "title": "把开发过程保存为默认作品",
  "file": "08-持续学习与后续P0/01-把开发过程保存为默认作品.md"
}
```

这是当前清单中的真实章节条目。
修改显示标题不应重建章节UUID。
改变已有key却沿用旧对象，会破坏读本与笔记关联。

## 4. 两条构建链路

第一条链路把课程转成普通作品正文，用于首次默认初始化。
第二条链路保留Markdown，编译图文阅读资源。
二者使用同一份清单和稳定章节身份。

```text
course.json + Markdown
├─ build-learning-course.mjs → learning-course.json → SQLite默认作品
└─ build-textbook.mjs → 教材契约 + 本地PNG → Vite图文读本
```

普通正文支持作者原来的笔记与编辑。
图文读本呈现随包更新的教材原文，不覆盖那份正文。
这解决“课程修订了，但作者笔记必须保留”的冲突。

## 5. 读本资源如何进入包

compileTextbook读取清单和章节Markdown。
解析图片引用，拒绝越界路径与不允许的资源格式。
每张PNG按内容SHA256生成包内文件名。
textbook-vite-plugin.mjs通过虚拟模块提供教材契约。

```text
virtual:rainsoul-textbook
→ book.workId
→ chapters[id,key,title,markdown,images]
→ /learning/<SHA256>.png
```

相同图片内容可共用资源，不必每章复制一份。
阅读组件只接受编译器批准的图片映射。
原始HTML、任意外链和远端图片不会直接变成可执行界面。

## 7. 默认初始化如何避免重复

Worker启动先读取包内learning-course.json。
ensureLearningWork验证课程后初始化或增量补充。
学习作品使用固定UUID与course_key标记。
同名作者作品不能因为标题相同被当作默认课程接管。

已有课程只补没有跟踪过的新卷章。
learning_volume跟踪卷key，learning_seed跟踪章key。
已编辑标题、正文、顺序、归属与删除状态都要保留。
已删整书重启时不会擅自复活。

## 8. 跟做：追加一章的练习流程

以下是维护者练习，先在个人分支操作，不直接污染已发布清单。
新章必须有新key，不复制旧key充当身份。

1. 在对应卷目录新建Markdown。
2. 写学习目标、前置概念、步骤、代码与练习。
3. 在course.json追加对应条目。
4. 引用实际存在的批准截图。
5. 运行课程构建器与读本编译测试。
6. 构建后在隔离目录打开课程核对。

```powershell
npm run test:unit -- tests/unit/learning-course-builder.test.ts tests/unit/learning-seed.test.ts
npm run build
```

教材编译相关测试文件以tests/unit实际清单为准。
不要为了漏图而暂时删掉图片校验后发布。

## 9. 更正教材时如何处理旧笔记

已导入普通正文不能自动覆盖。
更正教学原文会更新只读图文读本；普通正文仍保留作者内容。
重要历史错误还应新增勘误或补充章，明确旧讲法与更正原因。
这样旧笔记上下文可解释，而不是悄悄改写历史。

知识、剧情与伏笔已交付，可手工把模块大纲与数据流关联进去。
本教材先用正文清楚解释源码联系，当前未自动填充整本课程的所有剧情和伏笔关系。
学习作品是普通作品，不要求作者完成课程才能写小说。

## 10. 诊断与练习

| 现象 | 排查方向 | 正确原则 |
| --- | --- | --- |
| 每次启动多一本课程 | 固定ID与标记 | 初始化应幂等 |
| 更新后笔记消失 | 教材与作者正文是否分开 | 不覆盖作者数据 |
| 包内截图缺失 | 编译批准路径与资源输出 | 本地图片随包离线 |
| 新章未出现 | key跟踪、卷或作品删除状态 | 尊重删除，不擅自复活 |

练习一：为什么不用作品标题判定默认课程？
答案：作者可能创建同名作品，也可能给默认课程改名。

练习二：包内读本更新与已有用户正文保存是否同一事务？
答案：不是。读本是包内教材资源，笔记是用户作品持久化内容。

本章检查点：你能画出同源教材进入包内只读阅读与数据库增量初始化的两条路径，并解释已有用户正文保护。
