# 本机作者资料实践

写作工作台不需要账号系统才能显示作者头像与名称。
本章从“头像下面只显示名称”出发，完成界面、IPC、图片校验和本机原子保存的联系。
完成后，你能追踪一次改名到磁盘的全过程，并知道失败时为什么要保留旧资料。

**本章状态（2026-10-09）：**个人资料模块、界面接线和对应测试已实现；项目全部 P0 的最终发布验收仍未完成。
本章的作者名称是内部字段 `penName`，界面不显示“笔名”标签。

## 1. 前置知识

理解第三卷的主进程、preload 与命令白名单。
理解第五卷“内存显示成功”和“持久化成功”之间的区别。
会使用 PowerShell 查看本地文件，但不要随意修改正在使用的用户数据库。

个人资料属于作者，不属于“雨落之后”这一部小说。
切换作品不能切换头像；恢复旧小说版本也不能把作者名称改回旧值。
因此该数据存放在应用目录的 `author-profile.json`，不放入作品 SQLite。

## 2. 先写出数据契约

实际文件 `src/shared/profile.ts` 定义名称和规范头像。
名称去首尾空白，最多 80 个字符；空名称可以保存。
头像在完成规范化后存成 PNG data URL，未设置时为 `null`。

```typescript
export const penNameInputSchema = z.string().trim().max(80, '名称最多 80 个字符');
export type AuthorProfile = z.infer<typeof authorProfileSchema>;
```

界面、preload 和主进程共享该契约，但前端校验不能代替主进程校验。
来自渲染层的未知字段要被严格 schema 拒绝。
否则以后新增功能时，可能不小心把任意文件路径或配置写入权限暴露给页面。

## 3. 一次改名的数据流

```text
侧栏/设置输入
→ use-author-profile.ts
→ preload.setPenName
→ 主进程 IPC 校验
→ ProfileCommands 串行执行
→ ProfileService.setPenName
→ 临时 JSON + fsync + rename
→ 返回 AuthorProfile
→ 界面更新保存结果
```

`ProfileCommands` 用队列协调名称与头像操作。
两次输入或上传和改名同时发生时，不能各自读取旧资料然后相互覆盖。
关闭应用时等待队列 drain；这与作品保存等待是两个独立的职责。

```powershell
Set-Location E:\soulrain
Get-Content .\src\main\profile-commands.ts
Get-Content .\src\main\profile-service.ts
Get-Content .\src\renderer\hooks\use-author-profile.ts
```

读代码时从命令名称往下追，不要只看设置组件。
React 设置页保存输入失败后保留草稿，作者可以修正后再提交。
主进程成功回执才成为新显示资料。

## 4. 为什么临时写入后再改名

直接覆盖 `author-profile.json` 时，写入中断可能留下半份 JSON。
当前实现先使用唯一临时文件，独占创建、写入、刷新，再改名替换目标。
任一步失败应保留之前有效的资料，并清理本次临时文件。

```typescript
descriptor = openSync(temporary, 'wx', 0o600);
writeFileSync(descriptor, JSON.stringify(profile));
fsyncSync(descriptor);
closeSync(descriptor);
descriptor = undefined;
renameSync(temporary, this.file);
```

代码节选来自 `ProfileService.save`。
`wx` 不覆盖已存在的临时文件；`fsync` 是写入刷新；rename 是最后的提交边界。
这不是“对任意硬件故障绝对不会丢数据”的承诺，异常路径仍要用真实文件测试验证。
目录路径及祖先拒绝链接，避免写入跳到非预期目标。

## 5. 头像不是换个扩展名就可信

作者通过系统文件选择器选 PNG/JPEG。
选择器过滤只是方便选文件，实际文件必须进一步检查。
`avatar-selection.ts` 在原生解码前检查文件类型、大小和图片头；超大像素不能等解码完成才拒绝。

```text
文件 ≤16 MiB，拒绝目录与链接
→ 解析静态图片头与尺寸，拒绝超大像素/截断/动画
→ nativeImage 解码
→ 等比例缩小，长边 ≤256
→ 转规范 PNG
→ PNG 内容/CRC/dataURL 校验，最终 ≤1 MiB
→ 原子保存资料
```

不保存作者选择的原路径，原图片移走也不影响头像。
不直接将 SVG 或任意文件内容交给界面。
当前选择器没有开放 WebP：解析头支持不等于当前 Electron 解码已通过实机验证。
格式要同时通过安全检查和实际平台解码，才应作为产品选项开放。

## 6. 跟做：改名与头像重启验证

1. 启动应用，展开侧栏，直接编辑显示名称为“听雨”。
2. 确认头像下只显示“听雨”，没有额外“笔名”标签。
3. 进入设置，上传一张小尺寸静态 PNG/JPEG。
4. 打开“雨落之后”，确认作品标题没有变成作者名。
5. 正常关闭并重启，核对资料仍保留。
6. 在设置移除头像，名称应仍保留。

预期：改名不清头像，移除头像不清名称，不修改默认学习作品。
测试时可以使用隔离数据目录，避免把测试资料写进真实作者目录。
这也是 `tests/desktop/profile.spec.cjs` 使用临时目录的原因。

## 8. 排错与练习

| 现象 | 检查方向 | 正确处理 |
| --- | --- | --- |
| 改名后头像消失 | 更新是否合并旧资料 | 分别变更字段 |
| 上传图片卡住 | 解码前尺寸检查是否缺失 | 在解码前拒绝超限 |
| 资料损坏后被清空 | 读取失败是否当空资料 | 报错并保留原文件 |
| 关闭重启名称回退 | 原子写入与关闭 drain | 等待真实落盘 |

练习一：为什么不能把头像当某部作品的附件？
答案：头像属于作者级配置，小说恢复/删除不能修改作者身份显示。

练习二：只检查 `.png` 扩展名能防止非法文件吗？
答案：不能，扩展名与真实内容可不一致，需要头部、解码与规范 PNG 校验。

练习三：rename 失败时界面应如何表现？
答案：旧资料继续有效，显示原因，保留待修改输入，让作者显式重试。

本章检查点：你能沿 IPC 追踪一次改名，并用失败测试证明它不会破坏旧资料。
