# 结构化知识提取与分类审核

AI 从“雨落之后”提取角色、事件与优美描写后，不应该直接把它们塞进知识库。作者需要看完整内容、出处、类型和分类标签建议，再决定哪些成为自己的储备。本章补充第十章的逐条审核，解释结构化结果与层级分类同名问题。

**本章状态（2026-10-09）：**结构化提取解析、非法格式降级、分类完整路径、标签选择与逐条作者审核已实现并接入回写流程；专项末轮与完整交付门禁待验。模型响应仍采用测试替身，不代表真实云服务已经按格式返回，也不保证提取质量。

## 1. 结构化结果是草稿契约

`src/shared/ai-extraction.ts` 的 `parseAiExtraction` 读取受限JSON，形成 `AiExtractionDraft[]`。类型、建议分类和建议标签都只是建议；作者确认前没有数据库写入。

```json
{
  "items": [{
    "body": "雨落在旧车站，路灯把人影拉长。",
    "type": "passage",
    "source": "第一章 旧车站",
    "category": "景物描写 / 夜景",
    "tags": ["雨夜", "紧张"]
  }]
}
```

解析器接受纯JSON或JSON代码块；对条目数、文字长度和标签数有约束。模型输出不是可信配置文件，不能由它创建类别、执行命令或指定任意作品ID。

## 2. 非法格式为什么保留全文

如果一百条中某条结构错误，逐条过滤“合法”条目可能让作者误认为所有信息都被保留。当前策略是整个结构不符合契约时，降级成一条普通候选，`body`保留模型完整原文，类型显示“待分类”。

作者可以从完整文本中整理内容，再选分类与标签。系统不把格式失败当成已经提取成功，也不静默丢弃部分输出。原始候选仍可阅读，不会自动替换正文。

练习：给解析器一个缺少body的JSON，断言返回单条全文候选；不能只断言数组非空，必须比较原文是否完整。

## 3. 层级分类不能只显示叶子名

“人物描写 / 外貌”和“景物描写 / 外貌”可以具有同名叶子。仅显示“外貌”无法让作者确认归属。

`extractionCategoryPath`从当前类别向父类别遍历，显示完整路径，使用已访问ID集合防止无限循环。`suggestedExtractionCategory`匹配完整路径或唯一名称；出现多个匹配时留给作者选择，不猜测落点。

```text
人物描写 / 外貌
景物描写 / 外貌
```

数据库仍接收稳定 `categoryId`，完整路径只是展示与建议匹配。重命名类别不会把已有条目改到另一个同名类别。

标签也是作品内已维护字典。建议中的已知标签可供选用；未知分类和标签不会自动创建。作者可以先在设置维护字典，再回来整理，不能让模型无审查地扩充本机分类树。

## 4. 一次明确的作者审核

`src/renderer/components/ai-extraction-panel.tsx`对每条候选展示完整内容、出处、类型、分类/标签建议，以及实际类别选择和标签勾选。

作者修改正文、出处、主分类或标签，审核勾选会重置。这样“审核通过”绑定的是最终内容，不是五分钟前看过的另一个草稿。只有勾选且正文非空的条目才能入库。

```text
模型候选 → parseAiExtraction
→ 每条完整草稿＋分类/标签建议
→ 作者编辑并逐条勾选
→ approveAiKnowledge(items)
→ AiCommands 校验候选身份
→ Worker校验基线与当前作品分类/标签
→ 同事务新建知识并保留AI正文来源
```

`src/workers/database/ai-apply.ts`接收最终 `body/source/categoryId/tagIds`，不覆盖已有条目。未指定分类时落到作品“未分类”，不接受其他作品的分类ID。入库同时保留来源作品、章节/段落与版本，供后续追溯。

## 5. 跟做与验收重点

1. 在测试作品设置中建立两个同名叶子类别与两个标签。
2. 用测试替身返回结构化角色/事件/描写候选，打开回写审核界面。
3. 核对类别下拉框显示完整路径；歧义建议保持未选状态。
4. 修改一条知识内容并核对审核自动取消，再选择类别和标签。
5. 逐条勾选，确认只有选中条目入库，已有知识不覆盖。
6. 模拟无效类别、过期候选或事务失败，核对原稿、已有知识与历史均保持。

真实云端模型返回格式与提取质量需要作者自己的授权配置联调。上述自动化采用隔离目录与响应替身，不会替作者发送正文。

## 6. 练习与检查点

练习一：模型建议“外貌”，当前有两个同名叶子，应自动选哪一个？答案：不自动选，让作者看完整路径后决定。

练习二：改标签后是否可以保留此前审核勾选？答案：不可以，最终入库内容改变后应重新审核。

练习三：设计测试验证未知标签不会偷偷创建，并检查入库事务失败后没有部分候选留下。

检查点：你能说明模型建议、作者选择与数据库ID各自的作用，知道结构解析失败为何保留全文，以及一次审核入库的事务边界。
