# 第一章 桌面窗口为什么还需要安全边界

本章状态：隔离窗口、本地协议、单实例和重载限制已实现；完整安装升级验收尚未完成。

Electron 界面显示本地内容，并不意味着可以直接获得 Node 权限。渲染进程将来会展示导入文本、知识片段和模型返回值，任何不受控制的内容都不能自然变成文件读写能力。当前窗口启用 `contextIsolation` 和 `sandbox`，关闭 `nodeIntegration`，预加载层只暴露限定 API。

正式应用使用 `rainsoul://app/` 加载已构建资源。早期 Demo 的 `http://127.0.0.1:4173/` 依赖预览服务；服务没启动，浏览器就会“无法访问站点”。这解释了原型预览问题，但不是正式客户端的数据问题。`npm start` 的桌面窗口不依赖那个 HTTP 服务。

本地协议处理也要验证路径。`src/main/index.ts` 将请求路径解析到 rendererRoot 内，检查 host 为 app，且最终文件在指定目录边界下，才使用 `net.fetch` 读取。不能直接把 URL 拼接成任意系统路径。请求来自同一主窗口主 frame，才允许执行 IPC。

实践步骤：

1. 查 BrowserWindow 的 `webPreferences`，理解各选项保护什么。
2. 找 `setWindowOpenHandler`、`will-navigate`、`will-attach-webview`，确认外部导航不会改变当前信任边界。
3. 找单实例锁，第二次启动聚焦已有窗口，避免多个可写会话。
4. 找 F5/Ctrl+R 限制。页面重载若绕过保存门禁，会销毁尚未落盘草稿，所以不能把它当普通网页快捷键。

示例：某条知识内容含“点击这里打开网站”。未来即使允许安全外链，也应通过明确受控的外链动作处理，不能让正文 HTML 直接触发任意窗口导航；目前没有这种开放能力。

证据：首批桌面验收主动尝试重载并确认草稿仍在；相关设置见 `src/main/index.ts`，记录见 `tasks/desktop-foundation.md`。当前验证只覆盖本机桌面入口，不等于所有恶意输入场景都已专项审计。

练习：列出如果启用 `nodeIntegration: true`，一段错误渲染的脚本会额外得到哪些能力。再指出窄 API 比暴露整个 `ipcRenderer` 少了哪些危险入口。
