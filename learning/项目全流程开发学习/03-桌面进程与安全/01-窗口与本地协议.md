# 第一章 窗口与本地协议

本章状态：隔离窗口、本地资源协议、单实例与重载限制已实现。
本章解释为什么本地软件也需要安全边界。
完整安装升级和所有恶意输入场景不能由本章几个实验替代。

## 学习目标与前置知识

已经知道 Electron 主进程与 React 渲染器的分工。
知道 URL 的协议、主机和路径是不同部分。
本章实验只观察运行行为，不要求修改安全配置。
不要为了调试把 `nodeIntegration` 改成 true。

## 技术基础：进程隔离、URL 与最小权限

### 进程与线程

进程是操作系统运行程序的一种隔离单位，通常有自己的地址空间；线程是同一进程内的执行单位。Electron 的主进程控制窗口，渲染进程绘制页面，数据库 Worker 是 Node 工作线程。它们之间的隔离程度不同，但项目都通过消息交换明确的数据。

“最小权限”是只给某层完成任务所必需的能力。正文编辑器需要键盘输入和受限保存 API，不需要删除任意磁盘文件。关闭 Node 集成能减少页面受攻击后的系统影响范围，但仍须验证每个桥接命令。

### URL 与文件路径的关系

`rainsoul://app/assets/example.js` 包含协议 `rainsoul`、主机 `app` 和路径 `/assets/example.js`。协议处理器把允许路径映射到 `dist/renderer`。它先规范化真实磁盘路径，再确认仍在资源根目录之内。

```text
URL 路径 /assets/a.js → 解析为 dist/renderer/assets/a.js → 允许读取
URL 路径含越界片段 → 规范化后越过 renderer 根目录 → 拒绝
```

只检查字符串“没有 ../”并不充分：编码、不同分隔符与路径规范化都可能改变结果。检查主机和规范化后的目录边界，才是实际源码采用的关键防线。

### CSP 约束的是什么

Content Security Policy 是浏览器对页面资源来源的限制。例如 `script-src 'self'` 限制脚本来源，`connect-src 'none'` 限制页面发起网络连接。它针对不同资源类型分别生效。主进程云端 AI 请求不由页面 CSP 放行，而由主进程的授权和网络服务规则控制。

沙箱、隔离、协议边界和 CSP 组成多层保护；不能因为其中一层存在就删掉其他检查。下面的实践要核对每一层实际配置，避免把“本机文件”误当作“可信内容”。

## 1. 页面为什么不能直接拥有钥匙

界面会展示知识片段、导入稿件和模型返回内容。
这些内容即使来自本机，也可能含有 HTML 或危险链接。
如果页面同时拥有无限制文件读写能力，一次渲染错误可能变成系统操作。

因此窗口关闭 `nodeIntegration`，开启隔离与沙箱。
React界面通过预加载层获得明确 API，而不是整个 Node 环境。
“代码和用户内容在一个窗口出现”不意味着它们拥有相同权限。
这个原则也适用于本教材中的代码示例：示例只能被展示，不能自动执行。

## 2. 核对真实窗口设置

```powershell
Set-Location E:\soulrain
Select-String -Path .\src\main\index.ts `
  -Pattern 'webPreferences' -Context 0,2
```

你应看到类似以下真实配置：

```ts
webPreferences: {
  preload: join(__dirname, 'preload.cjs'),
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true,
  webSecurity: true,
}
```

`contextIsolation` 让预加载的执行环境与页面环境隔离。
`sandbox` 限制渲染进程可接触的系统能力。
`webSecurity` 保留浏览器的安全检查。
这些选项不是可以随意关闭来“解决跨域”的障碍。
如果页面确需新能力，应先定义窄 API，再增加验证。

## 3. 本地协议解决什么问题

旧 Demo 可能通过 `http://127.0.0.1:4173/` 预览。
预览服务停止，浏览器就无法访问那个端口。
正式客户端使用 `rainsoul://app/` 加载已构建资源，不依赖该 HTTP 服务。

```powershell
Select-String -Path .\src\main\index.ts `
  -Pattern 'registerSchemes|protocol.handle|loadURL' -Context 0,3
```

协议处理器将请求限制到渲染器产物目录。
它校验主机与解析后的路径边界，然后通过本地文件读取资源。
不能简单把URL路径拼到磁盘根目录再返回文件。
否则 `../` 等输入可能越过资源目录。

新教材图片也必须由构建白名单进入包内，而非引用任意 `file:` 文件。
路径边界、软链检查与资源白名单应随着资源能力增长持续验证。
本地协议存在，不自动意味着任意文件请求都安全。

## 4. 看懂内容安全策略

```powershell
Get-Content .\src\renderer\index.html
```

找到 `Content-Security-Policy`。
当前策略限制脚本来源、网络连接、框架与对象内容。
代码高亮或图文阅读不应成为放开任意脚本的理由。
Markdown内容中的“脚本代码”应保持文本，图片则必须映射到本地允许资源。

不要把 `unsafe-inline` 样式许可理解成脚本许可。
指令针对的资源类型不同，影响也不同。
当前云端 AI 的网络行为在主进程受控服务层完成，并获得作者逐次授权。
不能直接从文章HTML发起隐蔽正文上传。

## 5. 体验单实例与安全关闭

先打开“雨落之后”，再从资源管理器启动一次程序。
预期已有窗口获得焦点，不创建第二个可写窗口。

```powershell
Select-String -Path .\src\main\index.ts `
  -Pattern 'requestSingleInstanceLock|second-instance' -Context 0,2
```

单实例锁降低多个窗口同时写同一作品的复杂度。
它不能替代数据库事务与版本检查。
真正的并发保护仍需要存储层承担。

在章末输入一个未保存的新句子，按 F5 或 Ctrl+R。
预期应用不会像普通网页那样重载并丢掉当前页面状态。
测试时不要使用任务管理器强制结束作为正常关闭方式。
强制退出是另一种故障场景，需要独立的恢复验证。

## 6. 导航、弹窗和关闭令牌

```powershell
Select-String -Path .\src\main\index.ts `
  -Pattern 'setWindowOpenHandler|will-navigate|will-attach-webview|closeToken' `
  -Context 0,2
```

应用拒绝任意新窗口与页面导航，避免当前信任页面被外部内容替换。
正常关闭时，主进程发出随机令牌，请渲染器先完成保存。
只有合法来源回传匹配令牌，主进程才允许真正关闭。

令牌让旧确认不能误批准新一轮关闭。
但渲染器确认前仍需等待当前操作和保存队列。
第三方内容不能直接发送一个字符串就关闭正在写作的窗口。
这同时涉及来源判断与当前流程状态。

## 常见问题与排查

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| 旧网页端口不可访问 | 是否用Demo地址 | 启动正确预览或使用EXE |
| 第二次启动不出现新窗口 | 单实例正常行为 | 查看已有窗口 |
| F5没有重载 | 已有防丢稿限制 | 用正常关闭重开验证 |
| 图片只在源码下可见 | 是否进入构建白名单 | 检查打包资源，别放开任意路径 |

验收：能解释本地内容仍不应获得无限系统权限。
验收：能核对窗口、协议、CSP和关闭门禁所在位置。
验收：能区分Demo HTTP预览与正式本地协议。

参考：不应。外部链接需要明确受控行为，不能破坏当前页面信任边界。

练习2：有单实例锁，还需revision吗？
参考：需要。重试、异步状态和未来其他写入仍可能造成版本冲突。

参考：主进程请求 → 渲染器保存/等待 → 合法令牌确认后关闭。
