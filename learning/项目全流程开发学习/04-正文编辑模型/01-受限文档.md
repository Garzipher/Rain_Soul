# 第一章 受限文档

本章状态：小说正文只保存段落、文本与段内换行，固定样式已实现。
教材图文阅读使用独立 Markdown 真源，不要求小说正文支持任意 HTML。
你将在独立实验中生成“雨落之后”的两段文档并运行真实校验。

## 学习目标与前置知识

知道 JSON 对象、数组、字符串的基本写法。
已经了解界面调用与存储边界。
本章不需要数据库知识，也不修改真实作品。
所有实验都在编辑器测试中运行，不访问作者数据目录。

## 1. 为什么不直接存网页 HTML

正文作者需要分卷、章节、标题与段落，而不是网页布局工具。
任意 HTML 可能带外部样式、隐藏元素或脚本属性。
同一稿件在屏幕、TXT 与 DOCX 中也不应因为浏览器样式变化而变义。

受限文档将内容结构固定下来。
它描述“这是一个段落，里面有这些文字”，不描述“调用某段脚本”。
固定结构更容易校验、统计、定位与后续导出。
代价是不能直接把所有富文本功能搬进正文。
这是一种明确产品取舍，不是编辑器少一个工具栏就一概称为缺陷。

教材需要代码、表格、截图，所以使用专门的阅读层。
小说编辑与教材阅读有不同需求，不应为教材把稿件 schema 无限放宽。

## 2. 看一份完整合法正文

下面两段是“雨落之后”的练习文档。
UUID 在本示例中固定，方便观察；真实新段落由程序生成独立 ID。

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "attrs": { "id": "8d7c9235-37fb-4c38-8886-c3f95dd0aac3" },
      "content": [
        { "type": "text", "text": "雨停以后，林舟发现一封信。" }
      ]
    },
    {
      "type": "paragraph",
      "attrs": { "id": "17f055e2-63d2-4d1e-9f6e-22d225958714" },
      "content": [
        { "type": "text", "text": "他把信放在桌角。" }
      ]
    }
  ]
}
```

根节点是 `doc`，其 content 是段落数组。
每段 attrs 包含 ID，文字则在 text 节点中。
空正文仍有一个空段落，不能把 doc.content 设成空数组。
段内换行可以使用 `hardBreak`，它不代表创建了新段落身份。

## 3. 阅读真实 schema

```powershell
Set-Location E:\soulrain
Get-Content .\src\shared\document.ts
Get-Content .\src\shared\contracts.ts -TotalCount 22
```

接口让开发期知道形状，Zod 让运行期拒绝非法结构。
`.strict()` 拒绝外来属性，`.min(1)` 要求至少一个段落。
`.superRefine()` 还检查同文档内段落 ID 不可重复。
UUID 格式合法与唯一性是两个条件，不能只检查其一。

## 4. 编写一个可以执行的校验实验

先运行现有测试，确认当前环境正常。

```powershell
npm run test:unit -- tests/unit/document.test.ts
```

然后在个人练习分支中创建 `tests/unit/document-lab.test.ts`。
下面代码完整，可复制运行；不要覆盖现有测试文件。

```ts
import { expect, it } from 'vitest';
import { randomUUID } from 'node:crypto';
import { validateDocument, countDocumentWords } from '../../src/shared/document';
import type { WritingDocument } from '../../src/shared/contracts';

it('两段雨落之后正文合法且计数正确', () => {
  const lines = [
    '雨停以后，林舟发现一封信。',
    '他把信放在桌角。',
  ];
  const doc: WritingDocument = {
    type: 'doc',
    content: lines.map(text => ({
      type: 'paragraph',
      attrs: { id: randomUUID() },
      content: [{ type: 'text', text }],
    })),
  };
  expect(validateDocument(doc).content).toHaveLength(2);
  expect(countDocumentWords(doc)).toBe(18);
  const repeated = { ...doc, content: [doc.content[0], doc.content[0]] };
  expect(() => validateDocument(repeated)).toThrow();
});
```

运行它：

```powershell
npm run test:unit -- tests/unit/document-lab.test.ts
```

预期新增测试通过，合法文档有两个段落、字数18。
18 来自第一段11个汉字与第二段7个汉字，标点不计。
重复 ID 文档应被拒绝，不能靠自动接受绕过校验。
这个实验不会调用保存 API，也不会改“雨落之后”的真实正文。

## 5. HTML 样子的文字仍然可以是文字

用户可能在书中写 `<script>` 这个技术名词。
只要它处于 text 节点，应该按普通文字存储和展示。
危险之处在于把这段文字当 HTML 解释执行。

打开现有测试，找到对应边界用例：

```powershell
Get-Content .\tests\unit\document.test.ts
```

测试允许 text 内容包含 HTML 的字面文本，却拒绝额外可执行属性。
这是安全保留内容，而不是简单删除所有尖括号。
教材代码示例也应遵循同样原则。

## 6. 粘贴内容怎样进入正文

`ChapterEditor` 读取剪贴板中的纯文本，统一换行，再创建段落。
它不导入网页字体、背景色与脚本。
这让从网页复制的内容遵循作品固定样式。

```powershell
Select-String -Path .\src\renderer\components\chapter-editor.tsx `
  -Pattern 'handlePaste' -Context 0,12
```

粘贴与手工输入最终都走受限文档和保存流程。
不能在粘贴处理里直接写库，否则会绕过版本与失败保护。

## 常见问题与排查

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| doc 被拒绝 | 根 type、content 与 UUID | 对照完整 JSON 形状 |
| 两段文字却 ID 重复 | 是否复制同一 attrs | 每个新段使用独立 ID |
| 测试导入失败 | 文件是否放在 tests/unit | 保持示例的目录关系 |
| 网页样式没有保留 | 正文刻意只接纯文本 | 使用固定样式，不绕过 schema |
