# 第二章 段落位置会变，身份为什么不能跟着变

本章状态：基础段落 ID 插件及拆分、合并、复制相关测试已实现；真实知识/伏笔证据尚未接入。

如果用“第 5 段”定位伏笔，在前面插入一段后，原证据就会跳到另一段。稳定段落 ID 让位置和身份分开：移动段落不意味着换身份；复制一段不能让两段共享同一个 ID。后续剧情、引用、AI证据都会依赖这个基础。

`paragraph-ids.ts` 用 Tiptap Extension 增加段落 attrs.id，并在文档事务后遍历段落。缺少 ID 或遇到重复 ID 时生成新 UUID，已有唯一 ID 保留。粘贴 HTML 不信任外部 ID，renderHTML也不把内部标识直接暴露成普通格式属性。共享 schema 再检查全篇没有重复。

实践步骤：

1. 输入两段，记录各自 ID。
2. 在第一段中间按 Enter，观察新增段落获得不同 ID。
3. 复制整段并粘贴，确认复制件不与原段共用 ID。
4. 撤销与重做，确认文档仍有效，没有重复身份。
5. 阅读插件 appendTransaction：仅对 docChanged 做修正，修正事务本身无变化时返回 null，避免无意义循环。

示例：原段 ID 为 P1，内容“雨停了，灯还亮着”。拆成两段时，保留部分继续用 P1，新增部分获得 P2。未来引用 P1 的证据不能自动猜测改指 P2；证据内容发生变化时，需要保留旧摘录并标失效，作者重新关联。这是技术方案中的后续证据规则，当前还没有证据表实现。

边界：基础单元与组件测试通过，不等于千段落、复杂拖移和书签节点组合已经全验收。SP-01 仍需长篇和书签专项实验。
