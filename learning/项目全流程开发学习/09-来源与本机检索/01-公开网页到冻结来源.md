# 公开网页到冻结来源

本章目标是亲手追踪“输入网址→正文预览→知识原文证据”的链路。先读第三卷的IPC与Worker，再阅读第八卷第16章的文件拆书。本轮增加公开文章和粘贴文本两种来源；页面获取需要联网，正文保存、知识搜索与手工审核仍在本机。网页内容进入云端AI拆书时，另外进行逐次授权。

## 1. 原理：网址、HTML、正文分别是什么

网址是访问入口，不是可信正文。HTML还包括菜单、广告、脚本和相关文章。Readability根据文章节点结构提取可读内容；linkedom提供受限文档结构，解析过程不执行网页脚本。主进程负责网络，解析Worker负责有界CPU工作，渲染层只展示冻结段落。这样，保存队列不必等待远端站点返回。

公开网址仍可能指向本机路由器。SSRF是服务代用户请求了本不应访问的地址。仅在输入框检查HTTPS不够：域名可能解析成私网地址，重定向可能跳往内网，DNS再次解析也可能换地址。因此每一跳重新解析并检查所有地址，请求固定到已检查IP，TLS继续验证原域名。响应字节上限、解压后上限及整体期限共同约束压缩炸弹和慢连接。

“取消”不能只关掉加载动画。AbortController停止网络处理，解析取消必须结束实际Worker；迟到结果还要检查当前操作身份，避免旧文章覆盖新文章。测试中的模拟网址不是支持绕过登录、付费或反爬的功能。

## 2. 项目实现：冻结后不再次提取网页

沿下列文件阅读，先看每层的输入输出，再看内部实现：

```text
shared/source-document.ts：来源与段落的严格协议
main/public-web-address.ts：公开HTTPS及IP规则
main/public-web-transport.ts：固定IP、跳转、解压及总期限
main/web-article.ts：Worker创建与实际终止
main/web-article-worker.ts：有界HTML正文解析
main/web-extraction-commands.ts：操作身份、取消、预览
main/freeze-source.ts：冻结来源与SHA-256
workers/database/source-document.ts：事务内证据提交
```

hashVersion=1先将CRLF和CR转换为LF，过滤trim后为空的段落，保留其他空白及Unicode表示。正文哈希计算JSON段落数组的UTF-8字节，不把段落无分隔拼接；否则“ab/c”和“a/bc”会变成相同正文。SHA-256证明已存字节是否改变，不能证明网站作者、版权或内容真实性。

```typescript
// 源码节选：freeze-source.ts。ID在首次冻结时生成，重启不重新生成。
const bodyHash = sha256(JSON.stringify(paragraphs.map(segment => segment.text)));
const segments = paragraphs.map((segment, index) => ({
  id: randomUUID(), ordinal: index + 1, text: segment.text,
  textHash: sha256(segment.text),
}));
```

source_document保存标题、原始与最终网址、获取时间及哈希；source_segment保存段落原文。knowledge_source把作者审核的知识关联到具体段落。AI讲解独立存learning_annotation，不能把AI生成句子冒充原著。origin_json继续记录跨作品复制出处，不能把网页来源塞进去替代证据表。

## 3. 跟做：不依赖真实站点的第一份素材

1. 创建练习作品，进入拆书工具，选择粘贴来源。输入标题“合成雨景”和两段自己写的文字，读取预览。
2. 观察左边原文列表及右边审核区分别滚动；超过20段时分页。分页仅改变显示，不能重建来源ID。
3. 选中一段，填写分类与学习笔记，核对出处后确认入库。再打开知识卡，检查原文与讲解各自可追溯。
4. 使用自己有权访问的公开文章试网址获取。先查看原始网址、最终网址、标题与段落，确认提取质量后再审核；失败可改用粘贴，程序不会自动重发。

## 4. 拓展练习

### 实践补充：区分网页失败发生在哪一层

2026-10-12 排查中，同一客户端能获取 MDN 和 Project Gutenberg，维基文库连接则被重置。这说明需要分别观察地址解析、连接、响应、正文解析，不能把某一个站点不可达推断成所有网页功能失效，也不能仅延长等待时间。

DNS 把域名解析成 IP。`ENOTFOUND` 通常表示未找到域名，`EAI_AGAIN` 表示解析暂时失败；连接阶段的 `ETIMEDOUT`/`ESOCKETTIMEDOUT` 表示等待超时；`ECONNRESET` 表示连接被提前重置，可能来自网站访问策略或网络线路，仅凭此代码无法确定谁实施了限制。

项目在 `public-web-transport.ts` 的统一 catch 中读取错误码，用白名单映射成固定中文提示，建议重试、粘贴或本地文件。原始异常可能包含 URL、远端数据等信息，因此不直接把 `error.message` 显示出来。未知错误继续脱敏。用户取消和30秒总期限先判断，避免取消时的底层连接错误覆盖“已取消”提示；总时限不随重定向重置。达到总时限时界面明确显示“超过30秒，已停止”，并给出粘贴/本地文件回退路径。

跟做顺序：先在 `public-web-transport.test.ts` 注入带错误码和敏感原始消息的失败，确认旧实现不能区分原因；再实现固定文案映射。分别从 DNS 和请求入口注入，检查别名、未知错误以及取消/期限与网络错误同时发生时的优先级。最后使用隔离数据目录打开真实包，观察预览或提示；真实站点结果随网络变化，不能成为稳定单元测试的依赖。

练习：给模拟异常加上任意 API Key 字符串，确认所有输出都只含固定文案；解释为什么连接重置不能通过放宽公网 IP、关闭 TLS 校验或自动重试来“修复”。再对比“错误提示可理解”与“目标网站能成功获取”这两项不同的验收结论。

将一段文本的换行从CRLF改成LF，比较规范正文哈希；再在句末加一个空格，解释为何哈希改变。把两段合成文本换顺序，检查段落数组哈希是否变化。给取消解析用例补一个Worker退出断言，比较“Promise拒绝”和“实际工作已终止”的区别。最后画出网络获取、解析、保存三个独立队列，标注取消信号与迟到结果检查位置。
