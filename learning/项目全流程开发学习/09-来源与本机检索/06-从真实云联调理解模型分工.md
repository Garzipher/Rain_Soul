# 从真实云联调理解模型分工

学习目标：区分生成模型、嵌入模型和浏览器渲染；能沿 RainSoul 的代码解释一次真实请求；理解如何评价结果，而不只看接口有没有返回。

## 一、先认识三种工作

聊天模型输入文字，输出新的文字。会话、润色、续写和拆书建议都属于这类任务。模型不会自动拥有你的知识库，程序必须挑选参考并放入本次发送材料。

嵌入模型输入文字，输出一组数字，称为向量。意思相近的文本往往得到方向相近的向量。“人物独自在空房等待”与“用环境表现孤独”没有完全相同的词，却可能被找在一起。RainSoul 的 BGE-small 中文量化模型输出 512 个数字；它负责寻找写作参考，不能写出新的段落。

浏览器渲染输入网页地址，加载页面并运行 JavaScript。某些网站最初只返回空壳，文章需要脚本加载才出现；Readability 再从页面中提取正文。它不需要聊天模型，也不等于逆向爬虫。公开页面仍可能因网络、验证码或访问限制失败；本功能不绕过登录或付费限制。

## 二、顺着项目看一次请求

以“参考知识库续写”为例，界面先调用 `window.rainSoul.prepareAi`。预加载层把明确的命令送到主进程；`ai-commands.ts` 冻结作品版本，`ai-context.ts` 挑选正文范围，`ai-reference.ts` 添加作者选择的知识。

`ai-service.ts` 把操作要求和材料整理为 messages，并生成请求哈希和确认令牌。此时尚未发送。作者看到服务、模型、范围和计费提示后，`executeAi` 才允许继续。主进程读取系统加密的凭据；`ai-transport.ts` 通过 HTTPS 发送兼容聊天接口的请求。

理解连接方式时，只需看这个不含凭据的结构：

```json
{
  "model": "dots-studio/dots-3-note-preview:free",
  "stream": false,
  "max_tokens": 2048,
  "messages": [
    {"role": "system", "content": "依据上下文给出续写候选"},
    {"role": "user", "content": "作者确认的原创正文及参考"}
  ]
}
```

Authorization 请求头由主进程读取凭据后构造，不能把真实 Key 写进教程、脚本或 Git。返回的文字先成为候选；作者确认应用时，数据库检查版本并创建保护快照。这解释了为什么“生成成功”和“原文已修改”是两件分别验证的事。

## 三、真实测试告诉了我们什么

2026-10-13 的原创短样稿联调中，`openrouter/free` 返回了“User Safety: safe”。接口连通了，但没有完成写作任务。因此不能把 HTTP 成功当作产品效果通过。

切换固定免费的 Dots 模型后，中文会话、雨夜续写、拆书建议返回成功。续写生成后原文未变化；拆书摘录通过逐字核验，分类 ID 属于发送字典，手法、场景和练习齐全。随后只在隔离样稿中确认应用，检查新增快照与知识入库。

会话回复没有遵守 120 字要求，说明模型仍会偏离指令。免费 Gemma 端点本次受限，也说明公开标价为零不保证每次都有容量。详细证据见项目 `tasks/real-cloud-validation-2026-10-13.md`；未测试的云操作不能写成通过。

## 四、亲手跟做

1. 新建测试作品，写一段原创雨夜场景，记录当前内容和版本。
2. 添加一条原创动作描写知识，注明测试来源。
3. 在续写预览中检查只包含你确认的章节与参考；取消一次，确认正文未变化。
4. 重新预览并发送，先阅读候选，再决定是否应用。应用后检查快照和正文。
5. 在拆书页粘贴原创素材，分析后逐字对照摘录。没有逐条批准前，知识库应不增加条目。

云测试会使用服务额度；本机语义检索仅使用已安装模型和本地知识，不需要 API Key。不要用未发表作品做随意联调。

## 五、拓展练习：设计灰字原句补全

假设知识库有“雨夜在盛夏后，总是使人哗然转变”。作者输入“雨夜”时，可以用前缀匹配找到余下文字，作为虚拟灰字显示；Tab 接受后才写入正文，Esc 关闭。虚拟文字不计字数、不自动保存，也不能抢占中文输入法的候选操作。

这属于原句引用补全，匹配即可实现。若想写出符合当前故事的新句子，则需要生成模型，还要处理授权、网络延迟和继续输入后取消过期结果。Continue 的补全实现将停顿、缓存、光标上下文和取消分开处理，可阅读其 `core/autocomplete` 模块理解原因。该交互尚未在 RainSoul 实施。

进一步练习：列出“输入法组合中、光标移动、正文已变化、参考已删除”四种情况下，灰字提示应怎样消失；解释为什么接受原句时还应展示出处。

## 六、本机聊天模型的取舍

本机生成模型能在断网时进行会话或续写，但文件和推理内存比 24.5 MB 检索模型大得多。本机约 8 GB 内存、i5-4460，可先评估 Ollama 的 Qwen3 0.6B（下载约 523 MB）或 1.7B（下载约 1.4 GB）。下载体积不等于运行内存，还要留出上下文缓存、程序与系统的空间；中文效果与速度必须实测，不承诺等同云端大模型。模型标签和体积可查 [Ollama Qwen3](https://ollama.com/library/qwen3)，本轮没有下载聊天权重。

当前产品云适配层要求公开 HTTPS 地址，不能直接填入 Ollama 的 localhost 地址；后续需独立本机适配和权限设计。本轮没有安装本机聊天模型。比较时记录冷加载、首字延迟、总耗时、内存和三类写作任务效果，再决定是否值得内置。
