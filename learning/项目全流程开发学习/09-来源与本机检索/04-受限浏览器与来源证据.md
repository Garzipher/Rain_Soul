# 受限浏览器与来源证据

本章学习如何让不可信网页执行脚本，同时保护写作窗口、作品文件和网络边界。实现代码已经接入，但正式按钮仍受构建资格控制。读懂程序与证明它安全是两个需要分别完成的任务。

## 1. 先理解浏览器的两条工作链

静态获取只下载 HTML，然后把它当数据解析。若网页把正文留给 JavaScript 生成，初始 HTML 可能只有空容器。浏览器渲染会解析 HTML、加载脚本、执行代码，再生成 DOM。它能处理更多页面，也会运行来源网站提供的程序。

Electron 的 BrowserWindow 提供 Chromium 页面，主进程提供文件、窗口等桌面权限。`nodeIntegration=false` 让网页不能直接使用 Node，`sandbox=true` 启用 Chromium 沙箱，`contextIsolation=true` 分离页面与应用的 JavaScript 环境。本项目还不给素材窗口 preload，因此页面没有 RainSoul IPC API。

这些选项不能单独证明网络隔离。脚本仍可能通过 fetch、WebSocket、导航、媒体等途径发起请求。项目把网页放进一次性非持久 session，再建立受控 HTTPS 获取通道和拒绝代理；每种请求的实际走向仍需要在真实 Electron 中验证。

## 2. 从原理到项目链路

```text
拆书页：作者明确选择并确认渲染
  → web-extraction-commands.ts：资格、操作ID与模式校验
  → render-resource-broker.ts：下载初始HTML，锁定最终origin
  → restricted-web-renderer.ts：独立隐藏窗口与主进程期限
  → render-network-guard.ts：协议处理、权限、CSP与拒绝代理
  → render-error-observer.ts：观察脚本及接口失败
  → render-dom-capture.ts：有界遍历与序列化
  → 正文解析Worker：提取段落
  → 来源预览：作者审核后入库
```

### DNS 校验为何还需要固定 IP

只验证域名一次，随后再让网络库解析，可能得到不同地址。broker 检查全部 DNS 结果均为公网地址，然后固定已校验 IP 建连，TLS 仍校验原域名。每次重定向重复这个过程，初始最多三跳；页面子资源不能离开初始获取结束后的 origin。

子请求只允许同源 HTTPS GET。页面请求头不直接转发，Cookie、Authorization、作者正文和云 Key 都不进入资源通道。请求类型由 webRequest 与协议处理协作核对，不能从协议处理接口猜测“这是脚本还是图片”。

### 限额为何要在入队前检查

四个请求正在执行时，页面仍能瞬间生成大量排队请求。若只在出队后计数，内存队列可能失控。broker 在进入队列前预留请求预算，重定向继续计数，共享取消和期限。单响应与总响应同时限制压缩和解压后字节，防止小压缩包展开成巨大内容。

政策 v1 总期限为40秒、初始获取最多30秒；80请求、4并发；DOM节点与属性合计最多20,000、UTF-8序列化最多5 MiB。`renderLimits` 是主进程冻结常量，页面与IPC不能提高它。DOM捕获先遍历计数，再逐段有界序列化，不先生成完整 outerHTML。

网页字节未必是UTF-8。`restricted-html-encoding.ts`核对HTTP、BOM及文档编码声明：UTF-8与支持的GB系列可严格解码，声明冲突、空声明、损坏字节或转换超限则拒绝；规范正文和meta使用UTF-8。broker保留原解压bytes作为来源证据，另用bodyBytes发送给浏览器并重算响应长度；转码增长也计入容量。这样修正中文显示不会偷偷改变rawHash所代表的对象。可跟做`restricted-html-encoding.test.ts`里的GBK、冲突和预算边界，再追踪guard与renderer如何各自使用两份字节。

### CSP、失败观察与完整正文

CSP 可在网络请求进入拦截器前拒绝脚本或接口。仅观察 broker 请求成功，可能把缺失正文的页面误当成功。项目在首次导航前安装隔离世界观察器，核对随机标识、frame与执行上下文，限制报告长度；脚本、fetch/XHR失败会拒绝结果。

原站 CSP 与项目 CSP 共同生效，项目不放宽网站政策。图片、字体等资源限制可以显示警告；正文脚本或接口失败不能用一段残缺正文冒充成功。功能因此不适合依赖跨源接口、登录或验证码的页面。

## 3. 生命周期也是安全逻辑

主进程负责40秒看门狗，因此页面 `while(true)` 不能阻止主进程计时。终止前后核对 renderer 的 PID 与 creationTime，确认它独立于写作窗口。清理失败阻止下一任务，不能把遗留会话继续复用。

取消时，安装 guard 或观察器可能仍在异步等待。程序跟踪安装Promise，迟到资源也要关闭；清理有独立期限。窗口销毁与 DevTools 协议移除观察器的顺序必须实测：先销毁窗口可能让未完成的协议命令失败。本轮真实Electron夹具揭示了这一问题，修复与证据写入任务记录。

## 4. 三个 hash 各证明什么

| 字段 | 对象 | 用途 |
| --- | --- | --- |
| rawHash | 初始响应原字节 | 核对下载材料，转码不重定义它 |
| renderedDomHash | 受限渲染后的序列化DOM | 区分脚本执行后的页面 |
| bodyHash | 提取并冻结的正文 | 审核摘录、去重及检索缓存 |

来源捕获记录保存方式、捕获时间、政策版本和渲染DOM hash；资源限制警告在本次预览显示。作品库 v8 使用独立 `source_capture` 关系。新快照 payload3 保存该关系，旧 payload1/2 先核对原始hash，再在内存补空；旧记录显示未知，不推测历史获取方式。跨作品复制重新映射关系ID，保留来源含义。

## 5. 跟做：逐层检查，避免读取真实稿件

使用临时练习作品与受控网页，先看默认静态获取，再观察依赖脚本的夹具。检查取消后旧草稿仍存在、迟到结果没有替换预览，以及当前构建未通过资格时按钮禁用。不要用作者未发表作品或真实Key进行网络反例实验。
