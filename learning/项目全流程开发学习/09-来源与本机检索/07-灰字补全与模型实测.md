# 灰字补全、正文等待与模型实测

学习目标：分清原句提示与生成式续写，理解编辑器装饰、撤销分组和有界等待，并学会从真实输出判断模型质量。

## 一、原理：看见的文字未必属于文档

编辑器保存的是文档树，界面渲染的是DOM。ProseMirror的Decoration可把提示放在光标旁，却不创建文档节点。好比课本的便签：看得到，正文没有改变。RainSoul灰字接受前不进入JSON、不计字数、不触发保存；按Tab后才插入普通文本。

聊天模型根据上下文生成新内容，BGE把文本变成向量以寻找相近知识，前缀匹配则查找已保存的原句。这三条流程承担不同工作。写下“雨夜”后提示“里，灯光像一枚孤独的星。”是知识原句匹配，不能据此判断是否符合剧情。AI续写使用作者授权的正文、大纲、伏笔、写作特点及知识参考，生成候选后仍需对比确认。

## 二、项目应用：从输入到接受

`knowledge-completion.ts`取当前句片段，拒绝太短、空白结尾和已删除知识。中文至少两字符，纯英文数字至少三字符；最多扫描20万字符、展示160字符余句。这是本机确定性匹配，没有网络请求。

`knowledge-ghost-extension.ts`在输入停顿400ms后查询，用`Decoration.widget`绘制灰字与出处。光标移动、选区、失焦、右键、中文输入法组合和知识刷新会清理候选。按Tab前再次核对段落位置、知识版本与候选内容，避免把陈旧参考写入正文。

```ts
// 接受前是DOM装饰；接受时才变成一个独立的正文修改。
view.dispatch(closeHistory(view.state.tr)
  .insertText(candidate.suffix, position));
```

`closeHistory`把接受操作与刚输入的前缀隔离。否则400ms停顿短于默认500ms历史分组窗口，撤销补全可能连“雨夜”一起撤掉。无匹配时也不能反复派发空装饰事务，否则插件会自行每400ms重新查询。查询应由输入、选区、聚焦和知识刷新触发。

`ChapterEditor`接收当前作品知识；`WritingWorkspace`打开AI工具时暂停灰字，`AiWorkspace`还报告生成、待确认和候选待审核状态。因此关闭AI面板但保留候选时仍暂停，放弃或应用候选后才恢复。

## 三、网页为什么要等待

浏览器load完成可能只得到文章空壳。网络短暂安静之后，网页脚本还可能延迟填充正文。`render-content-ready.ts`每250ms捕获有界DOM并解析正文；正文连续稳定750ms、网络也安静后，再捕获复核一次。额外等待最多5秒，整次40秒总期限继续生效。

固定睡眠只能猜测时机，正文就绪轮询能等待实际内容，但仍是有界启发式。页面以后追加、跨源资源限制、登录验证和初始DNS/TLS错误不会因此自动解决。正式受限渲染的资格门禁也不会因等待测试通过而自动开启。

## 四、模型实测：运行成功不等于效果合格

本机i5-4460、8GB内存，Qwen3-0.6B Q8_0使用llama.cpp CPU四线程、1024上下文、关闭思考模式。加载约1.76秒，峰值工作集约873MB；短会话约10.8 token/秒，短续写约5.68 token/秒。速度不能直接换算中文字/秒，因为分词长度不同。

续写复述原文、未满足长度要求，拆书把普通雨景误判为拟人并给出不准确场景。JSON和逐字摘录校验通过，只证明格式和来源有约束，不代表教学解释正确。本轮没有把0.6B接入产品，1.7B则加载9.35秒、约2.82～3.24 token/秒、峰值工作集约2.02GB，续写与拆书解释有所改善但尚不推荐默认内置。详细来源、校验和计时见`tasks/local-chat-model-evaluation-2026-10-14.md`。

## 五、亲手跟做

1. 新建测试作品，把“雨夜里，灯光像一枚孤独的星。”保存为知识，出处填“原创练习”。
2. 在空章节输入“雨夜”，将光标留在段落末尾，停顿后观察灰字及出处。本章仍是2字，磁盘原文仍只有“雨夜”。
3. 按Tab接受，再撤销：应保留“雨夜”。按Esc后同一位置不继续提示；移动光标再回末尾可重新提示。
4. 打开AI工具，观察灰字消失。生成候选后即使关闭面板也不恢复；放弃候选后可恢复提示。
5. 运行`npx vitest run tests/unit/knowledge-ghost-editor.test.tsx --pool=threads --maxWorkers=1`，查看快速接受撤销和无匹配不循环的回归。

## 六、拓展练习与答案

**练习1：**为何不能把灰字直接作为临时text节点存入正文，再在导出时过滤？

答案：自动保存、字数、搜索、快照和AI上下文都会提前读取它，过滤一个出口不足以保护全部数据流。装饰层把未接受候选留在显示层，约束更集中。

**练习2：**本机模型返回合法JSON，为什么不能自动把“拟人手法”写入教学知识？

答案：格式校验只能证明字段存在。手法判断需要语义与文学依据，模型可能解释错误；候选须人工审核，原文摘录还要逐字核对。

**练习3：**把等待改成无限循环，会提高网页成功率吗？

答案：未必。永远不完成的脚本、持续追加和安全拒绝都可能存在。必须有容量、取消和总期限，失败保留已有作品并提供粘贴正文或文件导入。
