# 灰字补全、正文等待与模型实测

学习目标：分清原句提示与生成式续写，理解编辑器装饰、撤销分组和有界等待，并学会从真实输出判断模型质量。

## 一、原理：看见的文字未必属于文档

编辑器保存的是文档树，界面渲染的是DOM。ProseMirror的Decoration可把提示放在光标旁，却不创建文档节点。好比课本的便签：看得到，正文没有改变。RainSoul灰字接受前不进入JSON、不计字数、不触发保存；按Tab后才插入普通文本。

聊天模型根据上下文生成新内容，BGE把文本变成向量以寻找相近知识，前缀匹配则查找已保存的原句。这三条流程承担不同工作。写下“雨夜”后提示“里，灯光像一枚孤独的星。”是知识原句匹配，不能据此判断是否符合剧情。AI续写使用作者授权的正文、大纲、伏笔、写作特点及知识参考，生成候选后仍需对比确认。

## 二、项目应用：从输入到接受

`knowledge-completion.ts`取当前句片段，拒绝太短、空白结尾和已删除知识。中文至少两字符，纯英文数字至少三字符；最多扫描20万字符、展示160字符余句。这是本机确定性匹配，没有网络请求。

`knowledge-ghost-extension.ts`在输入停顿400ms后查询，用`Decoration.widget`绘制灰字与出处。光标移动、选区、失焦、右键、中文输入法组合和知识刷新会清理候选。按Tab前再次核对段落位置、知识版本与候选内容，避免把陈旧参考写入正文。

```ts
// 接受前是DOM装饰；接受时才变成一个独立的正文修改。
view.dispatch(closeHistory(view.state.tr)
  .insertText(candidate.suffix, position));
```

`closeHistory`把接受操作与刚输入的前缀隔离。否则400ms停顿短于默认500ms历史分组窗口，撤销补全可能连“雨夜”一起撤掉。无匹配时也不能反复派发空装饰事务，否则插件会自行每400ms重新查询。查询应由输入、选区、聚焦和知识刷新触发。

`ChapterEditor`接收当前作品知识；`WritingWorkspace`打开AI工具时暂停灰字，`AiWorkspace`还报告生成、待确认和候选待审核状态。因此关闭AI面板但保留候选时仍暂停，放弃或应用候选后才恢复。

## 三、网页为什么要等待

浏览器load完成可能只得到文章空壳。网络短暂安静之后，网页脚本还可能延迟填充正文。`render-content-ready.ts`每250ms捕获有界DOM并解析正文；正文连续稳定750ms、网络也安静后，再捕获复核一次。额外等待最多5秒，整次40秒总期限继续生效。

固定睡眠只能猜测时机，正文就绪轮询能等待实际内容，但仍是有界启发式。页面以后追加、跨源资源限制、登录验证和初始DNS/TLS错误不会因此自动解决。正式受限渲染的资格门禁也不会因等待测试通过而自动开启。

## 四、模型实测：运行成功不等于效果合格

本机i5-4460、8GB内存，Qwen3-0.6B Q8_0使用llama.cpp CPU四线程、1024上下文、关闭思考模式。加载约1.76秒，峰值工作集约873MB；短会话约10.8 token/秒，短续写约5.68 token/秒。速度不能直接换算中文字/秒，因为分词长度不同。

续写复述原文、未满足长度要求，拆书把普通雨景误判为拟人并给出不准确场景。JSON和逐字摘录校验通过，只证明格式和来源有约束，不代表教学解释正确。本轮没有把0.6B接入产品，1.7B则加载9.35秒、约2.82～3.24 token/秒、峰值工作集约2.02GB，续写与拆书解释有所改善但尚不推荐默认内置。详细来源、校验和计时见`tasks/local-chat-model-evaluation-2026-10-14.md`。

## 五、亲手跟做

1. 新建测试作品，把“雨夜里，灯光像一枚孤独的星。”保存为知识，出处填“原创练习”。
2. 在空章节输入“雨夜”，将光标留在段落末尾，停顿后观察灰字及出处。本章仍是2字，磁盘原文仍只有“雨夜”。
3. 按Tab接受，再撤销：应保留“雨夜”。按Esc后同一位置不继续提示；移动光标再回末尾可重新提示。
4. 打开AI工具，观察灰字消失。生成候选后即使关闭面板也不恢复；放弃候选后可恢复提示。
5. 运行`npx vitest run tests/unit/knowledge-ghost-editor.test.tsx --pool=threads --maxWorkers=1`，查看快速接受撤销和无匹配不循环的回归。

## 六、拓展练习与答案

**练习1：**为何不能把灰字直接作为临时text节点存入正文，再在导出时过滤？

答案：自动保存、字数、搜索、快照和AI上下文都会提前读取它，过滤一个出口不足以保护全部数据流。装饰层把未接受候选留在显示层，约束更集中。

**练习2：**本机模型返回合法JSON，为什么不能自动把“拟人手法”写入教学知识？

答案：格式校验只能证明字段存在。手法判断需要语义与文学依据，模型可能解释错误；候选须人工审核，原文摘录还要逐字核对。

**练习3：**把等待改成无限循环，会提高网页成功率吗？

答案：未必。永远不完成的脚本、持续追加和安全拒绝都可能存在。必须有容量、取消和总期限，失败保留已有作品并提供粘贴正文或文件导入。

## 七、分享模型与保护凭据

BGE-small按MIT许可可分发，仓库保留来源、固定版本、hash及完整许可，实际权重可作为GitHub Release或安装器附件。接收方的本机检索不需要作者的云Key。Key由Electron safeStorage/Windows DPAPI保存在仓库外；ignore与包审计防止配置被提交或打包。忽略规则不能撤销聊天里曾公开的Key，公开后仍需在服务商后台更换。

## 八、排错实践：先观察，再判断失败属于哪一层

本轮灰字桌面回归曾在关闭AI工具后失败。关闭动作先等待保存，再由界面恢复焦点，测试不能把按键调用返回当作对话框已经关闭。最初使用Home键，却发现真实光标仍在偏移2；改为等待对话框消失、正文可编辑且聚焦，再按左方向键核对偏移1、右方向键核对偏移2，才观察灰字恢复。这里修的是测试的同步和前提，没有给产品强行设置光标来伪造通过。

搜索性能也曾出现正文结果约200ms完成、显示双帧却耗时近2秒的现象。每个样本分别记录DOM耗时、第一帧、第二帧和窗口可见性，才能区分查询、渲染与显示节流。进一步阅读Playwright的Electron loader，发现它会重写`disable-features`，覆盖测试传入的遮挡控制参数。测试专用预加载必须在loader之后、Electron ready之前合并参数，并读取实际运行值核对。正式程序不引入这个测试预加载，性能门槛也没有因此放宽；失败轮保留，后续真实结果另行记录。

网页资格工具的另一处问题是`exit`事件不能保证输出管道和Windows子进程树都已关闭。超时后`taskkill /T /F`还在处理子进程，直接递归删除浏览器档案可能遇到EBUSY并掩盖最初的超时。工具现在等待Electron的`close`和taskkill的`close`，清理无法证明完成时保留档案及原始诊断。练习：为什么不能在这里仅增加固定三秒睡眠？答案：进程退出速度取决于负载，固定睡眠没有证明句柄已释放；应等待实际生命周期事件，并为等待设置期限。

## 九、排错实践：运行版本与测试目录

### 先解释技术原理

源码修改后，旧EXE不会自己更新。Electron目录包的`RainSoul.exe`负责启动，真正的应用代码打包在旁边的`resources/app.asar`中；必须重新构建整个目录包或安装器，才能使用新代码。Git只记录受控的源码和文档，不会因为设置了`.gitignore`就删除已经提交过的文件；停止跟踪需使用`git rm --cached`，本机文件仍然保留。

测试源码与测试结果也不同。`tests/`中的断言描述保存、恢复、引用和数据隔离应有的行为，修改功能时需要重复运行，应该提交。截图、trace、日志和覆盖率是执行生成的证据，可能很大、包含本机路径，应存到忽略目录，而不是混进应用安装包。

### 本项目中的一次真实排错

作者从`release/current/win-unpacked`启动后，知识库显示开发中。核对两个ASAR内的`package.json`，发现`current`仍是1.1.0，而已验收包是1.3.1；目录名不能证明版本。同时，最新界面在尚未选择作品时也错误地使用了未交付占位页。两处原因必须分别处理：统一当前程序入口；把缺少作品上下文改成明确的选择提示。

回归测试先在真实App中点击知识库，观察旧占位页导致断言失败，再修正未选作品分支；随后验证“前往作品集→打开作品→知识库”能显示原有条目。已有作品的加载、错误重试和编辑路径保持原有实现。桌面测试补同一路径，不能只断言提示文字改变。

### 跟做与检查

1. 从`release/current/win-unpacked/RainSoul.exe`启动当前包，先退出历史实例。历史包存入`release/archive`，保留升级验收基线。
2. 运行`npm run test:unit`，阅读`tests/`里的输入与断言；运行完整验收使用`npm run verify`。
3. 在`.artifacts/tests/`查看新的桌面与Demo证据，在`.artifacts/coverage`查看覆盖率，在`.artifacts/logs`保存命令日志。历史根目录证据已迁至`.artifacts/archive/root-20261014`，原文件名保留。
4. 用`git check-ignore -v .artifacts/tests/example.json`核对生成物被忽略，再用`git ls-files tests`核对测试源码仍受版本控制。

**练习：**为何把`tests/`整体加入ignore不能改善软件质量？答案：它只隐藏回归规范，让其他开发者和CI无法复验；正确做法是保留测试代码，把生成的结果集中存放并忽略。`.gitignore`也不会减少磁盘占用，整理本机文件仍需明确归属和可追溯的搬迁清单。
