## 技术基础：JavaScript、React 与桌面运行时

### 一门语言为何会出现在不同层

JavaScript 是运行时实际执行的语言，TypeScript 在其上增加开发期类型。浏览器的 JavaScript 能操作 DOM，但没有任意磁盘权限；Node.js 的 JavaScript 有文件和线程 API，却没有浏览器页面。语言相同不代表运行环境相同。

Electron 包含 Chromium 渲染器与带 Node 能力的主进程。React 运行在渲染器，处理页面；主进程运行本地服务；数据库 Worker 在单独线程执行同步 SQLite。三个地方不能互相拿普通函数引用随意调用，而要通过消息契约合作。

### React 的渲染思想

React 用组件描述“某个状态下页面应该是什么”。用户点击或输入后更新状态，React 比较前后输出并更新 DOM。不要手动修改 DOM 后期待 React 记住变化；下一次渲染可能根据旧状态把它覆盖。

```tsx
// 独立教学组件，不替换项目文件。
import { useState } from 'react';
export function TitleLab() {
  const [title, setTitle] = useState('雨夜来信');
  return <input value={title} onChange={event => setTitle(event.target.value)} />;
}
```

`title` 是本次渲染读取的值，`setTitle` 请求更新。`onChange` 读取输入框值，再驱动下一次渲染。这个组件退出后不保存任何数据，恰好说明 UI 状态与持久化之间还需要保存链路。

### SQLite 与服务器数据库的区别

SQLite 将数据库放在应用可管理的本地文件中，没有一个必须启动的数据库服务器。应用使用 SQL 查询，事务保证多条改动一起完成或一起回滚。它适合本机单用户作品，不能由此推断适合多端同时编辑同一文件。

`better-sqlite3` 是 Node 原生模块，提供同步接口。调用 SQL 时会占用线程，因此项目把它放入 Worker；同步不等于整个 UI 必须同步等待。主进程返回 Promise，React 等待回执时仍可展示状态。

### 为什么选这条学习路线

React/TypeScript 训练界面、数据建模与异步调用，Electron 训练权限边界，SQLite 训练关系与事务，测试训练可复核证据。Python/FastAPI 更适合独立研究模型输入输出和 HTTP 服务。本项目把它作为学习扩展，当前客户端不依赖 Python。

## 1. 先理解分工，再记框架名称

React 管理你看到的作品卡片、章节导航和编辑状态。
TypeScript 给这些状态与调用规定形状，帮助在运行前发现不匹配。
Electron 提供窗口和受控的本地能力，把网页界面组成桌面程序。
SQLite 将作品内容以事务方式存到本机文件。

可以把它想成一间写作室：
React 是桌面和抽屉的布局，TypeScript 是抽屉上的规格说明。
Electron 是房门和钥匙管理，SQLite 是有登记规则的档案柜。
类比只帮助入门；真正边界仍以进程、数据格式和权限检查为准。

“全部写在一个页面里”虽然容易做演示，却很难保证失败保护。
“再加一个后端服务”也不会自动让系统更专业。
当前目标是在普通 Windows 用户环境中完成可靠的本地写作。
因此主进程和数据库 Worker 已足够承担首批本地能力。

## 2. 检查环境，不靠猜测

```powershell
Set-Location E:\soulrain
node --version
npm --version
node -p "process.platform + ' ' + process.arch"
Get-Item .\package.json
Get-Item .\package-lock.json
```

预期平台与架构输出 `win32 x64`，Node 版本以 `v24.` 开头。
如果你在其他架构或系统上运行，不能直接照用本章的 Windows 交付结论。
Node 版本正确也不代表 Electron 内的 Node 完全相同。
这正是原生 SQLite 模块需要关注运行时兼容性的原因。

## 3. 按锁文件准备依赖

在已经安装好的工作区，可以直接进入下一步。
首次准备或需要恢复完整依赖时执行：

```powershell
npm ci
npm run typecheck
```

`npm ci` 使用 `package-lock.json` 中的锁定关系。
它会重建依赖目录，执行前不要让应用或测试仍占用这些文件。
不要改成 `npm install electron@latest` 来碰运气。
那会改变版本组合，排错对象从一个问题变成多个变化。

`typecheck` 成功通常没有长篇输出，以退出码为准。
失败时先读第一条类型错误，不要添加 `any` 一次性压掉全部提示。

## 4. 启动并辨认两种运行方式

```powershell
npm start
```

脚本先执行生产构建，再使用 Electron 启动当前项目。
进入作品集后打开“雨落之后”，检查第一章仍可编辑。
应用退出前正常等待保存，不要为了关闭终端直接强杀进程。

另一个交付方式是：

```powershell
npm run pack
Start-Process -FilePath .\release\win-unpacked\RainSoul.exe
```

目录包运行依赖同目录资源，不能只复制一个 EXE 到其他位置。
`npm start` 需要源码与开发依赖，目录包面向普通作者。
二者都应做实际验证，因为打包可能遗漏工作进程或学习资源。

## 5. 学习顺序应追着一个功能走

不要先把四门技术的全部教程看完才开始实践。
沿“输入一句话并保存”的路径学习，更容易知道知识为何必要。

| 阶段 | 先学什么 | 在项目中的观察点 |
| --- | --- | --- |
| 界面 | React状态与事件 | 修改章标题后为什么重新渲染 |
| 契约 | TypeScript接口 | `Chapter` 与 `WritingDocument` |
| 桌面 | 隔离窗口与预加载 | 页面为什么不能直接读磁盘 |
| 存储 | SQLite事务与版本 | 保存成功与回执为何要一致 |
| 质量 | 测试与故障分析 | 为什么正常输入通过还不够 |

每学一项，都回到“雨落之后”解释一次真实行为。
例如读完接口，不是复述 interface 语法，而是画出章标题从哪里传到哪里。
读完事务，不是背 ACID，而是说明正文成功、回执失败时如何恢复。

## 6. Python/FastAPI 放在哪里

未来可以在单独练习工程中验证提示词、结构化输出与模型调用。
Python 适合这类试验，FastAPI 可以把试验包装为清晰的 HTTP 接口。
但这不意味着正式桌面应用要强制捆绑一个 Python 服务器。

首版云端 AI 的明确边界包括：
每次操作先说明服务、发送范围和费用或计费信息。
作者确认后才能发送，超时不自动反复重发正文。
候选与原文对比，确认接受前保护版本。
这些是产品与安全要求，选择语言不能替代它们。

本卷不提供未接入模型的“假成功”调用代码。
学习验证路径见第八卷，实际功能以代码与测试为准。

## 常见问题与排查

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| `npm` 找不到 | Node安装与终端环境 | 重开终端并检查版本 |
| 安装依赖时文件占用 | 应用/测试是否运行 | 正常退出后再安装 |
| SQLite原生模块加载失败 | Node、架构、锁文件 | 恢复已验证版本组合 |
| EXE离开目录不能运行 | 目录包依赖被拆散 | 保留整个 `win-unpacked` |
