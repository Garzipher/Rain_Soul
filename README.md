# RainSoul

RainSoul 是面向 Windows 的本地写作工作台，采用 Electron、React/TypeScript、Tiptap 和 SQLite。

开发基线为[立项方案 V2.0](docs/Rain_Soul_项目立项方案_V2.0.md)、[PRD](docs/Rain_Soul_PRD.md)及[技术方案](docs/Rain_Soul_技术方案.md)，界面沿用[工作台 Demo](docs/demos/rainsoul-writing-style.html)。本指南介绍开发运行方式，不另行定义需求。

## 启动入口与目录

本机当前版本统一从 `E:\soulrain\release\current\win-unpacked\RainSoul.exe` 启动；安装器也放在 `release/current/`，只启动或安装这里的版本。运行目录包须保留整个 `win-unpacked`，不能单独取走EXE。启动前退出旧实例，避免单实例锁聚焦旧程序。

| 目录 | 内容 | 是否提交Git |
| --- | --- | --- |
| `src/` | 产品源码 | 是 |
| `tests/`、`scripts/` | 自动化测试源码、构建和验收工具 | 是；安装包不含测试源码 |
| `docs/`、`learning/`、`tasks/` | 产品文档、教材、结论与证据索引 | 是 |
| `.artifacts/` | 本机生成的日志、截图、报告、覆盖率和历史证据 | 否 |
| `release/current/` | 当前可用目录包与安装器 | 否 |
| `release/archive/` | 历史安装包与升级验收基线 | 否；日常不从这里启动 |
| `node_modules/`、`dist/` | 可重新生成的依赖、编译输出 | 否 |

新测试默认输出到 `.artifacts/tests/desktop`、`.artifacts/tests/demo`，HTML报告在 `.artifacts/reports/demo`，覆盖率在 `.artifacts/coverage`。历史根目录的 `test-results*`、`.p0-*.log` 等已保留原名归档到 `.artifacts/archive/root-20261014/`，搬迁清单在 `.artifacts/manifests/`。旧报告里的原路径按此映射查找；历史 `release/<名称>` 已移至 `release/archive/<名称>`。测试源代码是防止回归所需的项目资产，不能因为叫“脚本”就忽略。

## 当前开发范围

当前代码已接入真实本地存储：创建/打开作品、可选分卷、卷章排序和移卷、章节标题与固定样式正文编辑、实时字数、撤销重做、自动保存、失败后显式重试，以及正常切换和关闭前的保存保护。启动第二个实例会聚焦已有窗口。

作品按独立 ID 保存；同名作品互不混用。自动保存停顿间隔为 500ms，持续输入按最多 5 秒提交的基线处理；保存失败时草稿留在当前窗口，重试成功后才能离开。

右键作品、卷或章节可打开管理菜单，也可聚焦后按 `Shift+F10`。作品和卷可改名，卷章可上下移动，章节可移入其他卷或无卷。删除前会确认，删除数据保留在本机，在设置的本机数据区恢复。恢复卷只恢复本次一起删除的章节；单独恢复章节时，若原卷仍被删除，该章恢复到无卷位置。名称和正文均保留。

结构变更与新增章节出现回执错误时，先保留原请求，界面暂停编辑、切换和关闭；点击“重试结构操作”确认同一操作结果后继续，避免重复创建或删除。

个人资料已接入本机存储，支持修改侧栏名称和选择 PNG/JPEG 头像。P0 主流程已接入作品知识条目、层级分类/标签、正文与知识全文搜索、剧情树、五状态伏笔与段落证据、行内书签、版本化写作特点、整作品快照、`.rainsoul` 归档、TXT/DOCX 手稿导入与导出。跨作品知识汇总只读，复用时复制并保留来源。

用户已批准P1首批为需求会话和本地TXT/DOCX拆书，已在正式客户端实施；本轮自动化验证通过范围见验收记录：会话按作品保存，离线草稿、改名、确认删除和历史分页；云发送只带所披露的最近100条以内消息与当前草稿，逐次确认。完整回答保存未确认时只重试原数据库请求，不再次联网；可对照回答并明确放弃本次恢复记录。本地拆书逐段审核内容、分类/标签、作品出处和使用权限后批量入当前知识库，不创建手稿作品。1.2.0新增AI辅助拆书：另行选择原段、逐次授权，推荐可核对摘录及写法、场景、仿写练习；带入与替换前重新核对本机结果，重新审核后才入库。详见[实施与验收记录](tasks/p1-ai-book-extraction.md)。用户另行批准的公开 URL/粘贴导入、可恢复逐批 AI 拆书、本机检索与模型管理已接入源码，本批源码测试及实际目录包回归已完成；未资格模型禁用并明确回退关键词，跨作品分析与XMind仍后置。详见[本批执行与门禁](tasks/url-local-retrieval-ledger.md)。

云端 AI 已接入逐次授权、上下文/知识参考预览、候选对比、确认写入前快照、逐条知识候选审核、一致性和剧情感受建议。当前适配兼容 `chat/completions` 的公开 HTTPS 服务，使用非流式完整响应；流式响应列为优化路径。2026-10-13已用原创隔离样稿完成OpenRouter会话、续写/知识参考及AI拆书的真实请求和审核写入，具体效果与失败尝试见[真实云报告](tasks/real-cloud-validation-2026-10-13.md)。其余云操作、最终安装包云兼容/计费及干净Windows安装矩阵仍待验。本机Word2007样稿实开不代表其他版本或长篇矩阵通过。免费服务仍需作者自己的Key，免费额度与可用性由服务方决定。

网页/粘贴导入后先阅读原文，再按每批最多20段逐次授权AI分析并人工审核入库；完成批次在重启后可本机恢复，不恢复授权和审核勾选、不重新联网。知识检索和写作参考每页20条，当前作品最多选用5条；跨作品材料先复制。模型设置提供许可、大小、所需空间、固定下载或离线目录导入、进度与取消；未资格模型保持停用，推理不隐式补下载。详见[已批准设计](docs/superpowers/specs/2026-10-10-url-local-retrieval-design.md)及[模型资格记录](tasks/retrieval-model-qualification.md)。

## 项目开发学习

客户端首次离线启动默认在唯一“作品集”中提供普通作品“项目全流程开发学习”，按分卷、章节记录从需求与原型到架构、实现、测试、评审和交付的学习过程。完整教学源在 [learning/项目全流程开发学习](learning/项目全流程开发学习/)，当前九卷四十五章、二十八张离线图片，包含前置知识、跟做步骤、真实代码、排错、练习答案和系统截图。第九卷补充真实云联调、灰字补全及模型实测，明确区分运行成功、效果合格和未验收门禁。

学习章节默认以图文阅读展示 Markdown 标题、代码高亮、表格、本章目录和包内截图；可切换只读“Markdown 源文”核对语法。原“正文／作者笔记”入口已移除，旧数据保留，不混入阅读页。教材逐章先解释技术概念、工作原理和短例，再剖析本项目源码、接口及数据流，最后提供跟做步骤、排错和拓展练习。源文维护在仓库进行；普通小说和作者新增的无教材对应章节仍使用固定样式编辑器。

课程在构建时随程序打包，启动时幂等初始化到本机作品库。作品中的数据仅增添新卷章，保留作者已有编辑、排序和删除状态；同名用户作品不会被接管，已删除学习作品不会在重启时复活。包内只读教材随新版更新，不覆盖已安装的作者正文；旧正文的更正用新增勘误/补充章记录。每批开发持续更新项目内学习源，不要求作者先完成课程。

## 写作工具与分发

写作页保留正文、剧情架构、伏笔架构三个工作区。正文选区右键可以调用 AI 润色、续写和纠错，也可从右上角“AI 工具”打开；授权、上下文预览、候选审核仍逐次进行。右上角“版本历史”用于创建、预览、恢复和导出历史稿件。AI 与版本工具不再占用独立工作区标签。

段落末尾输入停顿400ms后可显示当前作品知识原句的灰字余句与出处，Tab接受、Esc取消；未接受不保存、不计字数。打开AI工具、生成或保留待审候选时暂停灰字。AI续写结合已授权正文、大纲、伏笔和写作特点生成新内容；原句前缀提示不判断剧情适用性。Qwen3的0.6B与1.7B已隔离CPU实测，当前电脑不建议默认内置，详见[模型研究](tasks/local-chat-model-evaluation-2026-10-14.md)。

安装器可发给其他 Windows 10/11 x64 用户，安装后无需 Node.js、Python或数据库服务。当前包没有可信发布者数字签名，Windows可能显示未知发布者或SmartScreen提示；正式公开分发仍需签名与系统矩阵验收，不要求用户关闭系统保护。首次安装及离线写作不需要网络；使用云端AI需自行配置服务、密钥并承担对应计费。个人作品和凭据不会包含在安装包中；应保留程序自带的Electron/Chromium和第三方版权许可文件。

交互卸载默认保留数据；主动选择删除时先提示备份并再次确认，再调用程序的安全清理模式。升级与静默卸载保留数据。清理拒绝链接/junction、运行中实例和异常路径；失败中止卸载并保留安装。文件删除中途失败可能留下不完整的隔离目录，错误提示会给出位置，不能当作完整备份。此流程已列入本轮自动化验收，干净系统安装/升级/卸载仍须另验。

旧EXE包含打包当时的代码，不会随Git合并自动更新；单实例锁也可能把新版启动转到仍运行的旧窗口。请先退出旧程序，再用新版启动。历史旧包已移出原release启动路径隔离，生成物不再纳入Git；源码和提交历史保留用于回退。

正式客户端沿用 Demo 的 RainSoul 标题与 Logo：天蓝色描边的倾斜圆角方框、浅蓝底与中心蓝点。侧栏、窗口和 Windows 程序图标遵循同一图形规范；[assets/rainsoul.svg](assets/rainsoul.svg) 及对应 PNG/ICO 随应用本地打包。

## 开发环境与启动

当前开发验证环境为 Windows x64、Node.js 24。无需单独安装 Python、数据库服务或本地模型。完整浏览器测试需要系统已安装 Google Chrome；首次安装依赖需要网络。

在项目目录执行：

```powershell
npm install
npm start
```

`npm start` 自动执行生产构建后启动 Electron。正式写作窗口通过本机 `rainsoul://app/` 加载打包资源，不依赖 Demo 的 HTTP 预览服务。

## 本机数据

正常运行默认使用 `%LOCALAPPDATA%\RainSoul`，其中 `catalog.sqlite` 保存作品目录，每部作品位于 `Projects\<作品 ID>\project.sqlite`，`author-profile.json` 保存作者名称和规范头像。个人资料不随作品快照恢复。实际路径可在设置页面查看；升级或重装前请保留整个数据目录。

当前源码作品库为 schema v8：v5增加独立会话与消息，v6增加冻结来源、知识来源关联和学习注释，v7补齐来源章节/段落坐标，v8保存捕获方式、时间及受限渲染DOM摘要。旧库前向迁移前生成包含已提交 WAL 数据的一致备份，失败回滚并拒绝启动，不自动降级或清理备份。归档按白名单接受v4～v8并转换导入新作品；新快照payload3保留捕获证据，旧payload1/2先核对原hash再内存兼容读取，不重写历史字节，恢复正文快照保留当前会话。凭据、模型及向量缓存不进归档。迁移、归档schema校验与快照关系有自动化覆盖，安装器原位升级仍待真实系统验收。

正文保存在本机，AI 仅在作者核对服务、完整发送范围及计费提示并逐次确认后联网。API Key 使用本机安全存储，不进入作品、归档、日志或错误提示。正常关闭会等待保存，保存失败或输入法仍在组词时阻止关闭；强制结束进程、系统断电或系统强制终止不等于正常关闭保护，未落盘草稿仍可能丢失。

## 验证与目录打包

```powershell
npm run verify
npm run pack:research
```

`npm run verify` 依次执行 TypeScript 检查、ESLint、覆盖率测试、真实 Electron 集成测试和原有 Demo 浏览器测试。`npm test` 的覆盖率与桌面测试均自动前置构建，不需要先手动生成 `dist`。

`tests/browser-setup.test.js` 通过临时本机 HTTP 服务检查真实 Chrome 连通性及离线阻断，不依赖外部搜索网站。真实云兼容及计费仍使用独立发布矩阵验收，本机检查不能替代它。

| 命令 | 用途 |
| --- | --- |
| `npm run test:unit` | 单元与真实 React/Tiptap 组件行为测试 |
| `npm run test:coverage` | 单元/组件测试及核心模块覆盖率门禁 |
| `npm run test:desktop` | 先构建，再运行 Electron 集成测试 |
